## CRITICAL 취약점 (5건)

### C-01. 전체 API 엔드포인트 무인증 접근 허용

**파일:** `q-center/src/main/java/qualitycenter/security/WebSecurityConfiguration.java:68-89`

```java
http.cors().and().authorizeRequests()
    .antMatchers("/api/login/**").permitAll()
    .antMatchers("/api/search/**").permitAll()
    .antMatchers("/api/std/**").permitAll()      // 데이터 표준 CRUD
    .antMatchers("/api/dm/**").permitAll()       // 데이터 모델 CRUD
    .antMatchers("/api/sysinfo/**").permitAll()  // 시스템 정보
    .antMatchers("/api/diag/**").permitAll()     // 진단
    .antMatchers("/api/admin/**").permitAll()    // 관리자 기능까지 개방
    .anyRequest().authenticated();
```

**위험:** 로그인 없이 모든 핵심 API(데이터 생성/수정/삭제, 관리자 기능)에 접근 가능. 외부 공격자가 직접 API를 호출하여 데이터를 조작할 수 있음.

**조치 방안:**
```java
http.cors().and().authorizeRequests()
    .antMatchers("/", "/*.html", "/login", "/logout").permitAll()
    .antMatchers("/api/login/login", "/api/login/existAdmin", "/api/login/createAdmin").permitAll()
    .antMatchers("/api/admin/**").hasRole("ADMIN")
    .antMatchers("/api/**").authenticated()
    .anyRequest().authenticated();
```

### C-02. 관리자 계정 생성/사용자 관리 API 무인증 노출

**파일:** `q-center/src/main/java/qualitycenter/controller/LoginController.java`

| 엔드포인트 | 라인 | 문제 |
|-----------|------|------|
| `GET /api/login/createAdmin?password=xxx` | 65-77 | 누구나 관리자 계정 생성 가능 |
| `POST /api/login/createUser` | 84-100 | 누구나 사용자 생성 가능 |
| `POST /api/login/removeUser` | 102-106 | 누구나 사용자 삭제 가능 |
| `POST /api/login/updateUser` | 108-121 | 누구나 사용자 정보(권한 포함) 수정 가능 |
| `GET /api/login/getUserList` | 123-126 | 전체 사용자 목록 열람 가능 |
| `GET /api/login/changePassword` | 79-82 | 누구나 타인 비밀번호 변경 가능 |

**위험:** `/api/login/**`이 `permitAll()`로 설정되어 있어, 인증 없이 관리자 생성, 사용자 삭제, 비밀번호 변경이 모두 가능.

**조치 방안:**
- `createAdmin`은 최초 설정 시에만 허용 (existAdmin 체크 후 차단)
- 나머지 사용자 관리 API는 관리자 권한 체크 필수: `@PreAuthorize("hasRole('ADMIN')")`
- `changePassword`는 현재 세션 사용자만 자신의 비밀번호 변경 가능하도록 제한

### C-03. CORS 와일드카드 + 자격증명 허용 조합

**파일:** `q-center/src/main/java/qualitycenter/config/WebResourceConfig.java:34-41`

```java
registry.addMapping("/**")
    .allowedOriginPatterns("*")     // 모든 출처 허용
    .allowedHeaders("*")           // 모든 헤더 허용
    .allowedMethods("*")           // 모든 HTTP 메서드 허용
    .allowCredentials(true)        // 자격증명 포함 허용
    .maxAge(86400L);
```

**위험:** 악의적 웹사이트에서 사용자 브라우저를 통해 인증된 API 요청을 보낼 수 있음. `allowCredentials(true)` + 와일드카드 조합은 특히 위험.

**조치 방안:**
```java
registry.addMapping("/api/**")
    .allowedOrigins("http://localhost:28091", "https://production-domain.com")
    .allowedHeaders("Content-Type", "Authorization", "X-Requested-With")
    .allowedMethods("GET", "POST", "PUT", "DELETE")
    .allowCredentials(true)
    .maxAge(3600L);
```

### C-04. 평문 데이터베이스 자격증명 (소스코드 내 하드코딩)

**파일:** `q-center/src/main/resources/application.properties:18-20`

```properties
spring.datasource.hikari.jdbc-url=jdbc:postgresql://127.0.0.1:25433/postgres?currentSchema=quality
spring.datasource.hikari.username=admin
spring.datasource.hikari.password=admin!123
```

**위험:** Git 저장소에 DB 비밀번호가 평문으로 노출. 저장소 접근 권한이 있는 모든 사람이 DB에 직접 접근 가능. `admin!123`은 약한 비밀번호.

**조치 방안:**
```properties
spring.datasource.hikari.username=${DB_USERNAME}
spring.datasource.hikari.password=${DB_PASSWORD}
```
- 환경변수 또는 시크릿 매니저(Vault, AWS Secrets Manager) 사용
- `.gitignore`에 환경별 설정 파일 추가

### C-05. Base64 패스워드 인코딩 (암호화가 아님)

**파일:** 여러 Vue 컴포넌트

| 파일 | 라인 | 코드 |
|------|------|------|
| `q-center/vue/front/src/views/login/NdLogin.vue` | 193 | `btoa(data.password)` |
| `q-center/vue/front/src/components/DSMyProfile.vue` | 125-126 | `btoa(this.oldPassword)` |
| `q-center/vue/front/src/components/MMUser.vue` | 152, 180 | `btoa(...)` |

**위험:** Base64는 인코딩이지 암호화가 아님. `atob()`으로 즉시 복호화 가능. 네트워크 스니핑 시 비밀번호 탈취 가능.

**조치 방안:**
- HTTPS 강제 적용 (TLS)
- 프론트엔드에서는 평문 전송 (HTTPS가 전송 구간 암호화 담당)
- 서버 측에서 bcrypt/scrypt/PBKDF2로 해싱

### H-02. 파일 업로드 경로 조작 (Path Traversal)

**파일:** `q-center/src/main/java/qualitycenter/controller/BoardController.java:185-206`

```java
String origName = file.getOriginalFilename();  // 검증 없음
Path savePath = Paths.get(dir.getAbsolutePath(), fileId + "_" + origName);
Files.copy(file.getInputStream(), savePath);
```

**위험:** 파일명에 `../../etc/passwd` 같은 경로 조작 문자열을 넣어 서버 임의 위치에 파일 쓰기 가능.

**조치:**
```java
String safeName = Paths.get(origName).getFileName().toString();  // 경로 부분 제거
safeName = safeName.replaceAll("[^a-zA-Z0-9가-힣._-]", "_");     // 특수문자 제거
```

### H-07. SHA256 패스워드 해싱 (부적절)

**파일:** `q-center/src/main/java/qualitycenter/service/auth/SessionService.java:93`

```java
admin.setPassword(securityManager.createHash(
    securityManager.encryptSHA256(
        securityManager.decodeBase64(admin.getPassword()))));
```

**위험:** SHA256은 범용 해시 함수로, GPU 기반 무차별 대입 공격에 취약. 패스워드 전용 해시 함수가 아님.

**조치:** BCryptPasswordEncoder(Spring Security 내장) 사용.

## 조치 우선순위

### 즉시 조치 (Critical)
1. API 엔드포인트 인증/인가 적용 (`permitAll()` → `authenticated()`)
2. 관리자 API에 `@PreAuthorize("hasRole('ADMIN')")` 추가
3. CORS 허용 출처를 운영 도메인으로 제한
4. DB 자격증명을 환경변수로 이전
5. HTTPS 강제 적용 + Base64 인코딩 제거

### 단기 조치 (1-2주)
1. CSRF 보호 활성화
2. 파일 업로드 검증 (확장자 화이트리스트 + 경로 검증)
3. GET → POST 변경 (상태 변경 API)
4. BCrypt 패스워드 해싱으로 전환
5. 글로벌 예외 핸들러 추가

### 중기 조치 (1개월)
1. 구버전 라이브러리 업그레이드 (Jackson 2.x, Spring Session 2.x)
2. 프로덕션 로그 레벨 INFO로 변경
3. 민감정보 로깅 제거
4. 세션 관리 활성화
5. 브루트포스 방어 강화 (IP 기반 차단, 지수적 백오프)
