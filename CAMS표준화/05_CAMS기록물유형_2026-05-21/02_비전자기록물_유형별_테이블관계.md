## 결론 한 줄

**8 유형 모두 `RG_DOCUMENT`/`RG_DETAIL`을 공통 마스터로 사용. 유형별 "추가 메타"만 별도 부속 테이블에 BSID/DSID 키 공유로 매달려 있음.** 단 구술·해외기록만 예외(별도 시스템).

→ **일반기록물(01)과 총독부기록물(04)은 동일한 RG_DOCUMENT/RG_DETAIL에서 관리됨**. `ARCAVETYPE` 코드(01 vs 04)로 행 단위로 구분되고, 총독부만 `RG_OLD_GOVTINFO`에 목차 1컬럼이 추가로 붙음.

## 2. 4가지 관계 패턴

```
[패턴 A — 마스터 only]
   RG_DOCUMENT (BSID PK)  ──┐
   RG_DETAIL  (DSID PK)   ──┴── 일반문서(01), 역사기록물(07)
                              (추가 부속 없음)

[패턴 B — BSID 공유 부속 (=주류 비전자 유형)]
   RG_DOCUMENT (BSID PK)
        │
        ├─ RG_OLD_GOVTINFO    (총독부 04)     BSID FK PK
        ├─ RG_GOVTINFO        (정부간행물 05) BSID FK PK
        ├─ RG_ADMIN_ADDINFO   (행정박물 08)   BSID FK PK
        └─ SV_ARCHIVE_ADDITION_ITEM (시청각 02) BSID FK [+DSID]
                              (1:1 부속, 메타만 추가)

[패턴 C — 분류체계만 별도]
   총독부 → CM_OLDGOV_*       (BRM 대신 총독부 분류체계)
   (테이블 분리는 아니고 마스터데이터만 별도)

[패턴 D — 완전 별도 시스템 (BSID 미사용)]
   해외기록물 06 → RG_POSS_MEDIAINFO  (MEDIA_SEQ_NO)
   구술기록   → RG_ORAL_INTERVIEW 등 5개 (REG_SEQ_NO)
                              (BSID 발급 없이 자체 키로 운영)
```

## 3. 부속 컬럼 수 — "얼마나 추가되는가"

| 유형 | 메인 컬럼 활용 | 부속 컬럼 수 | 해석 |
|---|---|---|---|
| 일반문서/역사 | 251개 | 0 | 마스터로 완결 |
| **총독부** | 251개 거의 전부 | **1** | RG_DOCUMENT 거의 그대로, 목차만 별도 |
| 정부간행물 | 다수 | 46 | 간행물 특유 메타(권호·발행처 등)가 많음 |

| 행정박물 | 다수 | 14 | 물리 박물 메타 |
| 해외기록물 | (BSID 미사용) | 9 | 매체 정보만 |
| 구술기록 | (BSID 미사용) | 26 | 인터뷰 워크플로 별도 |

## 4. 비전자기록물 = "철1건1" 구조

[cams 기록물 유형.txt](../CAMS_RAMP_통합/cams%20기록물%20유형.txt) 사용자 메모와 매뉴얼 일치:

- **비전자(02·04·05·08 등)는 RG_DOCUMENT 1건당 RG_DETAIL 1건이 원칙**
- 전자기록물(01 일반문서·07 역사기록물 일부)만 RG_DOCUMENT 1 : RG_DETAIL N (여러 문서가 한 철에 묶임)

→ 통합 DB 설계 시 비전자 유형은 **철·건 합칠 수 있는 후보** (논의용).

## 5. 정리 — "같은 테이블에서 관리되는가?" 직답

| 항목 | 일반기록물 | 총독부기록물 |
|---|---|---|
| 메인 테이블 | `RG_DOCUMENT` / `RG_DETAIL` | `RG_DOCUMENT` / `RG_DETAIL` ✅ 동일 |
| 구분 방법 | ARCAVETYPE = `'01'` | ARCAVETYPE = `'04'` |
| 부속 테이블 | 없음 | `RG_OLD_GOVTINFO` (1컬럼, 목차) |
| 분류체계 | BRM (일반) | `CM_OLDGOV_*` (총독부 별도) |

**같은 RG_DOCUMENT/RG_DETAIL을 공유하되, ARCAVETYPE 코드값으로 유형이 분기**되는 1상속 구조. 단, 총독부는 분류체계(BRM 대체)와 목차(부속)가 추가로 필요해 마스터데이터 영역에서 분리됨.

## 6. 미확인 / 다음 확인 거리

1. **민간기록물(매뉴얼 2.1.7) · 일반도서(2.1.8)** — ARCAVETYPE 코드값 미확정 (스키마 코멘트에 없음, CAMS 데이터 접근 불가로 실제 코드 확인 불가)
2. **이중보존매체(매뉴얼 2.9)** — 별도 테이블인지, RG_DETAIL 보조 메타인지 미확인
3. DOCTYPE `F` 코드의 정체 — A·B·C·D·E·G만 코멘트 확인됨
