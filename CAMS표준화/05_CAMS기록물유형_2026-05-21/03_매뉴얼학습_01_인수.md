## 0. 본 문서의 위치 (생명주기 좌표)

> 🎯 **이번 사업 한 줄 요약**: **RAMP(RMS의 후속)와 CAMS의 DB를 통합**한다. 인수 단계는 두 시스템이 만나는 유일한 데이터 채널 → 통합 매핑의 1순위 학습 대상.

```
[생산]                 [관리]                   [영구보존]
처리과/부서      →    기록관/자료관(RMS)  →    영구기록물관리기관 (AMS 적용)
                                              ├ (중앙) 국가기록원       → CAMS  ★ 이번 사업
                                              ├ (지방) 서울기록원        → 자체 AMS 구축 진행
                                              ├ (지방) 경상남도기록원    → 자체 AMS (예: GNAMS)
                                              └ (헌법) 국회·대법원 등    → 기관별 시스템
                                              │
                                              ↓
                                              ★ 인수 ← 이 문서가 다루는 단계 (CAMS 기준)
                                              │
                                              등록 → 정리 → 서고배치 → 보존 → 매체수록
                                              → 기술·재분류 → 열람·활용 → 폐기
```

**용어 관계 정리**:
- **AMS** = 영구기록관리시스템 (Archives Management System). **모든 영구기록물관리기관용 상위 카테고리·표준**.
- **CAMS** = AMS의 **중앙 인스턴스**. 국가기록원이 운영. **이번 dataQ 표준화 사업의 대상**.
- 서울기록원·경남기록원 등 지방기록원은 **각자의 AMS를 구축하거나 구축 중**. 본 매뉴얼은 CAMS 기준이며, 지방 AMS는 같은 NAK 표준을 따르되 인스턴스가 다름.
- **RMS → RAMP** (세대 교체). RMS(표준기록관리시스템)가 후속 시스템 **RAMP**로 전환됨. 현재 신규 인수의 생산기관 측은 RAMP 기준. 매뉴얼 본문은 RMS 시기에 작성되어 "RMS" 표기 다수.

**🎯 이번 사업의 본질**: **RAMP(구 RMS)와 CAMS의 DB 통합**.
- 생산기관 측 **RAMP** DB ↔ 영구보존 측 CAMS DB를 하나로 흡수
- 인수 단계는 두 시스템이 만나는 **유일한 데이터 채널**이므로 통합 매핑의 핵심 접점
- 메인 키 매핑: CAMS `BSID` ↔ RAMP `fls_id`, CAMS `DSID` ↔ RAMP `ritm_id`

**핵심**: 인수 = RAMP(또는 구 RMS·자료관·기타 외부시스템)에서 CAMS로 기록물이 넘어오는 진입 관문.
이 단계가 끝나면 기록물은 **임시영역(인수영역) → 관리영역**으로 승격되어 CAMS의 정식 마스터(RG_DOCUMENT/RG_DETAIL)에 등록된다.

**왜 중요한가**:
- CAMS의 모든 데이터는 인수에서 시작 — 인수에서 누락/오류가 발생하면 이후 보존·서비스 전부 영향
- 이관규격(V1.0/V2.0), 품질검사 7단계, 육안검수, N차 품질검사 등 **여러 검증 게이트**를 통과해야만 등록 가능
- 생산기관(중앙부처·지자체·교육청 등 738개) ↔ 영구기록기관 사이의 **유일한 데이터 채널**

|---|---|---|
| **RMS** | Records Management System. **생산기관(부처·지자체 등)**이 기록물을 만들고 관리하는 시스템 | 발신자 측 |

| **AMS** | Archives Management System. 영구기록관리시스템 일반 카테고리. CAMS는 그 중앙 인스턴스 | 상위 분류 |

| 약어 | 풀이 | 비유 |
|---|---|---|
| **기록물철 (BSID)** | Basic Series ID. **여러 문서를 묶은 폴더 단위**의 고유 번호 (12자리) | 파일 폴더 이름 |
| **기록물건 (DSID)** | Detail Series ID. **폴더 안의 개별 문서/항목** 고유 번호 (12자리) | 폴더 안 파일 이름 |
| **MBSID/MDSID** | M = Migration. 이관(인수) 처리 중에만 잠시 쓰는 **임시 번호** | 택배 운송장 번호 (도착하면 폐기) |
| **TBSID** | T = Temp. 인수 마지막 단계 임시영역에서 쓰는 **승격 직전 번호** | 회원가입 인증대기 번호 |
| **REG_SEQ_NO** | 구술기록 전용 일련번호 (BSID 안 씀) | 별도 시스템 회원번호 |
| **MEDIA_SEQ_NO** | 해외매체 전용 일련번호 (BSID 안 씀) | 별도 시스템 회원번호 |
| **관리번호** | 인수확정 시 자동 생성되는 CAMS 내부 영구 번호 | 주민등록번호 (한 번 발급 후 불변) |

### 1-B. 접두사 규칙 (인수 영역 식별)

> 📖 **읽는 법**: CAMS 테이블 이름은 접두사로 어느 단계의 데이터인지 구분 가능. `RG_M*`이면 "이관(Migration) 임시 영역" 같은 식.

| 접두사 | 의미 (풀이) | 어느 단계에서 사용 | 키 |
|---|---|---|---|
| **RG_S\*** | **S**urvey = 생산현황. 생산기관이 "올해 우리가 만든 기록물 목록은 이렇습니다"라고 신고할 때 쓰는 테이블 | [A] 사전 신고 | 자체 키 |
| **RG_TRANS\*, RG_S{T}\*** | 이관 일정 / 이관 승인 관련 | [B] 이관 합의 | — |
| **RG_M\*** | **M**igration = 이관(인수). RMS→CAMS로 들어와서 검사·검수 중인 임시 데이터 | [C][D][E] 접수·검사·검수 | MBSID/MDSID (인수 처리 중에만 유효한 임시키) |
| **RG_T\*** | **T**emp = 임시등록. 정식 RG_DOCUMENT로 승격 직전 마지막 임시영역 | [F] 확정 직전 | TBSID (승격 전 임시키) |
| **RG_UNREG\_\*** | UNREG = Unregistered. 인수규격 안 거치고 수기 입력한 비전자 기록물 대장 | [F] 보조 | 가등록번호 |
| **RG_DOCUMENT / RG_DETAIL** | 정식 관리 영역. 인수 완료된 모든 기록물의 영구 마스터 | [F] 이후 | **BSID / DSID** (영구 정식키) |
| **RG_NONFIXED, RG_TAKEOVER\_\*** | 행정박물 가인수인계 / 인수확인서 (물리 박물 전용) | [F] 보조 | — |
| **RF\_\*, ST_RFIDTAG** | RF = RFID 태그. 비전자 기록물에 부착하는 칩 발행 관리 | [F] 비전자 후속 | — |

→ **핵심 승격 흐름**: `RG_M* → RG_T* → RG_DOCUMENT` (임시키 MBSID/TBSID가 마지막에 영구키 BSID로 변환됨)

→ **비유**: 회원가입 같은 흐름.
- RG_M* = 이메일 인증 대기 (임시)
- RG_T* = 인증 완료, 가입 직전 (승격 직전)
- RG_DOCUMENT = 정식 회원 (영구 ID 부여)

### 1-C. 워크플로 약어 매핑

사내에서는 W 코드로 호칭. **W3=[A]생산현황접수, W4=[B]인수일정, W5=[C]이관기록물접수, W6=[D]+[E]품질검사·육안검수, W7=[F]인수확정/등록** ((1장) 소개·통합 분석 문서 기준).

### 1-D. 유형별 분기 정책 — "화면은 공통, 적재는 자동 분기"

**핵심**: 인수는 등록(A02)과 달리 **유형별 화면 분기가 없다**. RMS가 표준 NEO 규격으로 보내므로 모든 유형을 같은 파이프라인으로 받고, **승격(인수확정) 시점에 ARCAVETYPE 값에 따라 시스템이 자동으로 유형별 부속 테이블에 분기 INSERT**한다.

#### 1-D-1. 자동 분기 메커니즘

```
[인수 영역 — 유형 무관 공통 적재]
RMS NEO 파일 → RG_MDOCUMENT  (ARCAVETYPE 컬럼만 채워 구분)
            → RG_MDETAIL
            → 품질검사·육안검수 (전부 공통 테이블)
              ↓
[승격 시점 (인수확정 + 관리번호 부여) — ARCAVETYPE 기반 자동 라우팅]
              ↓
   ARCAVETYPE = 01 (일반문서) ─→ RG_DOCUMENT only
              = 02 (시청각)   ─→ RG_DOCUMENT + SV_ARCHIVE_ADDITION_ITEM 자동 INSERT
              = 04 (총독부)   ─→ RG_DOCUMENT (+ RG_OLD_GOVTINFO? 검증 필요)
              = 05 (정부간행물)─→ RG_DOCUMENT + RG_GOVTINFO 자동 INSERT
              = 06 (해외)     ─→ RG_DOCUMENT
              = 07 (역사)     ─→ RG_DOCUMENT only
              = 08 (행정박물) ─→ RG_DOCUMENT + RG_ADMIN_ADDINFO 자동 INSERT
```

→ 인수 화면은 1개지만, "인수확정 → 관리번호 부여" 버튼 누르는 순간 시스템이 ARCAVETYPE 값을 보고 유형별 부속 테이블에 자동 INSERT.

#### 1-D-2. 인수 vs 등록 분기 차이

| 차원 | 인수 (A01) | 등록 (A02) |
|---|---|---|
| 화면 분기 | ❌ 공통 1세트 (시청각·비전자만 보조 단계 추가) | ✅ 12 유형별 별도 화면 |
| 테이블 분기 | ❌ 인수영역은 RG_M* 공통, ARCAVETYPE 컬럼으로만 구분 | ✅ 입력 시점부터 유형별 부속 직접 적재 |
| 분기 발생 시점 | **승격 시점** (RG_T* → RG_DOCUMENT + 부속) | **입력 시점**부터 |
| 분기 주체 | **시스템 자동** (ARCAVETYPE 기반 라우팅) | **사용자가 화면 선택** |
| 이유 | RMS NEO 규격이 표준 → 처리 통일 | 사용자 수동 입력, 유형별 메타가 상이 |

#### 1-D-3. 화면 분기는 없지만 보조 단계는 유형별로 추가

인수 화면 내에서도 시청각·비전자만 추가 액션이 노출됨:

| 매뉴얼 절 | 분기 대상 | 보조 단계 |
|---|---|---|
| §1.3.1(5/5) | **시청각** (ARCAVETYPE=02) | 원본매체 수동 지정 — 관리번호 부여 전 필수 |
| §1.3.8 | **비전자기록물** | 실물확인 처리 — 이걸 해야 RG_DOCUMENT 정식 등록됨 |
| §1.3.11 | **비전자** | RFID 태그발행 |
| §1.3.12 | **비전자·혼용** | 정리의뢰 (전자는 인수확정 시 자동 진행) |

→ 같은 화면 내에서 해당 유형 행에만 추가 버튼이 노출되는 방식. 별도 화면이 아님.

#### 1-D-4. 실무상 유형별 주 진입 채널 (추정)

| 유형 (ARCAVETYPE) | 주 진입 채널 | 이유 |
|---|---|---|
| **01 일반문서** | **인수** | RMS의 핵심. 가장 큰 비중 |
| **02 시청각** | **인수** (+ 등록 일부) | RMS에서 NEO로 이관 |
| **07 역사** | 인수 + 등록 | RMS 이관도 있고 자체수집도 |
| 04 총독부 | **등록** (자체수집) | RMS 없던 시대, A02 §2.1.1.3 |
| 05 정부간행물 | **등록** (납본) | 발간기관 직접 납본, A02 §2.1.3 |
| 06 해외 | **등록** (기획수집) | A03 기획수집 → A02 §2.1.6 |
| 08 행정박물 | **등록** | 물리 박물, NEO 적용 불가, A02 §2.1.4 |
| (별도) 구술 | **등록** (자체생성) | CAMS 인터뷰 직접 수행, A02 §2.1.5 |

→ 인수 채널로 흘러오는 유형은 사실상 **01·02·07 위주**. 나머지는 등록 채널이 주력.

→ 따라서 인수 매뉴얼이 "유형별 분기 화면"을 만들 필요가 없었던 것 — 들어오는 유형 종류가 한정적.

## 2. 단계별 기능 상세 — A01 매뉴얼 목차순

### 1.1 생산현황관리 (A: 사전 신고)

매년 기록관 단위로 **전년도 기록물 생산현황을 CAMS에 제출**. 다음해 이관 대상 사전 파악용.

#### 1.1.1 생산현황접수
- **무엇**: RMS·자료관에서 생산현황 보고서를 온/오프라인으로 받아 1차 접수
- **입력**:
  - 접수년도(YYYY), 생산기관(코드), 접수처구분(기록관/자료관/목록관리), 접수처리(바로/예약)
  - 첨부파일: 생산현황 보고서식 (엑셀) 또는 규격 파일
- **출력**: 접수목록 + (오류 시) 오류통보 파일
- **자동 검증 오류 유형** (자주 발생):
  | 오류 | 의미 |
  |---|---|
  | 중복데이터/파일 존재 | 철분류번호·파일명 중복 (CAMS DB 기존 데이터와 충돌) |
  | 보존기간 유효성 오류 | 보존기간 값 없음 또는 코드 미일치 |
  | 생산기관등록번호 길이 불일치 | 13자리 아님 |
  | 인수인계처리과 기관코드 미기재 | 필수항목 누락 |
  | 파일표준규격오류(항목수) | 철등록 15개 항목 ≠ 실제 항목수 |
  | 처리과코드 항목 에러 | 처리과기관코드 누락 |
  | 철분류번호 중복 | 같은 철분류번호 2건 이상 |

#### 1.1.2 생산현황검수
- 진본성·무결성·신뢰성·이용가능성 4대 속성 보장 관점에서 메타데이터 검수
- 검수 결과: 정상 → 다음 단계 / 오류 → 오류저장 → 통보
- 일괄검수 또는 철 단위 검수

#### 1.1.3 생산현황확정
- 검수 완료된 생산현황을 **인수** 또는 **반려** 통보
- **통보방법**: 온라인(대용량송수신) 또는 오프라인(파일 다운로드 전달)
- 통보 완료 → 다음해 인수 기초자료로 활용

#### 1.1.4 생산현황통계
- 접수년도별·기관유형별·생산기관별 통계 조회
- 철·건 단위 인쇄 가능

  - 통보상태: 전체/미통보/통보중/통보완료/통보실패

### 1.3 기록물인수 (C/D/E/F: 본격 인수)

#### 1.3.1 이관기록물접수 — 인수의 시작점
**4가지 접수 경로**:

| 경로 | 출처 | 방식 | 비고 |
|---|---|---|---|
| 온라인 | RMS (대용량송수신 연계) | 자동 접수 + 자동 품질검사 | 중앙행정기관 주력 |
| 오프라인 (전자문서) | 폐쇄망 RMS | 수동 업로드 (CAMS 컴포넌트 또는 FTP) | 2016~17 대부분 |
| 오프라인 (자료관) | 자료관시스템 | 규격파일 + 실물 | CAMS 미연계 기관 |
| 오프라인 (목록관리) | 목록관리시스템 | 엑셀 일괄등록 | 기타 |

**이관규격 (TXT 파일 수)**:
- **V1.0** (2017 이전): TXT 8종 + 철 NEO + 건 NEO
- **V2.0** (2017~ 중앙행정기관): TXT 1종 + 철 NEO + 건 NEO (간소화)
- 지자체는 영구기록기관으로 직접 이관하지 않으므로 **여전히 V1.0**

**시청각기록물은 별도 흐름**: 이관기록물 접수 후 **원본매체유형을 수동 선택**해야 인수 완료 + 관리번호 부여 가능. (매뉴얼 2.4.1(5/5) 절)

**중요 부속 화면**:
- **인수인계서 작성**: 접수완료 후 가등록번호로 인수대장과 연결, 인수인계서 첨부
- **접수결과 통보**: V2.0만 자동 통보 가능
- **오류통보**: 이관/품질검사 중 오류 발생 시 RMS로 즉시 통보

#### 1.3.2 육안검수 대상 확정 — 표본 추출
- **바이러스검출기록물 처리**: 1·2차 바이러스 검사에서 검출된 건은 우선 별도 처리 (단순 엑셀 매크로도 바이러스로 오인되므로 사용자가 진행/반려 결정)
- **샘플링 검수**:
  | 방법 | 의미 |
  |---|---|
  | 전체 | 모든 철·건 검수 |
  | 샘플링[철] | 철 단위 무작위 추출 |
  | 샘플링[건] | 건 단위 무작위 추출 |
- **검수담당자 배정**: 샘플링된 철/건을 검수자에게 일괄 할당
- **일일 작업량 할당**: 담당자별로 하루 처리량 분배 + 진척 관리

#### 1.3.3 검수담당자 배정현황
- 담당자별 배정 수량 / 검수완료 / 진행중 / 미검수 카운트 조회
- 검수담당자 변경 시 해제 → 1.3.2에서 재배정

#### 1.3.4 이관기록물검수 — 핵심 검증

**(1) 검수대상 목록 조회 조건**
- 접수년도, 검수상태(미검수/검수중/검수), 생산기관, 온/오프라인, 접수처구분, 철제목, 생산년도, 철분류번호, **기계검수상태**(진행중/완료) 등

**(2) 품질검사 현황 모니터링 — 자동 검사 7단계**
| # | 단계 | 검사 내용 |
|---|---|---|
| 1 | 규격검사 | 이관 파일 규격 일치 여부 |
| 2 | 전자서명 유효성 검사 | 전자서명 무결성 |
| 3 | 파일추출 | NEO 내부 파일 추출 |
| 4 | 1차 바이러스 검사 | 1차 백신 |
| 5 | 바이러스치료 (검출 시) | 치료 시도 |
| 6 | 2차 바이러스 검사 | 2차 백신 (다른 엔진) |
| 7 | NEO 데이터 규격검사 | NEO 메타데이터 규격 일치 |

각 단계별: 전체대상건수 / 처리건수 / 정상건수 / 오류건수 / (치료가능·불가) 카운트.
**격리영역 흐름**: 1차격리(7일 대기) → 2차격리 → 완료영역 → 인수영역. 치료 불가 시 **파일 폐기**.

**(3) 철 단위 검수 — 강제인수 메커니즘**
- 철별 오류저장: 보존분류오류 / 특수목록오류 / 기타오류 (이상내역 입력)
- 오류저장 시 **강제인수 버튼** 활성화 → 오류가 있어도 사용자 판단으로 인수 진행 가능
- NEO 버튼 → 철 NEO 파일 직접 조회

**(4) 건 단위 검수 — 육안검수 결과 등록**
- **전자기록물 오류유형**:
  파일손상 / 암호입력 / 빈문서 / 내용누락 / 그림손상 / 확장자이상 / 관인누락
- **비전자기록물 오류유형**: 실물없음
- 본문·첨부 구분에 따른 오류 선택
- NEO 뷰어로 본문·첨부 파일 직접 확인 가능
- **육안검수정보 백업/복구**: 검수 결과를 백업해두고 필요시 복구

**(5) 기계검수 — DFR 서버 활용**
- DFR(Digital File Review?) 서버에 접수번호 단위로 검사 요청
- 자동 식별: **다중식별 / 확장자오기재 / 서명불일치 / 빈문서**
- 사람 검수 부담 경감 + 시스템 오류 자동 탐지

#### 1.3.5 전자기록물검수 (=전수검수)
- 일일 할당된 전자기록물 건만 조회 → 검수
- 기존 4단계(기관→철→건→결과)를 1단계로 압축

#### 1.3.6 N차 품질검사 — 검수의 검수
- **목적**: 육안검수자의 결과를 **품질검사자가 재검사** → 오검수율 측정
- 검사자 배정 → 품질검사 진행 → 오검수보정 → 결과
- **재검수 vs 오검수보정완료**:
  - 재검수: 육안검수자에게 다시 요청
  - 오검수보정완료: 품질검사자가 직접 수정 후 다음 단계

#### 1.3.7 기록물인수확정 — 4단계 확정

| 단계 | 화면 | 동작 |
|---|---|---|
| 1) 접수번호 목록 | 기관별 회차별 | 철 인수확정 / 반려 선정 / 확정통보 분기 |
| 2) 철별 인수확정 | 철 목록 | 선택 철 인수확정 → 위치/상태 변경 |
| 3) 접수번호별 인수확정 | 기관별 회차별 철 | 최종 확정 처리 |
| 4) 관리번호 부여 | 확정된 철 목록 | 보존시설 + 기록물유형으로 **자동 생성** |

**인수확정 시 위치·상태 변경**:
- **전자 철** → 전자서고/확인 상태
- **비전자/혼용 철** → 기록물인수/확인 상태

**관리번호 부여 규칙**: 유지보수 게시판 자료실 별도 다운로드 (매뉴얼 본문에 미공개)

#### 1.3.8 비전자기록물 실물확인 — 인수확정 이후 후속
- 이관 검수 시 "실물미확인" 상태로 인수확정된 기록물 + 비전자 붙임문서 포함 기록물 별도 관리
- **실물확인 처리 시 CAMS 관리기록물로 등록** ← 비전자는 이 단계까지 가야 정식 등록
- 검수구분: 비전자건실물확인 / 비전자붙임문서

#### 1.3.9 기록물현황

#### 1.3.10 인수기록물수정

배경: 2016년 "전자기록물 이관규격 간소화" 추진. 2017년 NEO 규격 변경과 함께 V2.0 시행.

## 6. 시청각기록물의 특수성

- 인수 접수 시 **원본매체유형을 수동 지정해야** 인수 완료 가능
- 매뉴얼 2.4.1(5/5)에서 별도 절로 분리
- 시청각 메타데이터는 인수 후 SV_ARCHIVE_ADDITION_ITEM 등 SV_* 부속 테이블에 적재 (이는 인수 매뉴얼 범위 외 — 등록 매뉴얼 A02에서 다룸)
- **이유**: 일반 문서는 NEO 자체가 메타를 충분히 담지만, 시청각은 원본매체 종류(필름·디지털 마스터·테이프 등) 정보가 NEO 외부에서 결정되어야 함

## 7. 인수 영역 → 관리 영역 승격 흐름

```
인수 영역 (임시)                       관리 영역 (정식)
─────────────────                  ─────────────────
RG_M* (인수영역 마스터, 추정)     →   RG_DOCUMENT (정식 마스터)
RG_TDOCUMENT (임시기록물철)       →   RG_DOCUMENT
RG_TGOVTINFO (임시정부간행물)     →   RG_GOVTINFO
RG_SDOCUMENT / RG_SDETAIL         →   RG_DOCUMENT / RG_DETAIL
(인수전용 미러)                      (모든 유형 마스터)

키 변환: MBSID/MDSID → BSID/DSID
상태 변환: 인수영역 → 전자서고/확인 또는 기록물인수/확인
```

**비전자기록물 추가 단계**:
인수확정만으로는 정식 등록 안 됨 → **§1.3.8 실물확인 처리**까지 가야 RG_DOCUMENT 등록.

## 10. 핵심 정리 — 이 단계가 끝나면 결정되는 것들

1. **무엇이 CAMS에 들어왔는가** — BSID/DSID 발급
2. **어떤 유형인가** — DOCTYPE 14종 중 분기
3. **전자/비전자/혼용 구분** — 후속 처리 분기
4. **품질 검증 통과 여부** — NEO 무결성, 바이러스, 규격
5. **사람의 육안 검토 통과 여부** — 파일손상·내용누락 등
6. **관리번호 부여** — CAMS 내부 영구 식별자
7. **위치/상태 초기값** — 전자서고/확인 또는 기록물인수/확인
8. **RFID 태그 발행** (비전자) — 물리 위치 추적 준비
9. **국가기록포털 공개** — 외부 서비스 시작
10. **다음 단계(정리)로 이동 또는 대기** — 비전자/혼용은 정리의뢰, 전자는 자동 진행
