## 4. B-3 예외 처리 (3건) — 옵션 C 채택

### 4-1. 배경
다음 3건은 **행안부 단어 의미와 RAMP 의미가 완전히 다름**:

| 영문약어 | 행안부 한글 | RAMP 한글 |
|---|---|---|
| SEQ | 순서 | 순번 |
| ELCT | 전자계약 | 전자 |
| SQL | SQL | 질의 |

→ RAMP 사용자는 SEQ를 '순번'으로, ELCT를 '전자'(전자기록물 등)로, SQL을 '질의'로 이해. 행안부 단어로 해석하면 컬럼 의미가 깨짐.

### 4-2. 검토한 옵션

| 옵션 | 처리 | KEY 영향 | 정책 |
|---|---|---|---|
| A. 행안부 Y→N + RAMP 메인 | 행안부 강등, RAMP 메인 채택, 영향 용어 삭제 | 🔴 큼 (순번 PK 41/58) | R1 위반 |
| B. 일반 Case2처럼 새 약어 부여 | 행안부 유지. RAMP는 새 약어 (예: SEQ→SEQNO) | 🟡 RAMP 컬럼 영문 변경 | R1 준수 |
| **C. RAMP 단어 등록 자체 안 함** | RAMP 컬럼명 영문/한글 그대로. RAMP 사전에서 단어만 빼고 비고 기록 | 🟢 없음 | R1 준수 |

### 4-3. 채택 — 옵션 C

**사유**: 'KEY 위주 전체 변경은 위험' (사용자 판단). 순번(SEQ)이 RAMP 스키마에서 PK 71% (41/58) 차지 — 변경 시 마이그레이션 사고 위험.

**처리**:
- RAMP 사전 1,573건에서 '순번'·'전자'·'질의' 3건 등록 대상 제외
- RAMP 컬럼명 영문(SEQ, ELCT, SQL) 그대로 유지
- RAMP 컬럼 한글 코멘트도 '순번', '전자', '질의' 그대로 유지
- 행안부 'Y' 단어 (순서, 전자계약, SQL) 그대로 유지 — 변경 없음
- **dataQ DB 내에서 같은 영문약어가 두 의미를 가짐**:
  - SEQ → 행안부 '순서' (Y) / RAMP 컨텍스트에서는 '순번'으로 해석
  - ELCT → 행안부 '전자계약' (Y) / RAMP 컨텍스트에서는 '전자'로 해석
  - SQL → 행안부 'SQL' (Y) / RAMP 컨텍스트에서는 '질의'로 해석

### 4-4. 예외 인지 사항

- **이 3건은 단어 표준화의 일반 원칙에서 벗어남**. 통합 시스템에서 영문약어가 단일 의미를 가지지 않음
- 향후 단어 분해 시 SEQ/ELCT/SQL을 만나면 **테이블 출처(RAMP인지 행안부 표준 어휘인지)에 따라 의미 다름** 인지 필요
- Phase 2 (용어 통일/분리) 단계에서 이 영문약어를 가진 용어는 별도 분기 처리 필요
- BEFORE/AFTER 작업 시 이 3건은 변경 사항 없음 (KEEP)

### 4-5. 영향 — 행안부 용어 처리
사용자 추가 지시 ("해당 단어로 만들어진 용어들은 삭제하고 기록으로 남기기"):
- 옵션 C 채택 시 행안부 단어는 손대지 않으므로, 행안부 용어 13,159건 중 SEQ/ELCT/SQL로 시작·구성된 용어도 그대로 보존
- 단, **RAMP 컨텍스트 용어**가 별도로 생성될 때 같은 영문약어로 충돌 발생 가능 → Phase 3 용어사전 재정의 시 해결

## 4-X. 보류 안건 (향후 결정 가능)

### 4-X-1. 기록물철 단어 — RAMP 우선 검토

| 구분 | 값 |
|---|---|
| RAMP 한글 | 기록물철 |
| RAMP 영문약어 | **FLS** |
| 행안부 한글 | 기록물철 (동일) |
| 행안부 영문약어 | **RCDSF** |
| 현재 분류 | Case 1 (한글 같음, 약어 다름) |
| 현재 처리 | 행안부 RCDSF로 흡수 (RAMP 컬럼 FLS → RCDSF, **234컬럼 영향**) |

**보류 안건 (B-3 옵션 A 패턴)**:
- 행안부 'Y' 단어 `기록물철/RCDSF` 를 `Y→N` 강등 또는 DELETE
- 행안부 'Y' 용어 중 RCDSF 사용분 처리 (다수 예상)
- RAMP 단어 `기록물철/FLS` 를 메인으로 유지
- 결과: RAMP 컬럼의 fls_id·fls_* 등 모두 그대로 유지

**검토 사유**:
- FLS = RAMP의 핵심 PK 토큰 (`tb_rdfolder.fls_id` 등)
- **234컬럼 영향** — RAMP 스키마에서 가장 큰 단어 변경 (Case 1 영문 변경 1순위)
- **FLS가 너무 광범위하게 사용 중** — 개발자·유지보수 인력 모두 FLS 명명에 익숙. 컬럼명·코드·문서·SQL 쿼리 등 운영 전반에 깊이 박혀 있음
- KEY 안전 회피 관점에서 SEQ/ELCT/SQL 처리와 동일한 논리
- 변경 비용 (개발 코드·유지보수 매뉴얼·운영 도구 수정) 이 행안부 흡수 이득을 초과할 가능성

**사용자 코멘트 (2026-05-23)**: "FLS를 너무 많이 쓰고 있어서 개발자나 유지보수도 전부 FLS로 쓰고 있을 것이란 말이지. 만약에 너무 많은 변경이 힘들다 그러면 FLS를 다시 사용할 생각도 있음."

**결정 상태**: **보류 (RAMP 우선 채택 가능성 높음)**. Phase 2 진행 중 변경 비용 평가 후 확정. 만약 RAMP 우선 채택되면:
- Phase1 §4 B-3 예외 케이스에 추가 (3 → 4건)
- Phase 2-1 BEFORE/AFTER 재생성 필요 (234컬럼이 변경 → KEEP으로 전환)
- 행안부 'Y' 단어 RCDSF + 사용 용어 백업·DELETE (B-3 패턴)
- RAMP `기록물철/FLS` 를 N으로 등록
