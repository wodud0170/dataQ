# CAMS ↔ RAMP DB 통합 분석

> CAMS(국가기록원 통합관리시스템)와 RAMP(=RMS 개선시스템) **DB 통합** 과제 전용 폴더.
> CAMS의 단어/도메인 표준화 작업(`../`)과는 **별도로 진행**됨.

---

## 📌 프로세스 변경 (2026-05-19)

### 이전 흐름 (시스템 경계가 있던 시절)
```
RMS(RAMP) → 영구이관 대상(10년+ 등) → CAMS DB로 ETL 이관
```

### 통합 후 흐름
```
단일 DB — "이관"은 시스템 경계가 아니라 라이프사이클 단계
```

### 표준화·매핑 작업 정책
- **이전 계획**: CAMS 표준화 → CAMS 기준 통합
- **현재 계획**: 원시(표준화 이전) 컬럼 매칭 우선 → 표준화는 후속
- **변경 이유**: 표준화된 명으로는 구 DB 사용자와 소통 곤란

### 통합 범위
- ✅ **비즈니스(기록물관리) 위주 테이블** 통합 대상
- ⛔ **곁가지(사용자·메뉴·권한·시스템 설정)** 통합 대상 제외 — 통합 후 신규 구성

### 분리된 작업 영역

| 영역 | 위치 | 내용 |
|---|---|---|
| **CAMS 단어 표준화** | `../` (CAMS표준화/) | 단어 145건 적재 완료, 용어·컬럼명 통일 후속 |
| **RAMP·통합 분석** | **본 폴더** | RAMP 진단, CAMS↔RAMP 매핑, 통합 가능성 |

두 작업은 **병행 가능**하며 서로 차단하지 않음. 다만 통합 매핑은 **원시 컬럼 기준**이라 CAMS 표준화 결과를 기다리지 않음.

## ⭐ 통합 핵심 메인테이블 4개

| CAMS | 컬럼 | RAMP | 컬럼 | 키 매핑 |
|---|---|---|---|---|
| **RG_DOCUMENT** | 110 | **tb_rdfolder** | 170 | `BSID` ↔ `fls_id` |
| **RG_DETAIL** | 99 | **tb_rdrecord** | 149 | `DSID` ↔ `ritm_id` |

이 4개가 통합의 기준점. 다른 모든 테이블은 이들에 종속. 컬럼 매핑 작업은 이 4개부터.

---

## 🔑 통합 매핑 정책 (확정 2026-05-19)

1. **표준화 이전(원시 상태)** 기준으로 매핑한다 — CAMS 표준화 결과 대기 안 함.
2. **RAMP를 표준 기준으로 간주** (RAMP의 R8 미준수 등을 인지하나 그래도 우선).
3. **매칭 성공 = CAMS 컬럼명을 RAMP 컬럼명으로 변경(흡수)** — RAMP 명명이 승자, CAMS 영문명은 매핑 테이블로만 보존.

## ⚠️ 데이터 접근성 비대칭

| 시스템 | 데이터 |
|---|---|
| **RAMP** | 향후 실제 데이터 조회 가능 |
| **CAMS** | **영영 접근 불가** — 메타데이터(스키마)만 |

→ 값 공간 충돌 검사·실데이터 검증은 RAMP 측에서만 가능. CAMS는 ID 생성규칙·도메인·코멘트 기반 추론.
