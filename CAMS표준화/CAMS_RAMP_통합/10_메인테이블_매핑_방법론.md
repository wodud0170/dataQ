# 메인테이블 컬럼 매핑 방법론 및 근거 프레임워크

> CAMS↔RAMP 통합을 위한 **컬럼 단위 매핑 작업의 근거 문서**.
> 통합팀이 매핑 결과(TSV)를 검토할 때 **신뢰의 기준**으로 사용.
> 매핑 결과물(TSV) 작성 전 본 문서가 우선.

---

## 1. 왜 방법론 문서가 먼저인가

컬럼 매핑은 결과(TSV)만으로는 검토가 불가능하다. 통합팀이 매핑 결과를 채택하려면 다음이 명시돼 있어야 한다:

- **어떤 신호**로 두 컬럼을 같다고 보았는가
- **신뢰도**가 얼마나 되는가 (확정 vs 추정)
- 매핑이 모호한 경우 **어떻게 처리**했는가
- **틀릴 수 있는 케이스**는 무엇인가
- 결과를 **어떻게 검증**할 수 있는가

본 문서는 위 질문에 대한 답을 미리 정해두고, **모든 매핑 결과를 이 기준에 비추어 검토 가능하게** 만든다.

## 2. 매핑 대상 — 핵심 메인테이블 4개

| 위치   | CAMS          | 컬럼수 | RAMP          | 컬럼수 |
| ---- | ------------- | --- | ------------- | --- |
| 기록물철 | `RG_DOCUMENT` | 110 | `tb_rdfolder` | 170 |
| 기록물건 | `RG_DETAIL`   | 99  | `tb_rdrecord` | 149 |

**합계**: CAMS 209컬럼 ↔ RAMP 319컬럼. 매핑은 양방향 검사로 진행 — CAMS→RAMP, RAMP→CAMS 양쪽 다 결락 확인.

### 두 테이블이 같은 단위인가 — 등가성 근거
1. **업무 위치 동일**: 양쪽 모두 "정식 등록된 기록물(철·건)"의 핵심 마스터.
   - CAMS: 이관·검수 후 RG_M*→RG_DOCUMENT/DETAIL 로 승격
   - RAMP: 인수계획·검수 후 tb_rd*에 정식 등록
2. **키 매핑 사용자 확정** (2026-05-19):
   - BSID ↔ fls_id (기록물철)
   - DSID ↔ ritm_id (기록물건)
3. **참조 관계 일치**: RG_DETAIL은 (BSID,DSID) 복합으로 부모 RG_DOCUMENT 참조. tb_rdrecord는 fls_id로 부모 tb_rdfolder 참조.

→ 두 테이블 쌍은 **동일 업무 단위**임이 확정. 컬럼 매핑은 의미 있는 작업.

## 3. 매핑 신호 (Signals)

각 컬럼 매핑은 **신호의 결합**으로 도출. 단일 신호로는 매칭 결정 안 함.

### S1. 한글명 동일/유사 (가장 강한 신호)
- **S1a 완전일치**: CAMS 컬럼코멘트 == RAMP 컬럼한글명 → 강한 매칭 후보
- **S1b 부분일치**: 핵심 명사 공통, 수식어 차이 (예: `등록일시` ↔ `최초등록일시`)
- **S1c 동의어**: 행안부 표준 변형어 관계 (`년도` ↔ `연도`, `순번` ↔ `일련번호`)

### S2. 영문명 패턴 일치
- CAMS의 영문명 약어와 RAMP의 영문명 (snake_case 풀이름) 사이의 의미 매칭.
- 예: CAMS `FST_REG_DT`(최초등록일시) ↔ RAMP `reg_dt`(등록일시) 또는 더 정확히는 `first_reg_dt` 류.
- 영문명 직접 일치는 드물 것(CAMS는 약어, RAMP는 단어 조합).

### S3. 데이터타입 + 길이 호환
- 타입·길이가 같으면 매칭 확률 높음.
- CAMS `VARCHAR2(N)` ↔ RAMP `STRING(N)` 동일 처리 (이름만 다름).
- CAMS `NUMBER(N)` ↔ RAMP `NUMERIC(N)` 동일 처리.
- CAMS `DATE` ↔ RAMP `DATETIME`/`STRING(14)` (RAMP는 시간 컬럼이 대부분 STRING).
- **길이 불일치**: 같은 의미라도 길이 다르면 메모(예: BSID 12 ↔ fls_id 14 같은 사용자 확정 케이스).

### S4. PK/FK 위치 일치
- 양쪽 모두 PK인 컬럼 또는 양쪽 모두 FK인 컬럼은 매칭 강하게 추정.
- 자식 테이블의 부모 키 위치 등 구조 신호.

### S5. 업무 의미 추론
- 컬럼이 속한 컬럼 그룹·코멘트 문맥으로 의미 추정.
- 예: `생산년도` 인근에 `생산시스템코드`·`생산일시`가 있으면 "생산 메타" 그룹으로 묶임.

### S6. 사용자 확정 매핑 (메모리·결정 기록)
- 이미 확정된 키 매핑(BSID↔fls_id 등)은 신호 검토 없이 적용.

## 4. 신뢰도 등급 (Confidence)

각 매핑 행은 다음 4단계 중 하나로 등급화:

| 등급 | 정의 | 적용 기준 |
|---|---|---|
| **A 확정** | 사용자 확정 또는 다중 강신호 일치 | S1a + S3 일치, 또는 S6 확정 |
| **B 후보** | 강신호 1개 + 보조신호 1개 이상 | S1a 또는 (S1b + S3) |
| **C 추정** | 약한 신호만 있음, 사람 확인 권장 | S1c 또는 S5만 |
| **D 불명** | 매칭 후보 없음 | 한 쪽에만 존재 |

→ TSV의 `신뢰도` 컬럼에 A/B/C/D 부여. 통합팀은 **A는 일괄 수용**, **B는 샘플 검토**, **C는 전수 검토**, **D는 신규 컬럼 또는 폐기 검토**.

---

## 5. 모호성 처리 (1:N, N:1)

| 케이스 | 처리 |
|---|---|
| CAMS 1컬럼 ↔ RAMP N컬럼 후보 | TSV에 N행 기록, 신뢰도 모두 C 이하, 비고에 "다중 후보" |
| CAMS N컬럼 ↔ RAMP 1컬럼 | 동일하게 N행 기록 |
| 의미 합쳐짐(CAMS 분리된 2컬럼 → RAMP 1컬럼) | 비고 "병합 매핑" 표시 |
| 의미 갈라짐(CAMS 1컬럼 → RAMP 분리된 2컬럼) | 비고 "분할 매핑" 표시 |

→ **사람이 보고 판단**하라는 신호 — 자동 결정 안 함.

---

## 6. 데이터 접근성 제약

| 시스템 | 접근 | 매핑에 미치는 영향 |
|---|---|---|
| **CAMS** | 데이터 영영 불가, 메타데이터만 | 값 공간 비교·실데이터 추론 불가. **S1/S3/S5만 사용 가능** |
| **RAMP** | 향후 실데이터 조회 가능 | 충돌·중복·실제 분포는 RAMP 확보 후 검증 |

→ 현 매핑은 **순수 메타데이터 기반**. 값 일치 검증은 미래 단계. 신뢰도 A라도 RAMP 실데이터로 재검증 권장.

---

## 7. 매핑 결과물 형식 (TSV 스펙)

`메인테이블_매핑.tsv` 파일은 다음 컬럼을 가진다 (각 행 = 1개 매핑 또는 1개 단방향 미매핑):

| 컬럼 | 내용 |
|---|---|
| `pair` | `철` / `건` — 어느 테이블 쌍인지 |
| `CAMS_영문명` | CAMS 컬럼 영문명 (없으면 빈칸) |
| `CAMS_코멘트` | CAMS 컬럼 한글 코멘트 |
| `CAMS_타입` | VARCHAR2(N) / NUMBER(N) / DATE 등 |
| `RAMP_영문명` | RAMP 컬럼 영문명 (없으면 빈칸) |
| `RAMP_한글명` | RAMP 컬럼 한글명 |
| `RAMP_타입` | STRING(N) / NUMERIC(N) / DATETIME 등 |
| `매핑방향` | 양방향 / CAMS→RAMP 단방향 / RAMP→CAMS 단방향 / 미매핑 |
| `신호` | 적용된 신호 코드 (예: `S1a+S3` ) |
| `신뢰도` | A / B / C / D |
| `흡수 후 컬럼명` | 통합 후 사용할 컬럼명 (정책: RAMP 영문명) |
| `비고` | 모호성·주의사항·근거 메모 |

→ 통합팀이 행 단위로 검토 가능. 신뢰도로 필터링.

## 8. 검증·검토 절차

매핑 TSV가 작성되면 통합팀은 다음 순서로 검토:

1. **A 등급 (확정) 일괄 검토** — 사용자 확정·다중 강신호. 샘플 점검 후 일괄 수용.
2. **B 등급 (후보) 그룹별 검토** — 비슷한 패턴끼리 묶어 검토.
3. **C 등급 (추정) 전수 검토** — 1건씩 사람 판단.
4. **D 등급 (미매핑) 정책 결정**
   - CAMS-only: 통합 후 RAMP에 신규 컬럼 추가? 폐기? 매핑테이블 보존?
   - RAMP-only: 그대로 유지 (현재 RAMP에 있으니까)
5. **실데이터 검증** — RAMP 데이터 확보 후 A·B 등급 샘플 검증.

---

## 9. 본 방법론의 한계

- **CAMS 데이터 미접근**으로 인한 본질적 추론 한계. 신뢰도 A라도 100%가 아님.
- **RAMP의 표준화 불완전**(R8 미준수 등 인지) — RAMP 컬럼명이 항상 좋은 이름은 아님.
- **컬럼 코멘트 품질 차이**: CAMS는 컬럼 코멘트가 풍부, RAMP는 컬럼한글명+설명 분리. 매칭 시 기준 달라질 수 있음.
- **자동 매칭의 한계**: 같은 의미인데 표기 완전 다른 케이스(외래어 vs 우리말 등)는 자동 검출 어려움.

→ 따라서 본 매핑은 **첫 안**이며, 통합팀 검토·수정이 본 작업의 핵심.

---

## 10. 본 문서의 위치

- 본 문서 = **합의 기준점**. 매핑 TSV의 모든 행은 이 문서에 정의된 신호·신뢰도·정책에 부합해야 함.
- 통합팀이 본 방법론에 이의가 있으면 매핑 시작 전에 본 문서 먼저 수정.
- 매핑 결과(TSV) 작성 후 본 문서를 변경하지 않음 (기준 변경은 모든 행 재검증을 의미).
