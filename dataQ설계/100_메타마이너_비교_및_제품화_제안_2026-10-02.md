## 0. 요약

- **MetaMiner 는 금융권 전사 메타데이터 관리의 허브 제품**이다. 지티원은 메타·품질·리니지·카탈로그·SQL 분석·금융 컴플라이언스를 한 회사에서 판다. 2025 예상 매출 350억, 2026 목표 400억. MetaMiner6 는 2024-06 GS인증 1등급.
- **기능 폭에서는 정면승부가 안 된다.** 컬럼 레벨 리니지(DataHawk), 노코드 워크플로우 디자이너, CASE 툴 연계, 다국어, 별도 품질 제품(DQMiner6)까지 갖췄다.
- **이길 수 있는 곳은 "표준화 작업 그 자체"** 다. 한글명 → 표준용어 자동 도출, 사전별 표준화 관례, 진단 → 조치 스크립트. 다만 MetaMiner 쪽도 "자동 용어 관리"·"스크립트 자동 생성" 을 내세우고 있어, 세부 비교 전까지는 **우위 가능성**이지 확정이 아니다.
- **가장 구체적인 무기는 SMETA 자료 흡수력**이다. 공공 메타시장 1위 SMETA 의 등록자료를 우리 모델에 그대로 올릴 수 있음을 RAMS 자료로 확인했다(§4.3). 노후 메타시스템 교체 수요를 노릴 수 있다.

**제품화 핵심 3가지** — (1) GS인증 1등급 완주 + 제품명 단일화, (2) "표준화 진단·정비" 포지션으로 공공 진입, (3) 품질진단을 별도 제품으로 상품화.

## 2. MetaMiner 기능 (공개 자료 기준)

**제품 페이지 기능 목록** — 데이터 표준 관리(도메인·코드·금칙어) / 데이터 모델 관리 / 메타데이터 수집 및 동기화(이기종 DBMS + CASE 툴) / 데이터 플로우 기반 영향도 분석 / 워크플로우 관리 / 메타데이터 검증 / XML 기반 데이터 교환 / 스크립트 자동 생성 / XML 템플릿 리포트 / Model Viewer

**아키텍처** — OMG **CWM** 기반 중앙 리파지토리. 워크플로우 엔진 + **워크플로우 디자이너**("추가 코딩 없이 결재 프로세스 수정"). 다국어 지원.

**진단 지표** — "Compliance Level for standard, and Alignment and Similarity Level for models". 표준 준수도와 모델 정합도·유사도를 따로 잰다.

**버전 이력에서 확인되는 것**
- 5.3 (2019) — DQMiner 실시간 연동, **국립국어원 사전 연동**, 리파지토리 DB 확대(DB2·MySQL). 같은 기사에 "업무별 표준사전 구축, 자동 용어 관리" 언급
- 6 (2024) — 환경 설정만으로 워크플로우 구성, **CASE 툴 없이 ERD 조회**, 메타데이터 라이프사이클·연관관계, **갭 분석**(여러 테이블 컬럼 일치 여부를 한 화면에서)

**함께 팔리는 제품**
- **DataHawk** — 컬럼 레벨 리니지. SQL·PL/SQL·Java·C 소스 파싱, Informatica·DataStage·MSTR, 80개 이상 언어
- **DQMiner6** — 자동 프로파일링, 데이터 오디팅, 룰 관리, 품질 분석·보고, 상시 모니터링
- **MetaCatalog v3** (2026-02) — 비정형 문서(PDF·Word·PPT) 메타 자동 추출, ML 자동 태깅, **LLM 설명 자동 작성**

### 2.1 AI 동향 — 오인 주의

**MetaMiner 에서 확인된 AI** (컴퓨터월드 2025-09-30, "AI 이네이블 메타마이너·DQ마이너")
- 품질 검증용 **업무 규칙 SQL 의 LLM 프롬프트화**, 프롬프트 검색·관리
- LLM 이 업무 규칙 설명문 자동 작성
- 에이전틱 AI — 신제품 출시 시 영향도 분석, 품질·컴플라이언스 자동 검토, 리스크 정량 평가

즉 **MetaMiner 의 AI 는 품질 규칙과 영향도 쪽**이다.

> **⚠ "표준 사전 자동 구축 · 모델 자동 현행화 · 주제별 자동 매핑" 은 MetaMiner 기능이 아니다.**
> 검색 요약이 MetaMiner 로 붙여 놨는데, 원문(컴퓨터월드 2025-07-31 기획특집)을 확인하니
> **엔코아 META# AI** 설명이었다. 표준화 자동화로 직접 부딪칠 상대는 지티원이 아니라 엔코아다.
> 이 문서를 근거로 영업 자료를 만들 때 이 부분을 섞지 말 것.

### 3.1 판정 요약

- **확실한 열세** — 수집 DBMS 범위, 워크플로우, 영향도·리니지, 보고서, 인증, 레퍼런스 규모
- **확인된 우위는 아직 없다.** 우위 가능 2건(표준화 자동 추천, 진단 → 조치)은 상대 쪽이 `?` 다. 데모나 매뉴얼로 세부를 확인하기 전까지 영업 자료에 "MetaMiner 대비 우위" 로 쓰면 안 된다
- 우리가 **설명할 수 있는 고유점**은 사전별 표준화 관례(98번)다. 같은 인스턴스에서 행안부 공통표준 사전과 기관 자체 사전을 각자의 규칙으로 돌린다. "업무별 표준사전" 을 MetaMiner 도 말하지만 사전마다 규칙을 달리하는지는 확인되지 않았다

## 4. 어디서 이길 수 있나

### 4.1 금융은 들어갈 자리가 아니다

MetaMiner 고객은 은행·증권·보험이고, 이들은 메타 + 리니지 + 품질 + 금융 컴플라이언스(AML 등)를 **한 회사 제품군으로 묶어서** 산다. 우리에겐 그 묶음이 없다. 단품 메타로 비집고 들어갈 이유를 만들기 어렵다.

### 4.2 공공은 SMETA 가 1위지만 "작업 도구" 자리가 비어 있다

공공 메타관리는 SMETA 가 조달 디지털서비스몰 기준 67% (2023, 10번 문서). MetaMiner 의 공공 MMS 수주는 공개 기사에서 확인하지 못했다.

공공 기관에 필요한 건 메타시스템 그 자체보다 **표준 준수율을 올리는 작업**이다. 수천 개 컬럼을 사전과 맞추고, 미등록 단어를 정리하고, 조치 스크립트를 뽑는 일. 우리 제품이 가장 공을 들인 곳이 여기다.

→ 포지션: **"표준화 진단·정비" 도구**. 신규 구축이면 메타시스템으로, 이미 메타시스템이 있는 기관이면 정비 프로젝트 도구로 들어간다.

### 4.3 가장 구체적인 무기 — SMETA 자료를 그대로 흡수한다

국가기록원 RAMS 신규 구축 자료(SMETA 등록자료 0908판)로 확인한 것:

| 자료 | 건수 |
|---|---:|
| 단어 | 3,497 |
| 도메인 | 642 |
| 용어 | 14,972 |

SMETA 도메인의 `분류어` 는 영문약어 목록이고, 고유 696개다. 이걸 우리 사전의 형식단어로 두면 **용어 14,972건 중 14,965건(100.0%)** 의 끝단어가 정합한다. 예외 7건은 `BKNM`(서명)·`DESCR`(기술) 두 단어가 분류어 목록에서 빠진 것뿐이다.

즉 **SMETA 의 표준화 관례를 우리 사전 세트가 손실 없이 표현한다.** 사전별로 형식단어 집합을 달리 둘 수 있게 만든 98번 덕분이다.

수협중앙회는 2025년 도입 10년 된 메타시스템을 교체했다(위세아이텍 WiseMeta 5.0 수주, 컴퓨터월드 2025-05-31). **노후 메타시스템 교체 시장이 있다.** SMETA 자료 이관 도구를 제품 기능으로 넣으면 그 시장의 전환 비용을 우리가 낮춰줄 수 있다 (§6.3).

## 6. 제품화 제안

### 6.1 제품명 단일화 — 결정 필요

지금 한 제품이 네 이름으로 불린다.

| 위치 | 표기 |
|---|---|
| GS인증 상담요청서·제품설명서·사용자 매뉴얼 (`GS인증/`) | **NavidM Meta** V1.0 |
| 브라우저 탭 제목 (`q-center/vue/front/index.html`) | Navid Meta |
| 매뉴얼·소개자료 생성기 (`dataQ설계/manual/`) | Navid Meta |
| Swagger API 문서 제목 (`SwaggerConfig.java`) | Narae DataQ |

GS 시험(ISO/IEC 25051 기준)은 제품설명서·사용자취급설명서가 **실제 제품과 일치하는지**를 본다. 신청서는 `NavidM Meta` 인데 화면 탭에는 `Navid Meta` 가 뜬다. 시험 전에 하나로 맞춰야 한다.

GS 신청 제품명은 대표님이 `NavidM Meta` 로 정했다. 화면·매뉴얼을 그쪽으로 맞출지, 신청서를 바꿀지는 결정 사항이라 **이 문서에서는 아무것도 바꾸지 않았다.**

### 6.2 포지셔닝 — "표준화 진단·정비"

| 고객 상황 | 우리 제품의 역할 |
|---|---|
| 신규 구축 (RAMS 형) | 설계 초안 → 표준 적용 → 진단 → DB 반영까지 메타시스템으로 |
| 이미 메타시스템이 있는 기관 | 표준 준수율 진단·정비 프로젝트 도구로. 기존 시스템과 경쟁하지 않고 옆에 선다 |
| 노후 메타시스템 교체 | SMETA 자료 이관 도구로 전환 비용을 낮춘다 (§6.3) |

메시지는 하나로 — **"표준을 문서가 아니라 DB 에 적용한다."** 소개자료(`dataQ설계/manual/build_intro.py`) 표지 문구 "표준은 문서에 있고, 데이터는 DB 에 있다" 와 같은 축이다.

### 6.3 SMETA 자료 이관 도구를 제품 기능으로

지금 SMETA 자료를 올리려면 엑셀 양식을 손으로 바꿔야 한다. 영문약어·영문명 열 순서가 반대고, 형식단어여부가 없어 도메인 `분류어` 에서 도출해야 하는 등 규칙이 있다. 이 변환을 **[SMETA 자료 가져오기]** 기능으로 넣는다.

- 입력: SMETA 등록자료 4종(단어·도메인·용어·테이블 목록) 그대로
- 처리: 사전 생성 → 도메인그룹·분류 → 단어(분류어 → 형식단어 도출) → 도메인 → 용어 → 테이블·컬럼
- 사람이 정할 것만 화면에 띄움 — RAMS 자료 기준 **도메인그룹이 갈리는 분류어 8개**(CD·YN·ID·EN·GRD·LV·SYMBL·EXTN)

RAMS 적재를 이 기능의 첫 실사용으로 삼으면 일회성 변환 스크립트가 제품 기능으로 남는다.

### 6.4 라인업 — 5/13 결정의 연장선

2026-05-13 "영업 라인업 분리" 결정으로 데이터 품질 진단 메뉴를 껐다. 코드는 살아 있다(94번 §0-2). 경쟁사는 전부 2제품 체계다.

| 회사 | 메타 | 품질 |
|---|---|---|
| 지티원 | MetaMiner6 | DQMiner6 |
| 위세아이텍 | WiseMeta | WiseDQ |
| 비투엔 | SMETA | SDQ |
| **우리** | NavidM Meta | **(미정 — 코드 있음, 메뉴 비활성)** |

품질을 **별도 제품으로 이름 붙이고 별도로 GS인증·조달 등록**하는 게 결정 취지와 맞다. 끈 채로 두면 코드만 낡는다.

### 6.5 출시 전에 정리할 것 — 제품 신뢰성

거버넌스를 파는 제품이 거버넌스를 우회하면 안 된다.

| 항목 | 근거 | 위험 |
|---|---|---|
| **승인 우회 경로** — 단건 컬럼 추가·삭제, PK/FK 조작이 88번 승인을 거치지 않음 | 94번 §0-3 | 매뉴얼은 Tier 1 승인 대상으로 기술. GS 시험에서 문서-제품 불일치로 걸릴 수 있다 |
| 엑셀 일괄등록에서 사전을 못 고름 | 99번 §3 | 지금은 무조건 기본 사전으로 들어간다. RAMS 적재 선행 조건 |
| 기본 사전으로 도는 조회 16곳 | `grep -rn "nameParam(null"` | 사전 세트의 완성도 |
| 도커 DB 이미지 스냅샷 4개월 낡음 | 99번 §0 | 배포 패키지 재현성. 지금 말면 98번 스키마가 없다 |
| 문서-코드 불일치 | 94번 §0-4 의 "PostgreSQL 수집 쿼리 0건" 은 현재 코드와 다름(4종 다 있음) | 94번을 근거로 한 판단이 틀린다. 94번 갱신 필요 |
| 대형 컨트롤러 | `DataModelController` 3,621줄, `DataStandardController` 3,296줄 | 98번 수정이 이 둘에 몰렸다. 기능 추가 속도가 여기서 막힌다 |

### 6.6 판매 모델 — 제안 수준

MetaMiner 가격은 공개돼 있지 않아 가격 비교는 하지 않는다. 방향만 적는다.

- **제품 + 표준화 정비 서비스 결합** — 데이터 표준화는 도구보다 작업이 크다. RAMS 처럼 "자료 적재 + 표준 적용 + 진단 + 반영" 까지를 한 묶음으로 판다
- 코어(표준사전·데이터모델·표준진단) / 옵션(품질진단, SMETA 이관) 으로 나눈다
- 설치형 경량 패키지(Docker 단일 tar)를 내세운다 — 폐쇄망 설치 가이드를 함께 낸다
