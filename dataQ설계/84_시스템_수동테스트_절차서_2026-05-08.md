## 시나리오 2. 표준 사전 — 단어 / 용어 / 도메인 / 승인 풀 플로우

### 2-1. 일반 사용자 등록 신청 (3건)
**준비**: jyjang 로그인 + `표준 사전 > 단어 사전`

1. [등록 신청] 클릭
2. 폼 입력:
   - 단어명: `테스트단어_A` (timestamp 추가 권장)
   - 영문명: `TST_WORD_A`
   - 약어: `TWA`
   - 설명: `수동 테스트용 단어 A`
3. [저장] 클릭
4. **기대**:
   - 성공 토스트
   - 그리드에서 `테스트단어_A` 행 확인 — APRV_YN = 'N' (승인 대기)
   - 행 클릭 시 상세에서 "승인 대기" 표시

5. 동일 절차로 `테스트단어_B` 등록 (반려 시나리오용)

6. `표준 사전 > 도메인 사전` 진입 → 도메인 1건 등록 신청
   - 도메인명: `테스트도메인_X` / 데이터타입: `VARCHAR` / 길이: `100`

7. 좌측 [내 정보] / [요청 현황] 진입
   - **기대**: 승인 대기 3건 (단어 2 + 도메인 1)

### 2-2. 관리자 승인 / 반려
**준비**: space 로그인 + `시스템 관리 > 승인 처리`

1. 그리드에서 `테스트단어_A` 체크 → [승인]
2. **기대**: 그리드에서 사라짐 (또는 상태 변경)
3. `테스트단어_B` 행 → [반려] → 사유 입력 (`테스트 반려`) → [확인]
4. `테스트도메인_X` → [승인]

### 2-3. 신청자 결과 확인
**준비**: jyjang 다시 로그인 + [요청 현황]

1. **기대**:
   - 단어A: 상태 = `승인`
   - 단어B: 상태 = `반려` + 사유 `테스트 반려`
   - 도메인X: 상태 = `승인`

### 2-4. 용어 등록 + 자동 분석 (DSTerm 1차)
**준비**: space 로그인 + `표준 사전 > 용어 사전 > [등록]`

1. 용어명 입력: `직원번호` (이미 단어 `직원`/`번호` 있다고 가정 — 없으면 미리 등록)
2. [자동 분석] 클릭
3. **기대**: 단어 분리 결과 노출 (`직원` + `번호`)
4. 분석 결과에서 단어 선택 → 도메인 자동 추천
5. [저장] → 그리드에서 확인

### 2-5. 미승인 단어 가드
**준비**: space 로그인

1. 일반 사용자가 등록한 미승인 단어 1건 존재 확인
2. 그 단어를 포함하는 용어 신청 시 → **승인 거부 메시지** 노출
3. 단어 먼저 승인 → 용어 재승인 가능

### 2-6. 글로벌 검색
1. 좌측 검색창 또는 글로벌 검색 → 키워드 `직원` 입력
2. **기대**: 단어 / 용어 / 도메인 그룹화된 결과
3. 결과 행 클릭 → 해당 화면으로 이동

### 2-7. cleanup
- 관리자 로그인 → 단어A 삭제 / 도메인X 삭제
- 또는 0-5 SQL cleanup

## 시나리오 3. 데이터 모델 (Phase 5 / 53번)

### 3-1. 모델 추가 (수동 정의)
**준비**: space 로그인 + `데이터 모델 > 데이터 모델 관리`

1. [추가] → 모달
2. 입력:
   - 모델명: `테스트모델_53`
   - 데이터소스: 드롭다운 1번째 (Oracle/Postgres 등)
   - 모델 유형: PHYSICAL
3. [저장]
4. **기대**: 그리드에 신규 행 노출 / `MODEL_TYPE='PHYSICAL'` 확인

### 3-2. 컬럼 그리드 직접 추가
1. 신규 모델 클릭 → 컬럼 화면 진입
2. [+ 행 추가] 3회 → 빈 3행 생성
3. 입력:
   | 행 | OBJ_NM | ATTR_NM | DATA_TYPE | LEN |
   |---|---|---|---|---|
   | 1 | `TMP_COL_TBL` | `TMP_COL_1` | `VARCHAR` | 50 |
   | 2 | `TMP_COL_TBL` | `TMP_COL_2` | `NUMBER` | 10 |
   | 3 | `TMP_COL_TBL` | `TMP_COL_3` | `DATE` | (비움) |
4. [저장]
5. **기대**: 3건 저장, `TERMS_STND_YN='N'` (자동 표준화 미실행)

### 3-3. 붙여넣기 (paste) 다행 입력
1. 클립보드에 다음 (탭 구분):
   ```
   PASTE_TBL	COL_PASTE_A	VARCHAR	100
   PASTE_TBL	COL_PASTE_B	NUMBER	5
   ```
2. 그리드의 빈 행 첫 셀에 클릭 → Ctrl+V
3. **기대**: 2행 자동 채워짐
4. [저장] → 성공

### 3-4. 엑셀 업로드 — 테이블 (Phase 5)
**파일**: `dataQ설계/테스트/selenium/data/test_53_tables.xlsx` (이미 있음)

1. 모델 화면 → [엑셀 업로드] → 테이블 시트
2. 파일 선택 → 업로드
3. **기대**: 테이블 N건 자동 추가, 그리드 갱신

### 3-5. 엑셀 업로드 — 컬럼 (Phase 5)
**파일**: `data/test_53_attrs.xlsx`
1. [엑셀 업로드] → 컬럼 시트
2. 업로드
3. **기대**: 매칭 OBJ_NM 의 컬럼만 INSERT (없는 OBJ_NM 은 skip 또는 에러)

### 3-6. 자동 표준화 트리거 ([해석] 버튼)
1. `TERMS_STND_YN='N'` 인 컬럼 (직전 등록한 컬럼) 선택
2. 행 [해석] 클릭 또는 일괄 [해석]
3. **기대**:
   - 한글명 → 단어 분리
   - 도메인 매핑 시도
   - `TERMS_STND_YN` 갱신 (`Y` 또는 `N` + 사유)

### 3-7. 컬럼 수정 시 메타 보존
1. 직전 컬럼 행에서 한글명 수정 → 저장
2. **기대**: `TERMS_STND_YN`, `DOMAIN_NM` 등 직전 메타 보존 (덮어쓰기 X)

### 3-8. 테이블명 변경 cascade
1. 그리드에서 `TMP_COL_TBL` → `TMP_COL_TBL_RENAMED` 변경 → 저장
2. **기대**: 해당 테이블 소속 컬럼 행들의 `OBJ_NM` 도 같이 변경

### 3-9. 단어 우선 cascade
1. 단어 사전에서 `TMP` 단어가 등록되어 있다고 가정
2. `TMP` 단어 영문명 변경 → 단어 저장
3. **기대**: `TMP` 를 포함하는 컬럼/테이블의 한글명 자동 갱신 알림

### 3-10. 물리 모델 삭제 거부
1. 데이터소스 연결되어 있는 PHYSICAL 모델 [삭제] 시도
2. **기대**: "운영 DB 연결된 물리 모델은 삭제 불가" 메시지

## 시나리오 5. 표준화 / 구조 진단 + 스케줄 (36번 / Phase 2~4)

### 5-1. 표준화 진단 즉시 실행
**준비**: PHYSICAL 모델 + 컬럼 데이터 있음

1. `표준화 진단 > 진단 실행` 진입
2. 모델 선택 → [진단 시작]
3. **기대**:
   - 진단 Job 생성 (TB_DIAG_JOB)
   - 백그라운드 q-executor 처리
   - 진단 결과 화면에서 결과 노출

### 5-2. 진단 결과 조회
1. `표준화 진단 > 진단 결과` 진입
2. 모델/Job 선택
3. **기대**:
   - 이슈 컬럼 그리드 (OBJ_NM, ATTR_NM, 이슈 유형)
   - 준수율 = (전체 - 이슈컬럼) / 전체 × 100
   - 이슈 컬럼수 = `COUNT(DISTINCT OBJ_NM || '.' || ATTR_NM) FROM TB_DIAG_RESULT`

### 5-3. 구조 변경 진단
1. 운영 DB 에 컬럼 1개 ALTER (예: VARCHAR(50) → VARCHAR(100))
2. `구조 변경 > 진단 실행`
3. **기대**:
   - TB_STRUCT_DIAG_HISTORY 신규 행
   - 변경 상세 (TB_STRUCT_DIAG_DETAIL) 1건 — 데이터 타입 길이 변경

### 5-4. 진단 스케줄 등록
**준비**: space 로그인 + `진단 스케줄`

1. [추가] → 폼
   - 스케줄명: `테스트_매일진단`
   - cron: `0 2 * * *` (매일 02:00)
   - 진단 유형: 표준화 진단
   - 모델: 1개 선택
2. [저장]
3. **기대**: 그리드에 행 추가, `USE_YN='Y'`

### 5-5. 스케줄 즉시 실행
1. 행 → [즉시 실행]
2. **기대**: 진단 Job 생성 + 결과 화면에서 확인 가능

### 5-6. 스케줄 일자/기간 필터
1. 진단 결과 화면 → 일자 범위 필터
2. **기대**: 해당 기간 내 진단만 노출

### 5-7. 일반 사용자 admin gate
1. jyjang 로그인 → 진단 스케줄 화면
2. **기대**: [추가]/[수정]/[삭제] 비활성 또는 미노출

## 시나리오 6. 진단 제외 관리 (79번)

### 6-1. 사전 준비
1. 운영 DB (Oracle 권장) 에 테스트 테이블 3개 생성
   ```sql
   CREATE TABLE IMSI_TEST_001 (id NUMBER, name VARCHAR2(50), code VARCHAR2(20));
   CREATE TABLE IMSI_TEST_002 (id NUMBER, code VARCHAR2(20), value VARCHAR2(100));
   CREATE TABLE IMSI_TEST_003 (id NUMBER, dt DATE, xyz_data VARCHAR2(50));
   ```
2. 모델 수집으로 메타 등록 또는 직접 INSERT (`TB_DATA_MODEL_OBJ` + `TB_DATA_MODEL_ATTR`)

### 6-2. 단건 OFF — 표준 진단 제외
1. `데이터 모델 > 진단 제외 관리` 진입
2. `IMSI_TEST_001` 행 → 표준 진단 토글 OFF
3. 사유 모달 → `테스트 단건 제외` 입력 → [저장]
4. **기대**:
   - `TB_DATA_MODEL_OBJ.STND_TARGET_YN = 'N'`
   - `STND_TARGET_REASON = '테스트 단건 제외'`
   - `DIAG_TARGET_UPDT_USER_ID = space`

### 6-3. 일괄 OFF — 구조 진단 제외
1. `IMSI_TEST_002` + `IMSI_TEST_003` 체크
2. [일괄] → 구조 진단 OFF + 사유 `테스트 일괄`
3. **기대**: 2건 모두 `STRUCT_TARGET_YN='N'` + 동일 사유

### 6-4. 컬럼 단건 OFF — 사유 빈칸 허용
1. `IMSI_TEST_001` 모델 컬럼 화면
2. `NAME` 컬럼 → 구조 진단 OFF
3. 사유 빈칸 → [저장]
4. **기대**: `STRUCT_TARGET_YN='N'`, `STRUCT_TARGET_REASON IS NULL`

### 6-5. 컬럼 일괄 OFF
1. `IMSI_TEST_002.CODE` + `VALUE` 체크
2. 일괄 표준 OFF + 사유 `컬럼 일괄`
3. **기대**: 2건 모두 `STND_TARGET_YN='N'`

### 6-6. 표준화 진단 모수 제외 검증
1. 진단 실행 → 결과 확인
2. **기대**:
   - `IMSI_TEST_001` 의 표준화 결과 0건 (모수 제외)
   - `IMSI_TEST_002.CODE/VALUE` 도 모수 제외
