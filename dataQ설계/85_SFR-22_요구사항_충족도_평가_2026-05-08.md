## 0-2. RFP 의도 해석 — 두 갈래 (i) vs (ii)

본 RFP 원문은 "데이터 관리 SW" 를 3개 항목으로 분해하나, **항목 B/C 의 주체가 누구인지** 가 모호. 두 가지 해석이 가능:

### 해석 (i) — DataQ 가 모든 항목을 직접 충족
- **B = DataQ 자체에 ERD 시각화 + 모델링 기능 보유 필요**
- **C = DataQ 가 외부 메타시스템 (다른 메타 솔루션) 과 연동**
- DataQ 가 모델링 SW + 메타 SW + 연계 SW 셋 다 책임

### 해석 (ii) — 발주처 의도 ★권장★
- **A**: 메타 시스템 = **DataQ 본체** (메타데이터 수집·관리 SW)
- **B**: 모델링 SW = **ERwin/DA#/PowerDesigner 같은 외부 ERD 툴** — RFP "데이터베이스모델링 관리를 위한 SW" 는 ERwin 류 모델링 도구를 의미. 발주처가 모델링 툴 라이선스/환경을 도입하고 그 설치를 지원
- **C**: 연계 모듈 = **모델링 툴 ↔ 메타 툴 (DataQ) 양방향 연동**. RFP "데이터 모델 정보와 메타데이터 관리시스템 간의 연동" 은 ERwin 모델 ↔ DataQ 메타 사이 동기화 의미

이 해석이 더 자연스러운 이유:
- "데이터 관리 SW" 라는 묶음 안에 **메타 도구 + 모델링 도구 + 연계 모듈** 셋이 따로 있는 발주는 공공 사업의 흔한 패턴 (WISE META 등에서 동일 광고)
- RFP B 의 "**원활히 편집·시각화**" 는 모델링 도구의 본연 기능. 메타 시스템 본연 기능이 아님
- RFP C 의 "**데이터 모델 정보와 메타데이터 관리시스템 간**" 은 둘이 분리된 시스템임을 명시 → 모델링 도구와 메타 시스템은 다른 시스템

### 해석 (ii) 기준 줄별 재평가

| ID | RFP 원문 | 해석 (ii) 의 책임 | 충족 | 근거 |
|---|---|---|:---:|---|
| **LA-0** | 메타데이터 수집·관리 SW | **DataQ** | ✅ | DataQ 본체 |
| **LA-1** | DB 구조 자동 수집 + 변경 이력 | DataQ | ✅ | §2 매트릭스 100% |
| **LB-0** | DB 모델링 관리 SW | **ERwin** (외부 도구 도입 지원) | ✅ | 사업 범위에 ERwin 도입 + 설치 가이드 작성으로 충족 |
| **LB-1** | 원활히 편집·시각화 + 충분한 성능 | ERwin (도구 본연 기능) | ✅ | ERwin 의 ERD 뷰어/편집기/대용량 처리는 도구 자체 검증 |
| **LC-0** | 메타시스템 연계 모듈 연동 | **DataQ ↔ ERwin** (양방향) | △ | DataQ ERwin 임포트 90% (메뉴 숨김) / 익스포트 미구현 |
| **LC-1** | 데이터 모델 정보 ↔ 메타시스템 연동 | DataQ ↔ ERwin (XML 양방향) | △ | 위와 동일 — 활성화 필요 |
| **LC-2** | 표준 포맷 추출·변환·적재 | DataQ ERwin XML / XMI export·import | △ | 추출/적재 일부 (Excel/ERwin 90%), 변환 룰 X, XMI X |

### 해석 (ii) 기준 집계
- ✅ 완전 충족 = **4줄** (LA-0, LA-1, LB-0, LB-1)
- △ 부분 충족 = **3줄** (LC-0, LC-1, LC-2)
- ❌ 미충족 = **0줄**
- → **줄 단위 충족률 = 약 79%** ((4 + 1.5) / 7)

### 해석 분기 임팩트

| 항목 | 해석 (i) | 해석 (ii) |
|---|---|---|
| 줄 단위 충족률 | 43% | **79%** |
| B 항목 작업량 | 6~17주 (자체 시각화/논리모델 등) | **0주 (ERwin 도입 가이드 1주만)** |
| C 항목 작업량 | 12~16주 (XMI 등 모든 표준) | **약 4주 (ERwin 활성화 3주 + export 1주)** |
| 입찰 가능 시점 | 13주 후 | **약 4~5주 후** |
| 1순위 작업 | 동일 (ERwin 활성화) | 동일 + ERwin XML export |

→ **해석 (ii) 가 맞다면 DataQ 는 RFP 거의 충족 상태 (79%) + 4~5주 보완으로 입찰 가능**.

→ 해석 (i)/(ii) 확정은 **발주처 사전 미팅 / RFP Q&A** 로 명확화 필요. 만약 (ii) 라고 발주처가 확인하면 입찰 자세 가 크게 달라짐 (현재 "GAP 명시" 모드 → "거의 충족 + 4주 보완" 모드).

### 발주처 확인 질문 (Q&A 항목)

> Q1. "데이터베이스모델링 관리를 위한 SW" 는 ERwin/DA# 같은 외부 모델링 도구를 의미하는지, 아니면 본 사업에서 도입할 솔루션이 자체 ERD 뷰어/편집기를 보유해야 하는지?
>
> Q2. "메타시스템 연계 모듈" 의 연계 대상은 (a) 발주처가 별도 운영 중인 또 다른 메타시스템인지, (b) 본 사업에서 도입할 모델링 도구 (ERwin 등) 와 본 사업의 메타 시스템 간의 연동인지?
>
> Q3. ERwin 라이선스/도입은 본 사업 범위에 포함되는지?
>
> Q4. "표준 포맷" 의 구체 명시 (XMI? ERwin XML? DA# XML? Excel? JSON?)

## 0-3. 발주처 발화 정보 — 해석 (ii) 사실상 확정

### 발화 내용 (사용자 → 본 분석)
> 공무원(발주처)이 "**SMETA + ERwin 구입**" 을 직접 언급함.

### 해석 임팩트
이 발화로 RFP 의 의도가 거의 명확해짐:

| RFP 항목 | 발주처가 의도한 SW | DataQ 포지션 |
|---|---|---|
| A. 메타데이터 수집·관리 | **SMETA** (또는 동급 메타 솔루션) | **SMETA 자리 후보** = DataQ 가 노리는 자리 |
| B. DB 모델링 관리 | **ERwin** (별도 라이선스/도구) | **DataQ 가 노리지 않음** — ERwin 도입 지원만 |
| C. 메타시스템 연계 모듈 | **DataQ ↔ ERwin 양방향 연동** | **DataQ 가 책임** (ERwin XML import/export) |

→ **해석 (ii) 가 사실상 확정** (신뢰도 95%+). 본 분석의 (i) 가정은 폐기 가능.

### DataQ 의 입찰 포지션 재정의
- **노리는 자리**: SMETA 의 자리 (메타데이터 수집·관리 시스템) = RFP A
- **경쟁자**: SMETA (비투엔)
- **별도 도구 (ERwin)**: 본 사업에서 발주처가 별도 도입. DataQ 가 만들 필요 X. 단 ERwin과의 연동은 책임
- **C 항목의 의미**: SMETA(또는 DataQ) ↔ ERwin 양방향 = ERwin XML 양방향 + (선택) XMI

### 충족도 재계산 — 해석 (ii) 확정 기준

| 항목 | 충족도 | 비고 |
|---|---|---|
| A. 메타데이터 수집·관리 | **100%** ✅ | DataQ 본체 100% 보유 |
| B. DB 모델링 관리 | **DataQ 책임 외** (ERwin 도입 지원만) | 1주 (도입 가이드 작성) |
| C. 메타시스템 연계 모듈 | 약 **30%** △ | ERwin XML 90% (메뉴 숨김), export X |

**입찰 가능 충족도** = A 100% + B 100% (ERwin 도입 지원으로 충족) + C 30% → 약 **77%**

### 입찰 자세 변화

| 시점 | 자세 (해석 i 기준) | 자세 (해석 ii 확정 기준) |
|---|---|---|
| 현재 | "GAP 큼, 13주 보완 필요" | **"거의 충족, 4~5주 보완"** |
| 4주 후 | 진행 중 | **"전 항목 입찰 가능"** |

### 4~5주 작업으로 풀 충족 가능

| 순서 | 작업 | 기간 | 효과 |
|---|---|---|---|
| 1 | **ERwin XML import 메뉴 복구 + 회귀 검증** | 3주 | C-LC-1/LC-2 핵심 충족. 90% → 100% |
| 2 | **ERwin XML export 신규 구현** | 1주 | C-LC-2 추출 완성. ERwin 양방향 |
| 3 | ERwin 도입 가이드 / 설치 지원 문서 | 1주 | B-LB-0/LB-1 충족 (도입 지원 측면) |
| (옵션) | XMI 2.x export/import | 6주 | C 강화 — "표준 포맷" 더 정식화 |

→ **약 5주 후 RFP 전 항목 답변 가능** + 6주 추가 시 XMI까지 정식 충족.

### SMETA 와 직접 경쟁 메시지 (RFP A 자리)

DataQ 가 SMETA 자리를 노리는 만큼 SMETA 대비 강점 부각이 핵심:

| DataQ 강점 | SMETA 대비 |
|---|---|

## 0-5. ERwin 연계 작업의 실제 리스크 — 양식 미확보 + 버전 미확정

### 현황 (사용자 → 본 분석, 2026-05-08)

> ERwin 연계는 **양식을 구할 수가 없어서 중단** 되었고, 발주처가 **어떤 ERwin 버전을 구매할지도 아직 모름**.

이전 분석에서 "ERwin XML import 90% 구현 + 메뉴 숨김 → 3주 활성화" 라고 산정한 부분은 다음 두 전제가 있었으나, 둘 다 미충족:

| 전제 | 실제 상태 |
|---|---|
| ERwin XML 양식 (스키마 / 샘플) 입수 가능 | ❌ **미확보. 작업 중단의 직접 원인** |
| 타겟 ERwin 버전 확정 | ❌ **미정. ERwin 7~12 버전 간 XML 포맷 차이 존재** |

### 리스크 임팩트

| 항목 | 이전 산정 | 실제 | 차이 |
|---|---|---|---|
| ERwin XML import 활성화 | 3주 | **양식 없으면 0주 진행 불가** | 차단 |
| ERwin XML export | 1주 | **양식 없으면 0주 진행 불가** | 차단 |
| 버전별 호환 분기 | 가정 X | **버전 확정 후 추가 작업 필요** | +1~2주 |

→ **현재 ERwin 활성화 작업은 대기 상태**. 양식 입수 또는 발주처 ERwin 버전 확정이 선결.

### 대응 시나리오 분기

#### 시나리오 α: ERwin 양식 입수 + 버전 확정
- 양식 입수 경로: ERwin 평가판 (Quest 가 평가판 제공) → sample 모델 export → 양식 분석
- 또는 발주처에서 보유 ERwin 라이선스/샘플 공유 요청
- 또는 도입 컨설턴트/전 사용자로부터 sample 입수
- **확보 후 작업**: 활성화 3주 + export 1주 = **4주**
- **타겟 버전 변경 시**: 버전별 분기 +1~2주

#### 시나리오 β: ERwin 양식 입수 불가 / 버전 미확정 → XMI 우회 ★강력 권장★
- **XMI (XML Metadata Interchange)** 는 OMG 표준 — 명세 공개, 라이선스 무관
- ERwin / DA# / PowerDesigner 모두 **XMI import 지원** (ERwin 9.x+ 정식)
- DataQ 가 XMI export 만 잘 만들면 ERwin 어느 버전이든 import 가능
- 발주처 입장: "표준 포맷" 의 정확한 답은 사실 **XMI 가 더 표준** (ERwin XML 은 사적 포맷)
- **작업**: XMI 2.x export/import = **6주**

#### 시나리오 γ: 발주처 ERwin 버전 확정 대기 + 병행 작업
- 사전 미팅에서 ERwin 버전 확인 시도
- 동시에 시나리오 β (XMI) 작업 시작
- ERwin 버전 확정되면 그 버전용 ERwin XML 추가 (1~2주)
- **총 소요**: 6주 (XMI) + 2주 (ERwin XML 추가) = **약 8주**, 단 가장 안전

### 권장 결정

| 조건 | 권장 시나리오 |
|---|---|
| 발주처에 ERwin 버전 즉시 확인 가능 | **α** (4주, 단 양식 입수도 따로 필요) |
| 발주처 답변 못 받음 / 양식 입수 불가 | **β** (6주, ERwin 버전 무관 XMI) |
