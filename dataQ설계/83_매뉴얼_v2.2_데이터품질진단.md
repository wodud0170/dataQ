## 1. 부하 안정성 정책 (절대 원칙)

### 1-1. 운영 DB 락 금지
- `LOCK TABLE`, `SELECT FOR UPDATE`, `WITH (NOLOCK)` **일체 사용 안 함**
- 운영 DB 에는 단순 SELECT 만

### 1-2. application-level 동시 진단 방지
- `TB_QUAL_RUNNING_LOCK` (메타DB) — PK: DM_ID + OBJ_NM + ATTR_NM
- 진단 시작 전 `INSERT ... ON CONFLICT DO NOTHING`
  - 1행 INSERT 성공 → 진행
  - 0행 (이미 다른 진단 점유) → SKIP
- 종료/예외 시 `DELETE` 보장 (try-finally)

### 1-3. stale lock 정리
- 30분 경과 lock 자동 정리
- q-executor 시작 시 1회 + 5분마다 cron

### 1-4. 글로벌 동시 진단 N건
- Java `Semaphore` (default 5)
- 슬롯 못 얻으면 진단 SKIPPED 상태로 즉시 종료 (큐잉 안 함)

### 1-5. 쿼리 보호
- `setQueryTimeout(60)` (default 60초)
- 누적 30분 (`TOTAL_TIMEOUT_SEC = 1800`) 초과 시 진단 중단

## 2. 도메인 룰 관리 (DSQualDomainRule)

### 화면 구성
- 좌측: 분류 → 도메인 트리 (카운트 포함)
- 우측: 선택 도메인의 룰 그리드

### 룰 타입
| 타입 | 파라미터 | 예시 |
|---|---|---|
| NOT_NULL | (없음) | NOT NULL 검증 |
| RANGE | min/max | `{min: 0, max: 100}` |
| REGEX | pattern | `{pattern: "^010-\\d{4}-\\d{4}$"}` |
| ENUM | values | `{values: ["Y","N"]}` |

### 카탈로그 (시스템 기본 vs 사용자 정의)
- 시스템 기본 (`IS_BUILT_IN='Y'`) — 행안부 도메인 분류 시드 43건
  - 수정/삭제 불가, [복사]만 가능 (사용자 정의로 fork)
- 사용자 정의 (`IS_BUILT_IN='N'`) — 자유롭게 CRUD
- [매핑] 클릭 → 카탈로그 룰을 도메인에 import

## 3. 컬럼 규칙 매핑 (DSQualColRule)

### Effective Rule 결정 흐름
```
TB_QUAL_COL_RULE 매핑 우선
  EXCLUDE_YN='Y'         → EXCLUDED (진단 제외)
  CUSTOM_RULE_ID 있음    → CUSTOM
  DOMAIN_RULE_ID 있음    → DOMAIN
매핑 없으면
  ATTR_NM_KR → TB_TERMS → TB_DOMAIN_RULE (SORT_ORD=1)
                           → DEFAULT
  도메인도 없음          → NONE (진단 skip)
```

### 필터
- 모델 / 도메인 분류 (단일) / 테이블 ILIKE / 컬럼 ILIKE / 적합률 범위 (rateMin/rateMax)

### 우측 drawer (컬럼 클릭)
- 도메인 정보 + 적용 규칙 + 직전 값 프로파일 + 직전 룰 결과
- **위반 샘플 미리보기 (LIMIT 5)**
- **룰별 적합률 분포 (LIMIT 20)**

## 4. 값 프로파일링 (DSQualValueProfile)

### 화면 흐름
1. 모델 선택 → effective rule 그리드 자동 로드
2. 도메인 분류 multi-select 필터로 컬럼 추림 (예: 전화번호 + 금액)
3. 컬럼 체크 → [선택 컬럼 진단]
4. **진행률 progress bar 실시간 표시** (3초 폴링, DONE/ERROR/SKIPPED 시 자동 종료)
5. 완료 시 그리드 자동 reload

### 동시 실행 동작
- 같은 컬럼이 다른 진단 점유 중이면 → 그 컬럼만 SKIP, 나머지 진행
- 글로벌 슬롯 5건 초과 진입 시 → 전체 SKIPPED

### 샘플링 (운영 DB 부담 완화)
- 1만건 / 10% / 100%
- DBMS dialect 별 `TABLESAMPLE` (PG) / `SAMPLE(n)` (Oracle) / `TABLESAMPLE PERCENT` (MSSQL)

## 5. 진단 결과 (DSQualRuleResult) — 3 탭

### 탭 1. 진단 단위 (룰별 집계)
- 룰명/유형/심각도 + 컬럼수/적용수/전체/위반/적합률

### 탭 2. 도메인 분류 단위 (Step 6 핵심)
- 분류별 적합률 막대 그래프 (95↑녹 / 80↑주 / 그외 적)
- 분류 클릭 → drill-down: 그 분류 컬럼별 룰 결과
- 행 [위반 샘플] 버튼 → 우측 drawer (PK + 위반값)
- "미분류" bucket 포함 (도메인 미매핑 컬럼)

### 탭 3. 상세 (raw)
- 기존 result raw 행 (룰명/테이블/컬럼/위반률/에러)

## 6. 진단 통계 (DSQualStats) — 시계열 라인 차트 (Step 7)

### 모델 적합률 추이
- DONE 진단 최근 30회 평균 적합률
- 단일 라인, datetime X축
- `HAVING SUM(TOTAL_CNT) > 0` — 결과 0건 진단은 제외

### 컬럼 단위 (테이블+컬럼 선택 시)
- 룰별 적합률 추이 (멀티 라인 — 룰별 색 구분)
- NULL% / DISTINCT% 추이 (값 진단 history)

### 차트 라이브러리
- apexcharts 3.40 (`vue-apexcharts`)
- 컴포넌트 단위 import — `components: { 'apexchart': VueApexCharts }`

## 8. API 요약

### 도메인 룰 (`/api/qual/domain`)
- `GET /tree` — 분류→도메인 트리 + 룰 카운트
- `GET /rules?domainId=` — 도메인 룰 목록
- `POST /rule/save` — 룰 추가/수정 (admin)
- `DELETE /rule/{ruleId}` — 룰 삭제 (admin)
- `POST /rule/importFromCatalog` — 카탈로그 → 도메인 매핑

### 룰 카탈로그 (`/api/qual/rule/catalog`)
- `GET /catalog?isBuiltIn=&domainClsfNm=&ruleType=&schNm=` — 검색
- `POST /catalog/save` — INSERT/UPDATE (시스템 기본 보호)
- `DELETE /catalog/{catalogId}` — 사용자 정의만 삭제
- `POST /catalog/fork` — 시스템 기본 → 사용자 정의 복사

### 컬럼 매핑 (`/api/qual/colrule`)
- `GET /list?dmId=&objNm=&attrNm=` — effective rule
- `GET /listWithLatest?dmId=&domainClsfNm=&rateMin=&rateMax=&objNm=&attrNm=` — + 직전 결과
- `GET /detail?dmId=&objNm=&attrNm=` — 위반 샘플 + 룰 결과
- `POST /save` — 컬럼-룰 매핑 (도메인/커스텀)
- `POST /exclude` — 진단 제외 토글

### 진단 실행 (`/api/qual/value`, `/api/qual/rule`)
- `POST /value/runColumns` — 다중 컬럼 값 진단
- `POST /rule/runColumns` — 다중 컬럼 룰 진단
- `GET /value/history/{diagId}` — 진행률 폴링 (progressDone/progressTotal)
- `GET /rule/history/{diagId}` — 진행률 폴링

### 진단 결과 (`/api/qual/rule`)
- `GET /historyList?dmId=&diagType=` — 최근 50건
- `GET /result?diagId=` — 진단 raw 결과
- `GET /resultByRule?diagId=` — 룰 단위 집계
- `GET /resultByClsf?diagId=` — 도메인 분류 단위 집계
- `GET /resultByClsfDrill?diagId=&domainClsfNm=` — 분류 drill-down
- `GET /violationSample?diagId=&ruleId=` — 위반 샘플

### 시계열 (`/api/qual/stats`)
- `GET /modelTrend?dmId=` — 모델 적합률 시계열
- `GET /columnRuleTrend?dmId=&objNm=&attrNm=` — 룰별 멀티 라인
- `GET /columnProfileTrend?dmId=&objNm=&attrNm=` — NULL%/DISTINCT% 추이

## 9. 시연 절차 (10분 코스)

### 사전 준비
- PC1 또는 PC2, 데모 모델 1개 (운영 DB 실 연결)
- 도메인 시드 + TB_QUAL_RULE_CATALOG 시드 (`qual_rule_catalog_seed_2026-05-07.sql`)

### 시연 흐름

**1) 도메인 룰 관리** (1분)
- 메뉴 진입 → 트리 (분류별 그룹) 노출
- "전화번호" 도메인 클릭 → 시드 룰 (REGEX) 표시
- [카탈로그] 버튼 → 시스템 기본 43건 + 사용자 정의 탭

**2) 컬럼 규칙 매핑** (2분)
- 메뉴 진입 → 검증 대상 그리드
- 도메인 분류 "전화번호" 필터 → 해당 컬럼만 추림
- 행 [상세] → 우측 drawer (적합률 + 위반 샘플)

**3) 값 프로파일링** (3분)
- 도메인 분류 multi 선택 (전화번호 + 금액)
- 체크 → [선택 컬럼 진단]
- **진행률 progress bar 실시간 갱신** ← 핵심
- 완료 시 그리드 자동 reload + 적합률 갱신

**4) 진단 결과** (2분)
- 메뉴 진입 → 자동으로 최신 DONE 진단 선택
- "도메인 분류 단위" 탭 → 분류별 적합률 막대
- "전화번호" 분류 클릭 → drill-down 컬럼별 결과
- [위반 샘플] → drawer (PK + 위반값)

**5) 진단 통계** (1분)
- 메뉴 진입 → 모델 선택 → 적합률 시계열 라인 차트
- 컬럼 선택 → 룰별 멀티 라인

**6) 안정성 시연** (1분)
- 진단 실행 중 같은 컬럼 재시도 → SKIP 메시지
- TB_QUAL_RUNNING_LOCK 직접 확인 (psql)
