## 1. 표준 사전 (단어/용어/도메인/표준코드)

### 1.1 도메인-단어 매핑 catalog 부재
- **현황**: 도메인이 어떤 단어 분류에 속하는지 매핑이 `TB_DOMAIN.DOMAIN_CLSF_NM` 으로만 1차원. 단어의 도메인 후보를 산정할 때 cascade query 가 매번 직접 join.
- **문제**: 자동 표준화 분석 (`/api/std/analyzeTermsBatch`) 시 매번 무거운 query. 상위 단어 5만 건에서 응답 시간 길어질 가능성.
- **영향**: 셀레니움 분석 시간 한 번 ~5초 (현재 시드 기준). 운영 환경에서 100~1000배 가능.
- **개선안**:
  - 도메인 추천 결과를 캐시 (Redis 또는 in-memory `@Cacheable`)
  - TB_WORD_DOMAIN_MAP 같은 비정규화 테이블로 전체 한 번만 조회
- **우선순위**: 🟡 중 (현재 PASS 중이지만 운영 부하 우려)

### 1.2 도메인 룰 등록 UI 부재 (70번 미구현)
- **현황**: TB_DOMAIN_RULE 은 70번에서 신규 도입. 시드 SQL 로 등록 가능 — 별도 UI 없음.
- **문제**: 관리자가 새 도메인 패턴(예: 우편번호 새 형식) 추가할 방법 = SQL 직접.
- **영향**: 운영 운영자 진입 장벽 큼.
- **개선안**: DSDomain 화면에 "이 도메인의 검증 규칙" 탭 추가 (CRUD UI). 70번 §5 Phase 2 항목.
- **우선순위**: 🟡 중

### 1.3 단어/용어 동의어(allophSynmLst) 활용 미흡
- **현황**: TB_TERMS 의 `alloph_synm_lst` 필드는 동의어 배열. UI 표시는 일부 (DSTerm 화면) 만.
- **문제**: 자동 표준화 분석에서 동의어를 통해 매칭 확장 가능 — 현재 미사용.
- **개선안**: analyzeTerms 매처에 동의어 fallback 추가 (예: '회원이름' → '이름' 미등록, '회원명' 동의어 매칭).
- **우선순위**: 🟢 낮

### 1.4 승인 프로세스의 cascade 동작 자체는 OK (검증됨)
- 셀레니움 `test_cascade_and_word_first.py` 통과 — 단어 반려 시 용어 cascade, 단어 선승인 강제 등 정상.

## 2. 데이터 모델 (수집/관리/UX)

### 2.1 ⚠️ initdb 와 DDL_claude_generated.sql 의 누적 불일치 (이미 알려진 메모리 항목)
- **현황**: `docker/dataq-db/initdb/01_schema.sql` 은 CLCT 폐기 이전. 실제 DB 는 DDL_claude_generated.sql 누적.
- **문제**: 신규 환경 구축 시 initdb 만으로는 현재 구조 안 됨.
- **영향**: 다른 PC/CI 환경에서 0부터 setup 시 깨짐.
- **개선안**:
  - 옵션 A: initdb 를 현재 DDL_claude_generated.sql 과 동일하게 재작성
  - 옵션 B: docker entrypoint 가 `initdb/01_schema.sql` 적용 후 `DDL_claude_generated.sql` 도 자동 적용
  - 옵션 C: Flyway/Liquibase 같은 마이그레이션 도구 도입 (큰 변경)
- **우선순위**: 🔴 높 (CI 도입 시 즉시 막히는 결함)

### 2.2 메타 수집 query 의 DBMS 별 누락
- **현황**: dm-collect.xml 에 정의된 named query — Oracle/MariaDB/Cubrid 일부만. Cubrid 의 `GetIndexes`/`GetConstraints` 미정의.
- **문제**: STRUCT 진단 시 인덱스/제약조건 변경 감지 불가 (해당 DBMS 만).
- **개선안**: 누락된 named query 채우기. 72번 §2 의 SQL 초안 참고.
- **우선순위**: 🟡 중 (Cubrid 운영 도입 시 필수)

### 2.3 컬럼 그리드 (DSDatamodelStatusColumn) 의 적용 규칙 표시 부재
- **현황**: 70번에서 별도 화면 (DSQualColRule) 으로 효과 규칙 표시. 컬럼 그리드 자체에는 없음.
- **문제**: 사용자가 컬럼 보면서 "이 컬럼 어떤 룰 적용 중" 확인하려면 다른 메뉴 가야.
- **개선안**: DSDatamodelStatusColumn 의 그리드에 "적용 규칙" column + 인라인 변경 드롭다운. 70번 §5.1 Phase 2.
- **우선순위**: 🟡 중

### 2.4 엑셀 업로드의 FK 정합성 검증 약함
- **현황**: `parseAttrWorkbook` 가 refTable 존재 여부만 확인.

## 5. 진단 스케줄러 (Phase 1~4)

## 7. 인프라 / 빌드 / 환경

### 7.1 ⚠️ q-common POM 의 systemPath warning (Maven 3.9+ 비호환)
- **현황**: `q-common/pom.xml` line 26 이 `systemPath=${project.basedir}/../lib/common-0.0.1-SNAPSHOT.jar`. Maven 3.9.14 이 invalid POM 으로 격상 → transitive 의존 차단.
- **문제**: q-center fat jar 에 korean-text 등 transitive 누락 → NoClassDefFoundError. fd1d151 에서 q-center 에 직접 의존성 명시로 우회. 다른 transitive 누락 시 같은 패턴 반복 발생.
- **개선안**:
  - 옵션 A: lib 의 common.jar 를 .m2 에 install:install-file 로 등록 → systemPath 제거
  - 옵션 B: q-common 을 multi-module 의존성으로 일관 관리 (현재도 q-common 자체는 그렇지만, common.jar 는 system scope 가 문제)
- **우선순위**: 🔴 높 (환경마다 재발 가능)

### 7.2 한글 경로 인코딩 이슈
- **현황**: Windows + 한글 사용자명 (`장재영`) 경로에서 java -jar 실패. PowerShell `Start-Process` 또는 ASCII 경로 복사로 우회.
- **문제**: 매 세션마다 재현. CI 환경 (사용자명 ASCII) 에서는 무관.
- **개선안**: 근본 fix 는 Windows OEM 코드페이지 차원이라 어려움. 현재 우회 (PS Start-Process) 가 정착.
- **우선순위**: 🟢 낮 (해결책 정착)

### 7.3 jasypt 암호화 위치 미공개
- **현황**: TB_DATA_SOURCE.PWD 가 jasypt 암호화 — secret key 위치 추적 안 해봄. createDataSource API 로 우회 가능.
- **문제**: 시드 SQL 로 직접 INSERT 시 EncryptionOperationNotPossibleException.
- **개선안**: 문서에 "데이터소스는 API/UI 로 등록" 명시. 시드 SQL 가이드에도 fallback (createDataSource POST 자동화 스크립트).
- **우선순위**: 🟡 중

### 7.4 docker initdb 자동화 부재
- 위 §2.1 과 묶임.

### 7.5 q-common install 후 q-executor mvn package 가 incremental skip
- **현황**: `mvn package -o` (offline) 가 q-common 변경 후에도 q-executor 의 fat jar 갱신 skip. `mvn clean package` 필수.
- **문제**: 빌드 자동화에서 매핑 갱신이 안 반영 — 디버그 시간 손실.
- **개선안**: 빌드 스크립트에 `clean` 강제 또는 `clean && package`. 메모리에 명시.
- **우선순위**: 🟡 중

### 8.6 v-data-table 의 적합률/위반률 색상 컨벤션
- **현황**: DSQualValueProfile 은 95+ 녹색 / 80+ 황색 / 80- 빨강. DSQualRuleResult 은 50/10 기준.
- **문제**: 사용자가 화면별 같은 의미 다른 색.
- **개선안**: 글로벌 색상 헬퍼 함수 — 모든 적합률/위반률 표시 통일.
- **우선순위**: 🟡 중

## 9. 셀레니움 / 테스트

### 9.1 셀레니움이 4-30 시점까지 부실했음 — 사용자 지적 후 보강
- **현황**: API 만 호출 + 결과 카운트만 비교. UI 의 실제 동작 (button click, swal, drawer) 검증 누락.
- **문제**: 4 건의 진짜 UI 버그 (axios baseURL/isAdmin/Gson String/Swal import) 를 셀레니움이 못 잡고 사용자 수동 발견.
- **상태**: 4-30 ~ 5-1 에 시나리오 무게 강화 — 30 STEP UI 풀 + 사용자 시나리오 5종 (DB snapshot 비교 + 에러 케이스 등).
- **개선안**: 신규 컴포넌트 작성 시 UI 셀레니움 초안 같이 작성하는 것을 룰로.

### 9.2 테스트 격리 (각 시나리오의 시드 의존성)
- **현황**: 일부 시나리오는 이전 시나리오의 결과에 의존 (예: 70번 시나리오가 67번 시나리오의 진단 결과 누적).
- **문제**: 시나리오 순서 바꾸면 fail 가능.
- **개선안**: 각 시나리오 시작 시 시드 재적용 또는 사용 데이터의 self-contained.
- **우선순위**: 🟡 중

### 9.3 테스트 데이터의 다양성 부족
- **현황**: TB_TEST_MEMBER 의 한글명/영문명 단순 패턴. 실제 운영 데이터의 다양성 (빈 string, 공백 padding, 특수문자, 매우 긴 값) 부족.
- **개선안**: edge case 행 추가 (NULL byte, UTF-8 4바이트, 길이 한계 등).
- **우선순위**: 🟢 낮
