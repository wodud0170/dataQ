# 79. 진단 대상 제외 관리 화면 설계

**작성일**: 2026-05-04
**최종 갱신**: 2026-05-04 — 사용자 확정 사항 반영 (테이블+컬럼 단위, 모수에서 완전 제외, 결과에 카운트만)
**대상 화면**: 데이터 모델 → **진단 제외 관리** (신규)
**범위**: **이미 수집된 OBJ (테이블) + ATTR (컬럼) 단위로** 표준화 진단 / 구조 변경 진단 대상에서 제외
**제외**: 수집 전 단계 필터링 (drivers.xml 레벨, 다음 단계 설계)
**연관 진단**:
- 표준화 진단 (`TB_DIAG_JOB`, `TB_DIAG_RESULT`) — 67번 영역
- 구조 변경 진단 (`TB_STRUCT_DIAG_HISTORY`) — 11번/40번 영역

## 0. 핵심 정책 (사용자 확정)

1. **적용 단위 — 테이블 (OBJ) AND/OR 컬럼 (ATTR)** 둘 다 가능
2. **테이블 플래그 OFF = 그 테이블의 모든 컬럼 자동 진단 제외** (cascade)
3. **컬럼 단위 플래그 OFF = 그 컬럼만 진단 제외**
4. **진단 모수에서 완전 제외** — 분모/분자 둘 다 안 들어감 (표준 준수율 통계 정상화)
5. **진단 결과 화면**: "제외 N건" 카운트만 표시 (위반 결과에 안 섞임)
6. **명명**: `STND_DIAG_TARGET_YN` / `STRUCT_DIAG_TARGET_YN` / `QUAL_DIAG_TARGET_YN` — **DEFAULT 'Y'** (포함이 기본). 사용자 화면 표현 "대상 여부" 와 일치.
7. **3개 진단 종류 모두 분리 토글** — 표준화 / 구조 변경 / 데이터 품질 진단 (67/70번 영역)

## 1. 배경

### 1-1. 현재 문제

표준화 / 구조 변경 진단은 모델의 **모든 OBJ** 를 대상으로 자동 수행. 그런데:

- **임시 테이블** (`TMP_*`, `TEMP_*`, `BAK_*`, `_BAK`) — 진단 대상이지만 표준화 의미 없음
- **연계용 테이블** (`I_*`, `O_*`, `IFRC_*`) — 외부 시스템 인터페이스용. 우리 표준 적용 대상 아님
- **백업/로그 테이블** (`*_BAK`, `LOG_*`, `_HISTORY`) — 대용량이라 진단 시 부하만 유발
- **삭제 예정 테이블** — 이미 deprecated, 진단 결과에 포함되면 노이즈

→ 진단 결과에 의미 없는 비표준 컬럼이 다수 섞여 **준수율 통계 왜곡** + **운영 부하 증가**.

### 1-2. 사용자 요구

> "표준화 진단 / 구조 변경 진단을 자주 수행할 텐데, 임시·연계 테이블은 매번 결과에 포함되어 거슬림. 진단 전에 제외할 수 있는 화면이 필요."

### 1-3. SMETA 비교

SMETA 의 진단 제외 기능은 [공식 명시 없음]. 이 영역도 DataQ 의 차별화 가능 영역.

```

| 컬럼 | 의미 | 적용 시점 |
|------|------|----------|
| STND_DIAG_TARGET_YN     | 표준화 진단 대상 ('Y'=대상 / 'N'=제외) | **즉시** (이번 작업 매퍼 적용) |
| STND_DIAG_TARGET_REASON | 표준화 OFF 사유 (필수 입력) | |
| STRUCT_DIAG_TARGET_YN     | 구조 변경 진단 대상 | **즉시** |
| STRUCT_DIAG_TARGET_REASON | 구조 OFF 사유 | |
| QUAL_DIAG_TARGET_YN     | 데이터 품질 진단 대상 | **컬럼/UI 만 추가** — 매퍼는 67/70번 정식 구현 후 |
| QUAL_DIAG_TARGET_REASON | 품질 OFF 사유 | |
| DIAG_TARGET_UPDT_USER_ID | 마지막 변경자 | |
| DIAG_TARGET_UPDT_DT      | 마지막 변경일시 | |

→ **사유는 진단 종류별 분리**. 표준 OFF 와 구조 OFF 가 다른 사유일 수 있음. ON 시 NULL 로 클리어.

ALTER TABLE TB_DATA_MODEL_ATTR ADD COLUMN STND_DIAG_TARGET_REASON VARCHAR(200);

ALTER TABLE TB_DATA_MODEL_ATTR ADD COLUMN QUAL_DIAG_TARGET_REASON VARCHAR(200);
ALTER TABLE TB_DATA_MODEL_ATTR ADD COLUMN DIAG_TARGET_UPDT_USER_ID VARCHAR(50);
ALTER TABLE TB_DATA_MODEL_ATTR ADD COLUMN DIAG_TARGET_UPDT_DT      VARCHAR(14);
```

OBJ 와 동일 8개 컬럼. DEFAULT 'Y' 로 기존 데이터 모두 대상 (회귀 없음).

### 2-3. Cascade 정책 — 효과적 진단 대상 여부 계산

```
IS_STND_TARGET   = (OBJ.STND_DIAG_TARGET_YN  = 'Y') AND (ATTR.STND_DIAG_TARGET_YN  = 'Y')
IS_STRUCT_TARGET = (OBJ.STRUCT_DIAG_TARGET_YN= 'Y') AND (ATTR.STRUCT_DIAG_TARGET_YN= 'Y')
IS_QUAL_TARGET   = (OBJ.QUAL_DIAG_TARGET_YN  = 'Y') AND (ATTR.QUAL_DIAG_TARGET_YN  = 'Y')
```

→ **OBJ 와 ATTR 둘 다 'Y' 여야 진단 대상**. OBJ 가 OFF 되면 그 테이블의 모든 ATTR 이 자동 제외 효과 (cascade).

### 2-4. TB_DIAG_EXCLUSION_RULE (신규 — 패턴 룰, 선택 사항)

```sql
CREATE TABLE TB_DIAG_EXCLUSION_RULE (
    RULE_ID VARCHAR(22) PRIMARY KEY,
    DM_ID VARCHAR(22) NOT NULL,
    RULE_NM VARCHAR(100) NOT NULL,
    PATTERN VARCHAR(200) NOT NULL,           -- SQL LIKE 패턴
    PATTERN_TYPE VARCHAR(10) DEFAULT 'LIKE', -- LIKE / REGEX (1차는 LIKE 만)
    TARGET_LEVEL VARCHAR(10) DEFAULT 'OBJ',  -- 'OBJ'(테이블명) / 'ATTR'(컬럼명)
    APPLY_TO_STND_YN VARCHAR(1) DEFAULT 'Y',
    APPLY_TO_STRUCT_YN VARCHAR(1) DEFAULT 'Y',
    REASON VARCHAR(200),
    USE_YN VARCHAR(1) DEFAULT 'Y',
    SORT_ORD INTEGER DEFAULT 0,
    CRET_DT VARCHAR(14),
    CRET_USER_ID VARCHAR(50),
    UPDT_DT VARCHAR(14),
    UPDT_USER_ID VARCHAR(50)
);

CREATE INDEX IDX_DIAG_EXCL_RULE_DM ON TB_DIAG_EXCLUSION_RULE (DM_ID, USE_YN);
```

| 컬럼 | 의미 | 예시 |
|------|------|------|
| RULE_NM | 룰 이름 | "임시 테이블" |
| PATTERN | LIKE 패턴 (escape '\\') | `TMP\_%`, `%\_BAK` |
| TARGET_LEVEL | 매칭 대상 | 'OBJ' = 테이블명 / 'ATTR' = 컬럼명 |
| APPLY_TO_STND_YN | 표준화 적용 | 'Y' |
| APPLY_TO_STRUCT_YN | 구조 적용 | 'Y' |
| REASON | 사유 | "임시 작업용 테이블" |

→ 룰 적용 시 매칭되는 OBJ 또는 ATTR 행에 `STND_DIAG_EXCLUDE_YN='Y'` 자동 마킹.

### 3-3. 사유 입력 흐름 (핵심)

| 동작 | 사유 모달 | 사유 필수 여부 | 비고 |
|------|:--------:|:-------------:|------|
| 단건 OFF (☑→☐) | ✅ | **선택 (빈칸 가능)** | 해당 진단 종류 사유만 — placeholder "사유 (선택)" |
| 단건 ON (☐→☑) | ❌ | — | 즉시 적용 + 사유 NULL 클리어 |

### 3-4. 사유 조회 — 3가지 경로

| 경로 | 표시 범위 | 용도 |
|------|----------|------|
| **그리드 인라인** | 사유 미표시 (행 OFF 시 회색 배경 또는 ⚠ 아이콘만) | 화면 가독성 우선 |
| **행 [상세] 모달/Drawer** | 진단 종류별 사유 + 변경자 + 변경일시 | 단건 정확 조회 |
| **데이터 모델 → 테이블/컬럼 화면의 기존 [다운로드]** | **신규 컬럼 자동 포함 (사유 3개 + 변경자/일시)** | 운영/감리 보고서, 일괄 검토 |

#### 그리드 시각 단서

```
☐ │ TMP_LOG          │ 임시로그 │  5  │  ☐  │  ☐  │  ☑  │  ⓘ      ← 회색 배경
☐ │ TB_MEMBER        │ 회원     │ 18  │  ☑  │  ☑  │  ☑  │  ⓘ      ← 흰 배경
```

→ 사용자는 그리드에서 OFF 행을 한눈에 식별. 사유는 ⓘ 클릭으로 확인.

#### 엑셀 다운로드 — 기존 화면 활용

별도 다운로드 버튼 추가 안 함. **데이터 모델 → 테이블 / 컬럼 화면**의 기존 [다운로드] 가 신규 컬럼을 자동 포함하도록 ExcelDownloadService 만 갱신.

기존 컬럼 + **추가 컬럼** (각 화면):

| 추가 컬럼 | 값 |
|----------|---|
| 표준 진단 대상 | Y / N |
| 표준 OFF 사유 | STND_DIAG_TARGET_REASON (N 일 때만) |
| 구조 진단 대상 | Y / N |
| 구조 OFF 사유 | STRUCT_DIAG_TARGET_REASON |
| 품질 진단 대상 | Y / N |
| 품질 OFF 사유 | QUAL_DIAG_TARGET_REASON |
| 마지막 변경자 | DIAG_TARGET_UPDT_USER_ID |
| 마지막 변경일시 | DIAG_TARGET_UPDT_DT (YYYY-MM-DD HH:MI) |

→ 사용자는 평소처럼 데이터 모델 → 테이블/컬럼 화면에서 [다운로드] 클릭. 새 컬럼이 자동 포함되어 분기별 검토 / 감리 / RFP 보고서 활용.

### 3-5. 탭 동작

| 탭 | 데이터 | 비고 |
|----|--------|------|
| 테이블 단위 | TB_DATA_MODEL_OBJ 의 모든 행 | OBJ 자체의 EXCLUDE_YN 토글 — 그 테이블 전체 진단 제외 효과 |
| 컬럼 단위 | TB_DATA_MODEL_ATTR (테이블 선택 시) | ATTR 단위 EXCLUDE_YN 토글 — 그 컬럼만 진단 제외 |

→ 테이블 단위에서 ON 한 테이블의 컬럼들은 컬럼 단위 탭에서 **회색 배경 + 비활성** 표시 (이미 부모가 ON 이므로 의미 없음).

### 3-3. 영역별 동작

#### 3-3-1. 모델 선택
- 상단 v-autocomplete (DSQualValueProfile 패턴 동일)
- DB 연결된 모델만 표시 (`connectedOnly='Y'` 필터)

#### 3-3-2. 상단 통계

- 그리드 변경 시 실시간 갱신

#### 3-3-3. 패턴 룰 영역 (접을 수 있음)
- 룰 목록 그리드
- `[패턴 룰 추가]` → 모달:
  - 룰명, 패턴, 사유 입력
  - 적용 대상 (표준화/구조 체크박스)
  - 미리보기: 패턴 매칭되는 OBJ 수 표시
- `[적용]` 버튼: 룰의 매칭 OBJ 모두 `EXCLUDE_YN='Y'` 마킹

#### 3-3-4. 테이블 그리드
- 컬럼: 체크박스 / 테이블명 / 한글명 / 컬럼수 / 표준화제외 / 구조제외 / 사유

- 필터: 전체 / 제외만 / 포함만 (표준화 또는 구조 기준)
- 정렬: 테이블명 / 컬럼수 / 제외 여부

#### 3-3-5. 일괄 처리
- 선택 행에 대해:
  - `[표준화 제외 ON/OFF]` — `STND_DIAG_EXCLUDE_YN` 일괄 설정
  - `[구조 제외 ON/OFF]` — `STRUCT_DIAG_EXCLUDE_YN` 일괄 설정

## 5. 진단 시 적용 — 모수에서 완전 제외

### 5-1. 표준화 진단 (이번 작업 — 매퍼 통합)

진단 대상 컬럼 조회 매퍼:
```xml
<select id="selectAttrListForStndDiag">
  SELECT a.*
  FROM TB_DATA_MODEL_ATTR a
  INNER JOIN TB_DATA_MODEL_OBJ o
       ON a.DM_ID = o.DM_ID AND a.OBJ_NM = o.OBJ_NM
  WHERE a.DM_ID = #{dmId}
    AND a.USE_YN = 'Y'
    AND o.USE_YN = 'Y'
    AND COALESCE(o.STND_DIAG_TARGET_YN, 'Y') = 'Y'   <!-- 테이블 진단 대상 -->
    AND COALESCE(a.STND_DIAG_TARGET_YN, 'Y') = 'Y'   <!-- 컬럼 진단 대상 -->
  ORDER BY a.OBJ_NM, a.ATTR_ORD
</select>
```

→ **분모/분자 모두에서 완전 제외**. 표준 준수율 계산 시 비대상 컬럼은 통계에 영향 X.

### 5-2. 구조 변경 진단 (이번 작업 — 매퍼 통합)

동일 패턴 — `STRUCT_DIAG_TARGET_YN = 'Y'` 만 비교 대상. OBJ 가 OFF 되면 그 ATTR 모두 자동 제외.

### 5-3. 데이터 품질 진단 (보류)

품질 진단 (67/70번) 정식 구현 단계에서 **`QUAL_DIAG_TARGET_YN` 매퍼 통합**. 본 79번에서는 컬럼/UI 만 준비, 진단 서비스 호출은 보류.

→ 컬럼은 미리 추가해두면 사용자가 사전 마킹 가능. 품질 진단 구현 후 매퍼/서비스만 결합하면 즉시 동작.

> ⚠️ **품질 진단 구현 시 반드시 체크해야 할 핸드오버 항목** (잊지 말 것):
>
> 1. **값 진단 매퍼** — 진단 대상 컬럼 조회 시 `WHERE COALESCE(o.QUAL_DIAG_TARGET_YN,'Y')='Y' AND COALESCE(a.QUAL_DIAG_TARGET_YN,'Y')='Y'` 조건 추가
> 2. **룰 진단 매퍼** — `TB_QUAL_COL_RULE` 와 cross check. ATTR.QUAL_DIAG_TARGET_YN='N' 인 컬럼은 룰 매핑 자체를 건너뛰기
> 3. **`TB_QUAL_COL_RULE.EXCLUDE_YN` 와의 의미 분리**:
>    - `TB_QUAL_COL_RULE.EXCLUDE_YN` = 룰 매핑 단위 제외 (특정 룰만 끄기)
>    - `TB_DATA_MODEL_ATTR.QUAL_DIAG_TARGET_YN` = 그 컬럼 자체를 모수에서 제외 (모든 룰 미실행)
>    - 충돌 시: **TARGET_YN 이 우선** (모수 자체 제외가 더 강한 정책)
> 4. **진단 결과 화면** — "품질 진단 대상 아님 N건" 카운트 별도 표시
> 5. **진단 통계 / 준수율** — 분모/분자에서 완전 제외 (표준화 진단과 동일 패턴)
> 6. **셀레니움 회귀** — `test_qual_*.py` 에 QUAL_DIAG_TARGET 관련 시나리오 추가
>
> → 본 핸드오버 미체크 시 진단 결과 모수에 제외 대상 컬럼이 섞여 통계 왜곡 발생.

### 5-4. 제외 카운트 별도 집계

```xml
<select id="selectDiagTargetStats">
  WITH counts AS (
    SELECT
      COUNT(*) FILTER (WHERE o.STND_DIAG_TARGET_YN = 'N')   AS excluded_obj_stnd,
      COUNT(*) FILTER (WHERE o.STRUCT_DIAG_TARGET_YN = 'N') AS excluded_obj_struct,
      COUNT(*) FILTER (WHERE o.QUAL_DIAG_TARGET_YN = 'N')   AS excluded_obj_qual,
      COUNT(*) AS total_obj
    FROM TB_DATA_MODEL_OBJ o
    WHERE o.DM_ID = #{dmId} AND o.USE_YN = 'Y'
  )
  SELECT * FROM counts
</select>
```

ATTR 카운트는 동일 패턴 — 부모 OBJ 의 OFF 까지 cascade 반영.

### 5-4. 진단 결과 화면 표기

```

진단 대상: 1,775 컬럼 (전체 1,820 - 제외 45)
표준 준수율: 91.2%   ← 제외 행은 분모/분자 둘 다 안 들어감

[제외된 45건 보기 ▾]
  └ 테이블 단위 제외: TMP_LOG (5컬럼), I_EXT_USER (12컬럼), ... 8건 → 45컬럼
    또는 (컬럼이 자체 토글된 케이스) ... 행 표시
```

→ 위반 결과 그리드에는 **제외된 컬럼 안 섞임**. 통계가 깨끗.

### 5-5. 진단 스케줄러 (cron) — 자동 진단도 동일 적용

진단 스케줄러가 기동될 때 같은 매퍼 호출 → 자동 진단도 제외 정책 자동 적용.

## 7. 패턴 룰 — 즉시 적용 vs 다음 수집 적용

### 7-1. 즉시 적용
- 룰 등록 즉시 `[적용]` 버튼 → 현 OBJ 에 매칭되는 행 모두 `EXCLUDE_YN='Y'`
- 사유는 룰의 `REASON` 으로 자동 채움

### 7-2. 다음 수집 시 자동 적용 (선택 사항)
- 수집 후 새 OBJ 가 추가되면 → 활성 룰에 매칭되는 OBJ 자동 마킹
- 수집 서비스에 hook: 새 OBJ INSERT 시 매칭 룰 적용

→ 사용자 의도: "수집 전 제외는 다음에" → **수집 서비스 hook 은 후속**.
이번 단계는 **즉시 적용만** 구현. 사용자가 새로 수집되면 다시 화면에서 룰 `[적용]` 버튼으로 마킹.

## 9. 사용자 시나리오

### 시나리오 A. 임시 테이블 일괄 제외

1. CAMS 모델 진단 시 `TMP_*` 임시 테이블 8건이 비표준 컬럼으로 표시되어 거슬림
2. 진단 제외 관리 메뉴 진입 → 모델 CAMS 선택
3. 패턴 룰 추가 → `TMP\_%`, 사유 "임시 작업용", 표준화+구조 모두 제외
4. 미리보기 → 매칭 8건 확인
5. `[적용]` 버튼 → 8건 모두 `EXCLUDE_YN='Y'`
6. 다음 진단 실행 시 자동 제외, 결과에 "제외 8건" 표시

### 시나리오 B. 특정 테이블만 표준화는 제외, 구조는 포함

1. `LOG_AUDIT` 테이블 — 표준화는 의미 없으나 구조 변경은 추적해야 함
2. 진단 제외 관리 → `LOG_AUDIT` 행에서 표준화 토글만 ON
3. 결과: 표준화 진단 제외, 구조 변경 진단은 포함

### 시나리오 C. 룰 일괄 검토 (분기별)

1. 분기마다 진단 제외 관리 화면 진입
2. 패턴 룰 목록 검토 — 더 이상 의미 없는 룰 비활성화
3. 새로 등장한 임시 테이블 패턴 발견 → 룰 추가
