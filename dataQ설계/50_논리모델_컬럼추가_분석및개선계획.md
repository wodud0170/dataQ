# 50. 논리 모델 컬럼 추가 — 현황 분석 및 개선 계획

**작성일**: 2026-04-20
**배경**: 수동 테스트 및 Selenium E2E에서 **논리 모델의 컬럼 추가가 실질적으로 불가능**함을 확인.
**대상 화면**: [DSDatamodelStatusColumn.vue](../q-center/vue/front/src/components/DSDatamodelStatusColumn.vue)
**관련 API**: [DataModelController.addAttr](../q-center/src/main/java/qualitycenter/controller/DataModelController.java)

## 0. 설계 철학 (확정)

**"물리명·데이터타입은 사용자가 작성하지 않는다. 표준화 사전을 통해 변환으로만 생성한다."**

- 입력은 **한글명 단일 경로**
- 한글명 → 용어사전(TB_TERMS) → 영문명·도메인 매핑 → 도메인사전(TB_DOMAIN) → 데이터타입·길이
- 수동 입력 경로는 **제공하지 않음**
- 변환 실패 시 처리:
  - **저장은 허용** (설계 흐름을 막지 않음)
  - `TERMS_STND_YN='N'`으로 기록
  - 그리드에서 **해당 행 빨간색 표시** (비표준 시각 경고)
  - [용어 등록하기] CTA로 후속 조치 유도
- 이후 해당 용어가 승인되면 [일괄 재변환] 으로 업데이트 가능

이 원칙은 논리 모델·물리 모델 모두 동일. 한글명 중심이므로 DDL 변환은 언제든 재실행 가능.

## 1. 현재 컬럼 추가 흐름 (있는 그대로)

### 1-1. 다이얼로그 UI — 필수 입력 4종
| 필드 | 컴포넌트 | 필수 | 입력 경로 |
|------|---------|------|-----------|
| 소속 테이블 | v-autocomplete | Y | 수동 선택 |
| 용어 사전 | v-autocomplete | - | 선택 시 영문명·한글명·도메인 자동 |
| 컬럼명 (물리명) | v-text-field | **Y** | 용어 선택 자동 / 표준 적용 자동 / **수동 허용** |
| 컬럼 한글명 (논리명) | v-text-field | **Y** | 용어 선택 자동 / 수동 |
| [표준 적용] 버튼 | v-btn | - | 한글명 → resolveStandard |
| 도메인 사전 | v-autocomplete | - | 선택 시 타입/길이 자동 |
| 데이터 타입 | readonly | **Y** | 용어/도메인/표준적용에서만 |
| 길이 / 소수점 길이 | readonly | - | 위와 동일 |
| PK/FK/NULL/기본값 | v-checkbox/text | - | 수동 |

### 1-2. 입력 경로 3개 혼재 (설계 철학에 반함)

- **A. 용어 사전 선택** — 원칙에 부합 (변환 경로)
- **B. 한글명 + [표준 적용]** — 원칙에 부합 (변환 경로)
- **C. 완전 수동 입력** — 원칙 위배. 서버 `validateAttrStandards`가 차단 시도하지만 오히려 혼란 유발

### 1-3. 서버 addAttr 검증 (핵심)

```java
// DataModelController.validateAttrStandards()
1. attrNm 필수
2. attrNm을 '_'로 split → 각 토큰
3. 각 토큰이 TB_WORD.WORD_ENG_ABRV_NM(승인 단어)에 있어야 함
4. 하나라도 누락 → "표준 미준수: 컬럼명에 표준 단어가 아닌 토큰이 있습니다"
5. dataType 필수
```

이 검증은 사후 차단 — 사용자 경험상 "왜 안 되는지" 알기 어려움. **사전 차단**(UI에서 경로 자체를 제거)이 맞음.

## 4. 개선 계획

### 4-1. 핵심 원칙 (재확인)

1. **입력은 한글명 1개**. 나머지는 변환 결과
2. **변환 성공 = 저장 가능. 변환 실패 = 저장 거부 + 등록 유도**
3. **UI에서 수동 입력 차단**. 서버 검증은 이중 보호
4. **용어/도메인 없으면 그 화면으로 딥링크**

### 4-2. 다이얼로그 재설계 (Phase B — 최우선)

**다이얼로그 구성** (변환 전용):
```
소속 테이블:     [autocomplete]
컬럼 한글명*:    [text-field]          [용어 조회/변환]

── 변환 결과 (readonly) ──
용어(매칭):      CUST_NM (고객 명)
도메인:          NAME_40 (VARCHAR(40))
컬럼 물리명:     CUST_NM
데이터 타입:     VARCHAR(40)

[추가] [취소]
```

**동작**:
- 한글명 입력 → blur 또는 [용어 조회/변환] 클릭 → `resolveStandard` 호출
- 변환 성공: 결과 영역에 용어/도메인/물리명/타입 표시, [추가] 버튼 활성화
- 변환 실패: 결과 영역에 실패 메시지 + **[용어 등록하기]** 버튼 → 용어 등록 다이얼로그 열기(또는 탭 이동). 등록 완료 후 다시 [용어 조회/변환]
- 물리명/타입/도메인 필드는 **readonly 또는 비노출**. 수동 편집 불가
- PK/FK/NULL/기본값 체크박스는 유지 (스키마 속성은 표준과 별개)

### 4-3. 용어 없을 때 유도 플로우 (저장 허용 + 경고)

한글명 → 변환 실패 시:

```
┌─ 표준 용어 없음 ─────────────────────────┐
│ '사용자명'에 해당하는 표준 용어가 없습니다.│
│                                           │
│ 선택 가능:                                 │
│   1. 용어를 등록하고 재변환               │
│   2. 비표준으로 저장 (그리드에 빨간색 표시)│
│                                           │
│   [용어 등록하기] [비표준으로 저장] [취소] │
└───────────────────────────────────────────┘
```

- **[용어 등록하기]**: 용어 등록 다이얼로그 인라인 오픈 (한글명 pre-fill)
- **[비표준으로 저장]**:
  - 물리명 = 한글명의 단순 romanization 또는 `TMP_COL_{순번}` (사용자 편집 가능 영역)
  - 데이터 타입 = 임시(`VARCHAR(255)`) 또는 공란
  - `TERMS_STND_YN='N'`, `DOMAIN_STND_YN='N'` 저장
  - 그리드에서 빨간색 배경 또는 경고 아이콘 표시
  - 이후 용어 승인되면 일괄 재변환 대상

### 4-4. 도메인 매핑 누락 시

용어는 있는데 `terms.domainNm` NULL 또는 TB_DOMAIN 미등록:

```
┌─ 도메인 매핑 필요 ──────────────┐
│ 용어 '고객명'에 도메인이 지정되지│
│ 않았습니다.                      │
│                                 │
│   [용어 수정하기] [도메인 등록]  │
└──────────────────────────────────┘
```

### 4-8. 컬럼 그리드 재배치 (가독성 개선)

**현재 순서** (소속테이블 → 물리명 → 한글명 → 타입 → ...)

```
소유자 | 테이블명 | 테이블 한글명 | 컬럼명 | 컬럼 한글명 | 데이터타입 | 길이 | 소수점 | NULL | PK | FK | 기본값 | 편집
```

**개선 순서** (한글명 중심 + 비표준 강조 컬럼 추가):

```
소유자 | 테이블 한글명 | 테이블명(물리) | 컬럼 한글명 ★ | 컬럼명(물리) | 데이터 타입 | 길이 | 소수점 | NULL | PK | FK | 기본값 | 표준 | 편집
```

**변경 포인트**:
1. **한글명을 물리명 앞**으로 이동 (한글명 중심 설계 반영)
2. "테이블 한글명 / 테이블명" 순서도 동일하게 변경
3. **표준 여부 컬럼 신규**: `TERMS_STND_YN` 기반 ✓ / ✗ 표시
4. **표준 미준수 행**:
   - `background-color: #FFEBEE` (연한 빨강)
   - 컬럼 한글명 앞에 `mdi-alert` 아이콘 + tooltip "비표준 용어"
5. 헤더 묶음 (parent-header): `[테이블]` | `[컬럼]` | `[타입]` | `[제약]` | `[표준]` | `[편집]` 그룹핑

### 4-9. 논리 → 물리 전환 (Phase D)

논리 모델로 용어 기반 설계 완료 후 DDL 생성 가능 여부:
- 현재 변환 흐름으로는 저장 시점에 이미 용어/도메인/물리명/타입이 모두 채워짐
- → 논리 모델이어도 **DDL 생성이 그대로 가능**
- → 별도 "물리화" 단계 불필요 (44번 설계의 논리/물리 구분도 재검토 대상)
