## 3. VSCode Java 확장 문제 (미해결 → 새 계정으로 우회)

### 증상
- Spring Boot Dashboard에 q-center / q-executor apps가 보이지 않음
- `redhat.java` 확장 로그에 JDT Language Server NPE 캐스케이드:
  - `LibraryDetector` probe 실패
  - `CommandLineShortener` NPE

### 분석 과정
1. **첫 가설 (틀림)**: JDK 17+ 미설치 → Microsoft OpenJDK 21 설치 (winget). 불필요했음. `redhat.java-1.53.0` 확장이 자체 번들 Temurin JRE 21을 포함 (`.vscode/extensions/redhat.java-1.53.0-win32-x64/jre/21.0.10-win32-x86_64/`).
2. **두 번째 가설 (틀림)**: JDT persisted VM XML에 Java 8이 default로 박혀 있어서 LSP가 Java 8로 구동됨 → XML 편집해 Java 8 제거. JDT가 reload 시 자동 재탐지해서 되돌림.
3. **세 번째 가설 (틀림)**: `HKLM\SOFTWARE\JavaSoft` 레지스트리가 auto-detect 소스 → `Java Development Kit` / `Java Runtime Environment` 키 삭제 (백업: `Desktop\javasoft-backup.reg`). 효과 없음 — JDT가 다른 소스(PATH 상 Oracle javapath shim 등)에서 Java 8을 계속 찾아냄.
4. **진짜 원인**: **Java 8 + 한글 경로 classpath = `sun.jnu.encoding=MS949` 인코딩 문제**.
   - JDT가 Java 8을 probe할 때 `java.exe -classpath "C:\Users\장재영\...\org.eclipse.equinox.launcher_...jar" ...` 형태로 실행.
   - Java 8은 Korean Windows에서 `file.encoding=MS949`, `sun.jnu.encoding=MS949`를 하드코딩하고 Windows ACP UTF-8 beta(`chcp 65001`)를 존중하지 않음.
   - 한글 경로가 classpath 파싱에서 깨져 "기본 클래스를 찾거나 로드할 수 없습니다" → LibraryDetector NPE.
   - 검증: jar를 `/tmp/ls.jar`(ASCII)로 복사 후 같은 명령 실행 → 정상 동작. 한글 경로 원인 확정.
5. **LSP 자체는 JDK 21 번들로 문제 없음**: 문제는 JDT가 "auto-detect된 모든 JVM"을 초기화 단계에서 probe한다는 점. Java 8이 등록되어 있는 한 한글 경로 probe로 죽음.

### 시도했으나 실패한 우회
- `java.jdt.ls.java.home` / `java.configuration.runtimes`로 JDK 21 명시 지정 → auto-detect가 덮어씀
- JDT `.metadata` VM XML 직접 편집 → 재탐지로 되돌림
- 레지스트리 `JavaSoft` 키 삭제 → 다른 소스에서 재탐지

### 최종 결정
**새 로컬 계정 (ASCII 프로필) 생성**. 근본적으로 한글 경로 문제를 없앰.

- **계정명**: `jjy` (ASCII)
- **비밀번호**: `dev123`
- **권한**: Administrators 그룹
- **상태**: 생성 완료, 활성화됨

### 그 외 제안했던 우회 (참고용, 적용 안 함)
- **Junction 링크**: `mklink /J C:\u "C:\Users\장재영"` + `code --user-data-dir "C:\u\AppData\Roaming\Code\User" --extensions-dir "C:\u\.vscode\extensions"` — 파일 이동 없이 ASCII 경로로 VSCode 기동. 새 계정 대비 덜 근본적이라 사용 안 함.
- **VSCode data-dir 이동**: `--user-data-dir D:\vscode-data` — 확장/설정 새로 세팅 필요.
- **Java 8 폴더 rename**: `jdk1.8.0_202_off` — 프로젝트 빌드에 Java 8 필요해서 보류.

## 6. 교훈

- Korean Windows + Java 8 + 한글 경로 = 구조적 충돌. JVM 시작 지점에 한글 경로가 들어가면 MS949 파싱으로 깨짐.
- JDT가 사용자 지정(`java.jdt.ls.java.home`)보다 auto-detect를 우선시하는 경로가 있어서 설정만으로 Java 8 probe를 막기 어려움.
- 레지스트리 삭제는 auto-detect 소스 중 **일부**만 제거. PATH, JAVA_HOME, 기타 probe 경로가 남아있음.
- 근본 해결은 "JVM이 보는 경로를 ASCII로 만드는 것" — 새 계정 또는 junction.
