# dataQ 편의성 개선 34건을 한 번에 몰아넣은 이유

Phase 1이 마무리되는 2026-03-27경, 프론트엔드 전체 화면을 훑으면서 "고쳐야 하는데 지금까지 미뤄둔" UX 건을 한 번에 정리했다. 결과적으로 34건이 리스트업됐고, 이틀 안에 대부분을 처리했다. 34건은 많지도 적지도 않은 숫자지만, 이걸 **한 번에 묶어서** 처리했다는 점이 이 기록의 주제다.

## 왜 쌓아뒀는가

각각의 건은 크지 않다. "검색 초기화 시 목록도 전체 재조회되게 해라"나 "일괄삭제에 확인 모달을 달아라" 같은 것들이다. 한 건을 잡으면 10분에서 30분이면 끝난다. 그런데 이런 건이 Phase 1 기간 내내 화면 쓰면서 "이거 불편한데"라고 느낄 때마다 쪽지처럼 생겼다.

문제는 쪽지를 바로 처리하지 않는다는 거였다. Phase 1의 주 작업은 표준사전 관리, 진단 엔진, 자동 표준화 같은 큰 기능의 골격을 잡는 것이었다. 그 사이에 "검색 초기화 버튼 동작 수정" 같은 걸 끼워넣으면 컨텍스트가 흔들린다. 지금 머리 속에 진단 로직의 5단계 파이프라인이 떠 있는데 갑자기 Vue 컴포넌트의 `watch` 동작을 건드리는 건 비효율이었다. 그래서 "나중에 모아서 처리" 폴더에 넣어두고 계속 쌓았다.

2026-03-27에 이 폴더를 열어보니 34건이었다. 한 건당 15분씩 잡아도 8시간 넘는 양이었고, 컴포넌트 11개에 걸쳐 있었다.

## 왜 한 번에 처리했는가

두 가지 선택지가 있었다. (1) 큰 기능을 만들 때마다 관련 화면의 UX 건을 같이 처리해서 34건이 쌓이지 않게 만든다. (2) 일단 쌓이게 두고 시점이 맞을 때 한 번에 처리한다.

(1)이 원칙적으로는 맞지만, 큰 기능을 만드는 과정은 한두 화면만 건드리는 게 아니다. 자동 표준화만 해도 단어·용어·도메인·진단 결과 네 화면에 걸쳐 있다. 그 안의 UX 건까지 같이 잡으려고 하면 큰 기능의 진도가 늦어진다. 반대로 (2)는 쌓아두는 동안 "그거 계속 불편한데 왜 안 고쳐지지?"라는 피로가 누적되는 대신, 처리할 때 **배치로 처리하는 효율**이 생긴다.

배치 효율이 정확히 뭔가 하면 이렇다. `DSTerm.vue`를 열어서 11번 건("단어구성목록 렌더링 이상")을 고친다. 같은 파일에 있는 다른 건(9번 "선택 건수 표시", 10번 "일괄삭제 명칭 변경", 12~16번 "용어 등록 모달 관련")을 연달아 고친다. 파일 하나를 열고 맥락을 잡는 비용이 한 번으로 압축된다. 그 후에 빌드하고 테스트하는 비용도 한 번으로 압축된다. 34건을 11개 파일로 나눠 보면 파일당 평균 3건인데, 파일 단위로 묶어서 처리하면 컨텍스트 스위치 비용이 3분의 1로 줄어든다.

결과적으로 (2)가 맞는 판단이었는데, 모든 UX 개선을 이렇게 쌓아두면 되느냐 하면 그건 아니다. 다음 섹션의 조건이 붙는다.

## "쌓아두기"가 통하는 조건

34건을 처리하면서 몇 가지 패턴이 보였다.

**공통 패턴 1: 의존 관계가 없는 건은 쌓아둬도 된다.** "일괄삭제에 확인 모달 추가" 같은 건 독립적이다. 지금 고쳐도, 두 달 뒤에 고쳐도 같은 결과가 나온다. 반대로 "모달 구조 자체를 Step 3에서 Step 2로 줄인다"(12번) 같은 건 다른 결정(단어 선택과 도메인 선택을 한 화면에 둘 것인가)과 묶여 있어서 쌓아두면 맥락이 사라진다. 12번은 실제로 34건 중 유일하게 "이번엔 패스"로 남겨둔 건이다.

**공통 패턴 2: 사용자가 직접 말한 건은 쌓아두지 않는 게 낫다.** 34건 중 대부분은 내가 쓰면서 느낀 건이었고, 외부에서 올라온 게 아니었다. 외부에서 올라온 건이 섞여 있었다면 그 건만큼은 우선순위가 높았을 거다. "사용자가 이 불편을 다시 마주치기 전에" 고쳐야 하는 건은 쌓아두면 안 된다.

**공통 패턴 3: 쌓아두는 기간에 상한을 둔다.** 34건까지 쌓인 건 솔직히 많았다. 이 중 몇 건은 한 달 전에 느낀 것이어서 "왜 이게 불편했는지"를 다시 떠올리는 데 시간이 걸렸다. 리스트에 원인을 같이 적어두지 않았다면 아예 못 고쳤을 거다. 다음에 비슷한 걸 쌓을 때는 20건 정도에서 한 번 비우는 편이 낫다.

## 이틀 안에 처리한 실제 흐름

2026-03-27 리스트 정리, 2026-03-28 ~ 29 이틀에 걸쳐 구현. 컴포넌트별로 묶어서 돌았다.

- **DSDataDiagResult.vue (진단 결과)**: 검색 초기화 동작, 칩 배지, 일괄 용어등록, SQL 복사 버튼 상태, 빠른 등록 모달 미리보기 — 8건을 반나절에.
- **DSTerm.vue (용어 관리)**: 선택 건수, 일괄삭제 명칭·확인, 단어구성목록 렌더링, 등록 모달 중 API 스킵·자동 선택·toast — 9건을 반나절에.
- **DSWord.vue (단어 관리)**: 영문약어 중복 체크, 이음동의어 CSV 붙여넣기, 모달 너비, 단어 일괄등록 실패 CSV — 4건을 한두 시간에.
- **DSDomain.vue (도메인 관리)**: 검색 축소, 일괄삭제 확인 — 2건.
- **MMApproval.vue (승인 관리)**: 상세 패널, 필터 탭, 일괄 승인 UX — 4건.
- **DSDiag.vue (진단 실행)**: 진단 시작 시 스피너, 중복 실행 방지 UX — 3건.
- **공용 헤더·메뉴**: 메뉴 rename, 아이콘 정리 — 3건.
- **남은 1건 (12번 모달 3-Step → 2-Step)**: 이번 라운드 제외.

문제로 불거진 건이 두 개 있었다. 하나는 11번("단어구성목록 렌더링 이상")을 고치면서 v-for의 바인딩 키를 바꿨는데, 용어 수정 모달에서 재렌더링이 안 되는 부작용이 생겼다. `:key`를 `wordId`에서 `wordId + index` 조합으로 바꿔서 해결. 다른 하나는 20번("영문약어 중복 체크")에서 blur 이벤트로 체크하려 했는데, 사용자가 엔터만 치고 submit하는 경로에서는 blur가 안 뛰어 체크가 건너뛰어졌다. blur에만 걸지 않고 form submit 직전에 한 번 더 체크하도록 고쳤다. 두 건 다 "큰 기능 구현 중"이었으면 놓쳤을 만한 작은 regression이었다.

## 배치 처리가 준 부수 효과

처음에 의도하지 않았던 건데, 34건을 한 번에 처리하면서 몇 가지 공통 패턴이 눈에 띄었다.

"일괄 작업에 확인 모달이 없다" 계열이 네 화면에 걸쳐 있었다. 용어·단어·도메인·코드. 같은 패턴의 버그였지만 화면마다 별도로 고치고 있었는데, 고치는 방식이 조금씩 달랐다. 공통 `confirmDialog` 믹스인을 만들어서 네 곳을 같은 구현으로 돌렸다. 한 건씩 분산 처리했으면 이 공통 추출이 안 일어났을 거다. 각 화면의 확인 모달이 조금씩 다른 채로 계속 갔을 거고, 다섯 번째 화면이 생기면 또 다르게 구현됐을 거다.

"실패 목록 CSV 다운로드"도 비슷하다. 용어 일괄등록에는 이미 있었는데 단어 일괄등록에는 없었다(23번). 둘을 같은 헬퍼로 묶어서 쓰게 고쳤고, 이 헬퍼가 나중에 코드 일괄등록에도 재사용됐다. 배치로 처리하지 않았으면 두 번째, 세 번째 구현 때마다 복붙했을 거다.

"검색 초기화 버튼 동작"(3번)도 두 화면에서 같은 버그였다. 초기화 버튼이 입력 필드만 비우고 조회는 안 하는 문제. 이것도 한 번에 둘 다 같은 패턴으로 고쳤다.

배치 처리의 진짜 이익은 컨텍스트 스위치를 줄이는 것보다 이런 **공통 패턴 추출** 쪽에 있었던 것 같다. 여러 건을 나란히 놓고 보면 "어, 이거 다 같은 문제네"라는 걸 발견하기 쉽다. 건 하나씩 처리하면 각 건이 독립적으로 보여서 공통 추출의 기회가 사라진다.

## 남은 것과 안 남은 것

34건 중 33건은 이 이틀 안에 처리됐다. 남은 건 12번 하나. 이건 며칠 뒤 표준사전 화면 전반을 Vue 컴포넌트 관점에서 다시 볼 때 같이 판단하기로 미뤘다. "3-Step을 2-Step으로 줄인다"는 결정이 모달 하나만 보고 내릴 수 있는 게 아니라, 용어 등록의 전체 흐름(Step 2에서 단어 선택, Step 3에서 도메인 선택)이 어떻게 묶이는 게 맞는지 전체적으로 재검토해야 해서다.

결과적으로 34건 중 33건이 처리됐고 컴포넌트별로 공통 패턴 세 가지가 추출됐다. 이 이틀이 생산성이 높았던 건 34건이 많아서가 아니라, **여러 건을 나란히 놓고 본 덕에** 각 건을 따로 봤을 때는 안 보였던 것들이 드러나서였다. 다음에 이런 건을 쌓을 때도 "20건 쯤 되면 한 번 내려놓고 같이 본다"는 리듬을 유지하는 게 맞을 것 같다.
