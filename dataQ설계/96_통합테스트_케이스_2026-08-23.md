## 1. 통합 케이스 — 인과 단위로 분해

### 1-0. 케이스 단위 정의

**케이스 하나 = 인과 한 고리.** "원인 행위 → 확인 가능한 결과 상태" 가 1:1 이어야 한다.

```
✗ IT-02 표준화 개선 루프          ← 실패해도 어디가 깨졌는지 모름
✓ IT-DIAG-021  용어 등록 후 재진단 → 해당 컬럼 이슈 소멸
✓ IT-DIAG-022  이슈 소멸 → terms_stnd_yn 'Y' 승격
✓ IT-DIAG-023  이슈 감소 → 준수율 상승
✓ IT-DIAG-024  준수율 변경 → 대시보드 반영
```

케이스는 **체인(CHAIN)** 으로 묶어 순서 의존을 표현한다. 앞 케이스가 FAIL 이면 뒤는 `BLOCKED`.

| ID 체계 | 영역 |
|---|---|
| `IT-STD-nnn` | 표준 사전 (단어·용어·도메인·코드) |
| `IT-APV-nnn` | 승인 워크플로우 |
| `IT-DM-nnn` | 데이터 모델 (수집·편집·cascade) |
| `IT-GOV-nnn` | 88번 거버넌스 |
| `IT-DIAG-nnn` | 진단 (표준·구조·제외관리) |
| `IT-SCH-nnn` | 스케줄 |
| `IT-SYS-nnn` | 시스템·권한 |

표기: `[UI]` 화면 / `[API]` HTTP / `[DB]` SQL 단언 / `[!]` 부작용 부재 / `★` 결함 회귀 케이스

## 2. 결함 검출 전용 케이스 (DEF-01 ~ DEF-12)

소스 추적에서 **확인된** 결함·의심을 재현하는 케이스. IT 시나리오와 별도로 돌린다.
상태: `확인` = 코드/실측으로 확정 · `의심` = 코드상 그렇게 보이나 미실증

| ID | 결함 | 상태 | 재현 | 판정 SQL |
|---|---|---|---|---|
| **DEF-01** | 승인 용어 참조 시 단어 반려 불가 (FK NO ACTION) | **확인** (2026-08-23 실측) | IT-04 분기 B | 수정 후: 친화 메시지 + raw 예외 미노출 |
| **DEF-02** | `deleteObj`/`deleteObjs` 가 INDEX/CONSTRAINT/inbound FK/`FK_PARENT_OBJ_NM` 미정리 | **확인** (javadoc 과 코드 불일치) | 테이블에 인덱스·제약·자식FK 만든 뒤 삭제 | `SELECT count(*) FROM tb_data_model_index WHERE dm_id=:dm AND table_nm=:tbl;` → 현재 `>0` (기대 0) |
| **DEF-03** | 테이블 rename 시 `FK_PARENT_OBJ_NM` 미갱신 | **확인** | 부모 테이블 rename 후 자식 컬럼 확인 | `SELECT count(*) FROM tb_data_model_attr WHERE dm_id=:dm AND fk_parent_obj_nm=:orig;` → 현재 `>0` |

## 3. 전역 정합성 단언 세트 (L4)

각 시나리오 **전후로 실행**한다. 시나리오가 전역 불변식을 깨뜨리지 않았는지 확인.

```sql
-- L4-1. 고아 매핑
SELECT 'orphan_terms_words' k, count(*) v FROM tb_terms_words tw
  WHERE NOT EXISTS (SELECT 1 FROM tb_terms t WHERE t.terms_id=tw.terms_id)
UNION ALL
SELECT 'orphan_attr', count(*) FROM tb_data_model_attr a
  WHERE NOT EXISTS (SELECT 1 FROM tb_data_model_obj o
        WHERE o.dm_id=a.dm_id AND COALESCE(o.obj_owner,'')=COALESCE(a.obj_owner,'') AND o.obj_nm=a.obj_nm)
UNION ALL
SELECT 'orphan_diag_result', count(*) FROM tb_diag_result r
  WHERE NOT EXISTS (SELECT 1 FROM tb_diag_job j WHERE j.diag_job_id=r.diag_job_id);
-- 기대: 전부 0

-- L4-2. 중복
SELECT 'dup_word' k, count(*) v FROM (SELECT word_nm FROM tb_word GROUP BY 1 HAVING count(*)>1) x
UNION ALL
SELECT 'dup_terms', count(*) FROM (SELECT terms_nm FROM tb_terms GROUP BY 1 HAVING count(*)>1) x;
-- 기대: 전부 0

-- L4-3. 컬럼 수 정합
SELECT count(*) AS attr_cnt_mismatch FROM tb_data_model_obj o
WHERE o.use_yn='Y' AND o.obj_attr_cnt <>
      (SELECT count(*) FROM tb_data_model_attr a
        WHERE a.dm_id=o.dm_id AND COALESCE(a.obj_owner,'')=COALESCE(o.obj_owner,'')
          AND a.obj_nm=o.obj_nm AND a.use_yn='Y');
-- 기대: 0   (DEF-08 로 인해 동명이 테이블이 있으면 깨질 수 있음)

-- L4-4. ATTR_ORD 연속성 (테이블별 1..N)
SELECT count(*) AS ord_dup FROM (
  SELECT dm_id, COALESCE(obj_owner,'') ow, obj_nm, attr_ord
  FROM tb_data_model_attr WHERE use_yn='Y'
  GROUP BY 1,2,3,4 HAVING count(*)>1) x;
-- 기대: 0

-- L4-5. 표준 flag 쌍 일관성 (§0-5: 항상 같은 값이어야 함)
SELECT count(*) AS flag_mismatch FROM tb_data_model_attr
WHERE use_yn='Y' AND terms_stnd_yn IS DISTINCT FROM domain_stnd_yn;
-- 기대: 0  (진단 직후 기준. 표준화 변환 직후엔 일시적으로 다를 수 있음)

-- L4-6. 승인 상태 값 집합
SELECT DISTINCT aprv_status FROM tb_data_model_attr;
-- 기대: {NULL, DRAFT, SUBMITTED, APPROVED, REJECTED} 외 값 없음

-- L4-7. 스케줄 ↔ 모델 정합
SELECT count(*) AS live_sch_dead_model FROM tb_diag_schedule s
WHERE s.use_yn='Y' AND NOT EXISTS
      (SELECT 1 FROM tb_data_model m WHERE m.dm_id=s.data_model_id AND m.use_yn='Y');
-- 기대: 0
```
