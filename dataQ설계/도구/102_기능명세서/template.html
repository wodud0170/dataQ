1제품 구성

화면과 API 를 맡는 웹 서버, 오래 걸리는 작업을 맡는 작업 서버, 둘이 함께 쓰는 공용 모듈과 메타 저장소로 이뤄진다. 고객 DB 에는 수집·진단·DDL 반영 때만 접속한다.

q-center 웹 서버

Vue 화면을 내려주고 API 를 받는다. 로그인·세션·권한 판정, 표준 사전과 데이터 모델 편집, 승인 처리, 작업 서버로 보내는 요청과 진행 알림 중계를 맡는다.

q-executor 작업 서버

오래 걸리는 일을 별도 스레드로 돌린다. 데이터 모델 수집, 표준 진단, 구조 변경 진단, 엑셀 일괄등록, 정해진 시각에 진단을 띄우는 스케줄러.

q-common 공용 모듈

두 서버가 함께 쓰는 데이터 객체, MyBatis 매퍼 XML 27개, 엑셀 처리 같은 공용 서비스.

4핵심 업무 흐름

여러 화면에 걸친 기능을 업무 순서로 묶었다. 각 단계의 세부는 6장의 해당 영역에 있다.

표준 사전 등록과 승인 3장 표준 사전 · 8장 승인

  1. 등록단어·용어·코드·도메인을 화면에서 하나씩, 엑셀로 일괄, 한글컬럼 일괄 표준화로 한꺼번에 등록
  2. 승인 상태 결정표준 직접 관리 권한(관리자는 모든 권한)이 있으면 바로 승인. 없으면 승인 대기
  3. 승인·반려표준 승인 권한자가 표준 사전 변경 승인 화면에서 건별·일괄 처리. 결재선이 있는 유형은 단계마다 결재자가 결재함에서 승인하고 마지막 단계에서 승인된다. 용어·코드는 구성 단어가 먼저 승인돼야 승인된다. 반려하면 사유를 남기고 항목을 지운다
  4. 결과 확인승인 내역과 변경 이력이 쌓이고, 요청자는 표준 사전 변경 요청 현황에서 처리 결과와 사유를 본다

단어·용어·도메인·코드는 표준사전 단위로 나뉜다. 기관마다 표준화 관례가 다르면 사전을 따로 두고, 데이터 모델마다 쓸 사전을 지정한다.

데이터 모델 수집 4장 데이터 모델 · 11장 데이터 소스

  1. 데이터 소스 등록DBMS 유형·드라이버·접속 정보를 넣고 연결 테스트. Oracle·Tibero 는 SID 와 Service Name 중 고른다
  2. 데이터 모델 등록데이터 소스와 표준사전을 지정한다
  3. 수집 범위대상 DB 에서 스키마 목록을 읽어 고른다. 시스템 스키마는 빠진다
  4. 수집 실행작업 서버가 테이블·컬럼·인덱스·제약조건을 읽어 저장한다. 진행 상황이 화면에 바로 뜬다
  5. 활용테이블·컬럼 화면에서 조회·편집, 데이터 모델 현황, ERD, DDL 내려받기, XMI 2.1 내보내기

수집 말고도 엑셀 업로드나 모델링 도구 파일(ERwin XML, XMI 2.1)로 테이블·컬럼을 들여올 수 있다. 수집 때 같은 물리명 행은 DB 메타데이터로 덮어쓰고, 이번 수집에 없는 기존 행은 지우지 않는다.

데이터 모델 변경 승인 5장 거버넌스

DRAFT저장, 신청 전 → SUBMITTED신청, 승인 대기 → APPROVED승인 — 모델에 반영 REJECTED반려 — 변경 전으로

어떤 변경이 승인을 거치나

  • 스키마에 영향을 주는 변경 (TIER1): 테이블·컬럼 추가·삭제, 영문명·소유자·타입·길이 변경 — 모델 직접 반영 권한이 없으면 승인 필요
  • 그 밖의 수정 (TIER2): 한글명·설명·NULL 여부·디폴트 등 — 바로 반영, 이력만 남김
  • 모델 직접 반영 권한자(관리자 포함)가 한 변경은 바로 승인 상태. 신청 묶음은 모델 승인 권한자가 처리

승인 뒤

  • 변경마다 변경 전후 값과 DDL 조각(모델 데이터소스의 DBMS 문법 — Oracle·Tibero·PostgreSQL·MariaDB·SQL Server)을 이력에 남긴다
  • 그 모델 시스템의 DB 반영 권한자가 [DB 반영] 으로 모델의 데이터소스에 DDL 을 실행한다. 테이블 추가는 이때 승인된 컬럼으로 CREATE TABLE 을 만든다
  • 실행 결과를 성공 · 권한 없음 · 실패 · 건너뜀 으로 나눠 기록한다

진단 6장 진단·스케줄

표준 진단

  1. 진단 대상 컬럼을 고른다 (진단 제외로 지정한 테이블·컬럼은 빠짐)
  2. 컬럼마다 네 가지를 판정: 용어 미존재 · 한글명 불일치 · 데이터 타입 불일치 · 데이터 길이 불일치
  3. 결과를 저장하고 준수율을 낸다
  4. 결과 화면에서 용어 바로 등록, 컬럼 표준화·코멘트 변경 스크립트 생성
준수율 = (전체 컬럼 − 이슈 컬럼) ÷ 전체 컬럼 × 100

구조 변경 진단

  1. 저장된 데이터 모델(승인된 테이블·컬럼)을 기준으로 삼는다
  2. 지금 대상 DB 의 구조를 다시 읽는다 (진단 제외 대상은 양쪽에서 뺌)
  3. 컬럼 · 인덱스 · 제약조건의 추가·삭제·변경을 찾는다
  4. 일치율을 내고 결과를 엑셀로 내려받는다
일치율 = (1 − 바뀐 테이블·컬럼 ÷ 전체 테이블·컬럼) × 100

스케줄

  • 간편 설정 (매일 · 매주 · 매월 + 시각) 또는 Cron 식
  • 표준 진단·구조 변경 진단을 정해진 시각에 띄운다. 같은 모델·같은 유형의 예약 진단이 돌고 있으면 건너뛰고 기록한다
  • 즉시 실행, 실행 이력 (실행 중 · 완료 · 오류 · 건너뜀)과 소요 시간

한글컬럼 일괄 표준화 7장 표준화 도구

  1. 입력엑셀·CSV 업로드나 직접 입력. 대상 데이터 모델과 등록할 표준사전을 고른다
  2. 단어 분리이미 있는 용어인지 먼저 보고, 형태소 분석(OKT)으로 단어를 1순위·2순위로 나눈다. 동의어를 찾고 없는 단어는 새로 제안한다
  3. 조합·추천단어 영문약어를 이어 붙여 용어 영문약어를 만들고, 마지막 단어로 도메인을 추천한다
  4. 리뷰행마다 단어 교체·도메인 변경. 등록할 수 있는지와 못 하는 이유를 표시한다
  5. 등록새 단어와 용어를 한 번에 등록하고, 원래 입력과 표준 매핑을 변환 이력에 남긴다
