## 1. 용어 통일 — `형식단어`

행안부 공공DB 표준화지침 의 공식 용어는 **형식단어**. 동의 용어 "분류어" 는 지침의 괄호 부연설명일 뿐이다 ([25번 §134](25_공공DB표준화지침_준수현황.md)).

이번 작업으로 **사용자 가시 텍스트 모두 `형식단어` 로 통일**:

| 위치 | 변경 |
|------|------|
| DSTermRecommend.vue placeholder | `분류어 검색/선택` → `형식단어 검색/선택` |
| no-data-text | `일치하는 분류어 없음` → `일치하는 형식단어 없음` |
| 버튼 라벨 | `분류어 추가` → `형식단어 추가` |
| 안내문 | `마지막 단어가 분류어가 아니거나...` → `마지막 단어가 형식단어가 아니거나...` |
| swal 알림 | `분류어 조회 실패` / `분류어를 선택해주세요` → `형식단어` |

**변경 안 한 것** — 코드 내부 변수/식별자 (호환성):
- DB 컬럼: `WORD_CLSF_YN`
- VO 필드: `wordClsfYn`
- JS 변수: `selectedClsfWord`, `classWords`, `domainsInClsf`
- 주석 내 "분류어" 잔존 (영향 없음)

> **사용자매뉴얼** 의 "분류어" 표기 (8.2 절 등) 는 후속 작업으로 별도 갱신 예정.

## 2. 분리 알고리즘 — 4단계

### 2-1. 1단계: 기등록 용어 매칭 (TB_TERMS 직접)
입력 전체가 `TB_TERMS.TERMS_NM` 에 정확히 일치하면 즉시 `REGISTERED` 상태로 반환. 단어 분리·도메인 추론 등 후속 처리 모두 스킵.

### 2-2. 2단계: OKT 형태소분석 + 후보 토큰 구성
1. OKT (Twitter Korean Text) 로 입력 토큰화
2. **NN(명사) 태그만** 추출 (조사/어미 제외)
3. 후보 토큰 set 구성:
   - OKT NN 토큰
   - TB_WORD 의 단어명 중 입력 부분문자열인 것 (length ≥ 2)
   - TB_WORD_DICT 의 추천 사전어 중 입력 부분문자열인 것

### 2-3. 3단계: DP 기반 최적 분리 (B + D 적용)

**점수 체계** ([calculateTokenScore](../q-center/src/main/java/qualitycenter/controller/DataStandardController.java#L2562)):

| 매칭 종류 | 점수 |
|----------|------|
| TB_WORD (length ≥ 2) | `10000 + length × 100` |
| **TB_WORD (length = 1, 형식단어)** | `10000 + 100 = 10100` (분류어 정상 점수) |
| **TB_WORD (length = 1, 비형식단어)** | `5000` ([D] 격하 — 카테고**리** / 메모**리** 같은 외래어 끝의 우연 매칭 방지) |
| TB_WORD_DICT | `5000 + length × 100` |
| OKT 2~4자 | `500 + length × 50` |
| OKT 5자 이상 | `100` |
| 1자 OKT | `10` |
| 1글자 강제 skip | `−500` |

**B. SPLIT_PENALTY = 8000** ([dpSplit](../q-center/src/main/java/qualitycenter/controller/DataStandardController.java#L2418)):
DP 가 토큰을 추가할 때마다 점수에서 8000 차감. 같은 입력을 단일 단어로 cover 가능하면 그쪽이 점수상 유리.

이유: 원래 점수 체계는 토큰 수가 늘면 합산이 커져 분리가 점수상 유리한 구조였다. 예 (B 적용 전):
- `상품카테고리` ← `상품(2,TB) + 카테고리(4,OKT)` = 10200 + 700 = **10900**
- `상품(2,TB) + 카테고(3,OKT) + 리(1,TB,clsf=N)` = 10200 + 650 + 10100 = **20950** (분리 압승 = 잘못된 결과)

B 적용 후 SPLIT_PENALTY 차감으로 단일 단어 우선:
- 통째 = 10900 − 16000 = −5100
- 분리 = 20950 − 24000 = −3050  (D 미적용 시 여전히 분리 우세)

D 적용 (1자 비분류어 격하 5000):
- 분리 = 10200 + 650 + 5000 − 24000 = **−8150**
- 통째 = **−5100** ← 최종 통째 채택

### 2-4. 4단계: 사후처리 — 미신뢰 구간 사전 재검색

DP 결과를 받은 후, **미신뢰 토큰 연속 구간**을 합쳐 사전(TB_WORD/DICT/**alloph_synm**) 재검색 ([resolveUncertainRuns](../q-center/src/main/java/qualitycenter/controller/DataStandardController.java#L2774)):

**트러스트 vs 미신뢰**:
- 트러스트: TB_WORD ≥ 2자 / TB_WORD 1자 형식단어 / DICT 매치
- 미신뢰: OKT-only / TB_WORD 1자 비형식단어

**처리**: 미신뢰 토큰이 연속 2개 이상이면 합쳐서 검사. 발견되면 단일 토큰으로 치환.

예: `상품카테고리` → DP 가 `[상품, 카테고, 리]` 반환 →
- 트러스트: 상품 (TB_WORD ≥2자)
- 미신뢰: 카테고 (OKT only), 리 (TB_WORD 1자 비형식단어)
- 합쳐서 "카테고리" 검사 → TB_WORD `범주` 의 `ALLOPH_SYNM_LST` 에 "카테고리" 발견 → `[상품, 카테고리]` 로 치환 (selected = 범주의 wordId/CTGRY/Category)

이 방식의 장점:
- DP 의 candidate set 을 건드리지 않음 → 회귀 위험 0
- 미신뢰 구간만 보수적 보강 → 의도치 않은 분리 변경 없음
- 단계별 디버깅 용이 (DP 결과 vs 사후처리 결과 로그 분리)

## 3. UX 흐름

### 3-1. Stepper — 3단계 (이전 4단계에서 축소)

| 단계 | 설명 | 비고 |
|------|------|------|
| 1. 입력 | 한글 컬럼명 textarea + 양식 다운로드 + 파일 업로드 | 줄바꿈으로 구분 |
| 2. 분석 | OKT + DP + 사후처리 진행 표시 (loading) | |
| 3. 리뷰 | 결과 표 + 등록 액션 | **STEP 4 (완료/DDL) 제거** — 등록 후 이 화면에 머무름 |

**STEP 4 제거 사유**: 등록 후 결과 화면으로 이동하면 그 전 화면 복귀 불가능, 부분 수정 불가능 → 사용자 답답함. DDL 생성 기능은 [데이터 모델 관리 → DDL 다운로드](../q-center/src/main/java/qualitycenter/controller/DataModelController.java#L189) 에 별도 존재.

### 3-2. STEP 3 리뷰 화면 구성

**상단 카운터**:
- 전체 / 기등록 / 자동완성 / 부분매칭 / 미매칭
- (등록 진행 후) 등록완료 또는 등록신청 / 실패 카운터 추가

**필터 칩** (`이슈` 를 두 개로 분리):
- 전체 / 자동완성 / 부분매칭 / 미매칭 / 기등록 / 등록실패 (있을 때)

**툴바**:
- `[표시 컬럼 ▼]` 메뉴 — 구성단어/영문약어/도메인/타입길이 컬럼 토글
- `[용어 등록 (N건)]` — 등록 가능 row 자동 일괄 등록 (N=isRowRegisterable 인 row 수)
- `[다시 입력]` — STEP 1 복귀

**`[전체 승인]` 버튼 제거**:
이전엔 이 버튼으로 일괄 등록 대상을 명시 마킹(`_approved=true`) 했지만 "**뭘** 승인?" 사용자 혼란. 새 모델은 **데이터 상태 자체로 등록 가능 자동 판정** (`isRowRegisterable`).

### 3-3. 등록 가능 판정 — `isRowRegisterable(row)`

다음 4 조건 모두 충족 시 등록 가능:
1. `status !== 'REGISTERED'`
2. `_postStatus !== 'SUCCESS' && !== 'SKIPPED'`
3. 모든 `words[].status === 'MATCHED'`
4. `recommendedDomainNm` 비어있지 않음

이전 `_approved` 플래그 제거. 사용자가 [수정] 거치지 않아도 데이터가 충족되면 즉시 등록 가능.

### 3-4. 액션 컬럼 — 7가지 분기

| 상태 | 표시 |
|------|------|
| `REGISTERED` (기등록 용어) | 회색 "기등록" 텍스트 |
| `_postStatus = SUCCESS` (admin) | 녹색 칩 "등록완료" |
| `_postStatus = SUCCESS` (일반) | 청색 칩 "등록신청 완료" |
| `_postStatus = SKIPPED` | 회색 칩 "이미 등록됨" |
| `_postStatus = FAIL` | 빨강 칩 "등록실패" + [재수정] (툴팁에 에러 메시지) |
| **등록 불가 (단어/도메인 미충족)** | **노랑 칩 (사유) + [수정]** (툴팁에 상세) |
| **등록 가능** | **[수정] (회색) + [용어 등록] (활성)** |

**차단 사유 칩** ([getBlockReason](../q-center/vue/front/src/components/DSTermRecommend.vue)):
- `단어 미인식` — UNRECOGNIZED 단어 있음
- `단어 미등록` — NEW 단어 있음 (등록 필요)
- `도메인 미지정` — recommendedDomainNm 비어있음
- 툴팁에 어느 단어가 미인식/미등록인지 상세

### 3-5. 단건/일괄 등록 일관성

- **단건 [용어 등록]** (액션 컬럼): `isRowRegisterable=true` 일 때만 활성. 모달 안 거치고 즉시 등록.
- **일괄 [용어 등록 (N건)]** (상단): `isRowRegisterable=true` 인 row 만 자동 처리. PARTIAL 은 자동 제외.

→ 단건/일괄 모두 같은 기준. 시도 자체 불가능한 경우 버튼 비활성.

### 3-6. 등록 후 동작 — STEP 3 에 머무름

`registerTermsBatch` 응답의 `details[]` 를 row 별 매칭하여 inline 갱신:
- SUCCESS / SKIPPED → row 잠금 (재등록 불가)
- FAIL → row 는 살아있고 [재수정] 으로 보완 가능

화면 이동 없음. 카운터·칩만 갱신.

### 3-7. 그리드 인라인 도메인 변경

**문제 사례**: 분석 시 마지막 단어가 형식단어 아니어서 도메인 없던 row → [수정] 모달에서 형식단어 추가 → 그리드 복귀 → 도메인 v-select 안 보임

**원인**: `item.domainCandidates` 가 분석 시점에만 세팅되어 모달 수정 후 갱신 안 됨.

**수정** ([doConfirmEditFinish](../q-center/vue/front/src/components/DSTermRecommend.vue)):
모달 확인 시 `this.domainsInClsf` 를 `item.domainCandidates` 에 동기화 → 그리드 v-select 활성화.

추가로 그리드 v-select 의 잠재 버그도 수정: `@change` 핸들러 부재 → 도메인명만 바뀌고 type/length 안 따라옴 → `onGridDomainChange(item)` 추가.

### 3-8. 표시 컬럼 토글

`[표시 컬럼 ▼]` 메뉴에서 다음 컬럼 on/off:
- 구성단어 / 영문약어 / 도메인 / 타입길이

한글명/상태/액션은 항상 표시.

## 4. 데이터 모델 활용

### 4-1. TB_WORD

| 컬럼 | 활용 |
|------|------|
| `WORD_NM` | 단어 매칭 (DP candidate, 사후처리) |
| `WORD_ENG_ABRV_NM` | 영문약어 결합 (예: GDS_CTGRY) |
| `WORD_ENG_NM` | 영문명 |
| **`WORD_CLSF_YN`** | 형식단어 여부 → 1자 단어 점수 분기 + 도메인 cascade 후보 |
| **`ALLOPH_SYNM_LST`** | 동의어 목록 → 사후처리에서 카테고리 → 범주 매핑 |
| `DOMAIN_CLSF_NM` | 형식단어가 가지는 도메인 분류 → 도메인 cascade |

### 4-2. TB_WORD_DICT

`WORD_KOR / WORD_ENG / WORD_ABRV` 매핑. DP 점수에서 TB_WORD 다음 우선순위.
DP 와 사후처리 둘 다에서 candidate 로 활용.

### 4-3. TB_DOMAIN

`DOMAIN_CLSF_NM` 으로 형식단어와 cascade. 마지막 단어가 형식단어이면 그 단어의 `DOMAIN_CLSF_NM` 을 거쳐 후보 도메인 도출.
