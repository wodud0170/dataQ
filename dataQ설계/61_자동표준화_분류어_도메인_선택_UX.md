# 61. 자동 표준화 — 분류어·도메인 선택 UX 추가

**작성일**: 2026-04-22
**화면**: 데이터 표준화 진단 > **자동 표준화 지원** ([DSTermRecommend.vue](../q-center/vue/front/src/components/DSTermRecommend.vue))
**대상 모달**: 단어 정보 수정 모달 (리스트 행의 [수정] / [재수정] 버튼 클릭 시)

## 1. 배경

### 1-1. 현재 문제
용어 등록 시 **"마지막 단어는 분류어여야 한다"** 는 유효성 검사가 있는데, 사용자가 어떤 단어를 넣어야 그 검사를 통과할지 **UI 만 보고는 알 수 없음**.

- 일반 단어는 자유 입력 가능
- 분류어는 TB_WORD 에서 `word_clsf_yn='Y'` 인 단어만 해당
- 자유 입력 후 미등록 단어면 신규 등록 플로우로 빠지고, 분류어인지 아닌지는 끝에 가서야 검증 실패로 드러남

### 1-2. 개선 목표
**분류어를 사용자 앞에 직접 꺼내 보여준다**. 드롭다운에서 선택만 하면 확실히 분류어가 들어가게. 도메인도 그에 맞춰 같이 선택.

## 2. 확정 사항 (Q&A 5개)

| # | 질문 | 확정 답변 |
|---|------|----------|
| 1 | UI 배치 | **같은 줄** — 기존 `[단어명 입력] [단어 추가]` 옆에 `[분류어 ▼] [도메인 ▼] [분류어 추가]` 이어 붙임. 모달 폭 조정 필요 |
| 2 | 선택 후 동작 | **[분류어 추가] 버튼을 별도로 눌러야** 리스트에 반영. 드롭다운 선택만으로 자동 추가 X |
| 3 | 추천 도메인 | 분류어에 따라 자동 이동. 이미 분류어로 완성된 용어는 **기존 추천 도메인이 드롭다운에 preselect 된 채로 표시** (확인만 하는 프로세스) |
| 4 | 분류어 위치 | 고정 X. 일반 단어와 동일하게 리스트 맨 끝에 추가되지만 이후 순서 이동 가능. 선택지를 주는 목적 |
| 5 | 중복/이상 케이스 | 일반 단어와 동일하게 취급. "분류어가 이미 있는데 또 추가" 같은 이상 케이스는 관리자가 정리 |

### 핵심 목적 (사용자 문구)
> "마지막 단어 같은 경우 분류어가 강제되는데 사용자 입장에선 어떤 단어를 마지막으로 추가해야 그 유효성 검사를 통과할지 알수가 없기 때문. 직관적으로 보여줘서 사용자 편의를 증가시키는 것."

## 3. 데이터 구조 (기존 스키마 활용)

```
TB_WORD (word_clsf_yn='Y' 인 행 = 분류어)
  - word_id, word_nm (한글), word_eng_abrv_nm (영문약어), word_eng_nm (영문명)
  - domain_clsf_nm: 연결된 도메인 분류명
       ↓ domain_clsf_nm
TB_DOMAIN_CLSF (도메인 분류)
       ↓ 1:N
TB_DOMAIN (실제 도메인)
  - domain_id, domain_nm, data_type, data_len, data_decimal_len
  - domain_clsf_nm 으로 역참조 가능
```

**쿼리 패턴**:
```sql
-- 분류어 드롭다운 원천
SELECT word_id, word_nm, word_eng_abrv_nm, word_eng_nm, domain_clsf_nm
  FROM TB_WORD
 WHERE word_clsf_yn = 'Y'
   AND aprv_yn      = 'Y'
   AND use_yn       = 'Y'
 ORDER BY word_nm;

-- 도메인 드롭다운 원천 (cascade)
SELECT domain_id, domain_nm, data_type, data_len, data_decimal_len
  FROM TB_DOMAIN
 WHERE domain_clsf_nm = :domainClsfNm
   AND aprv_yn        = 'Y'
   AND use_yn         = 'Y'
 ORDER BY domain_nm;
```

## 4. UI 변경

### 4-1. 모달 내 기존 구조 (변경 전)
```
┌─ 단어 정보 수정 ─────────────────────────┐
│ [ 단어 테이블 ]                          │
│                                          │
│ [ 한글 단어명 ] [ 단어 추가 ]            │  ← 이 줄에 추가
│                                          │
│ 용어 미리보기: ... → ...                 │
│                                          │
│                  [ 취소 ] [ 확인 ]       │
└──────────────────────────────────────────┘
```

### 4-2. 변경 후
```
┌─ 단어 정보 수정 ─────────────────────────────────────────────────┐
│ [ 단어 테이블 ]                                                  │
│                                                                  │
│ [ 한글 단어명 ] [ 단어 추가 ]  │  [ 분류어 ▼ ] [ 도메인 ▼ ] [ 분류어 추가 ] │
│                                                                  │
│ 용어 미리보기: ... → ...                                         │
│                                                                  │
│                  [ 취소 ] [ 확인 ]                               │
└──────────────────────────────────────────────────────────────────┘
```

- `v-dialog max-width: 750 → 1000` 확대 (5요소 들어가도록)
- `flex-wrap: wrap` 으로 좁은 화면에서 자동 줄바꿈 허용 (반응형)

### 4-3. 동작 흐름
1. 모달 열림 시 **분류어 드롭다운 1회 로드** (TB_WORD 전량, 100건 내외 예상이라 가볍다)
2. 사용자가 분류어 선택 → 선택한 분류어의 `domain_clsf_nm` 으로 도메인 드롭다운 cascade 로드
3. `editingItem.recommendedDomainNm` 이 현재 도메인 목록 안에 있으면 → 그걸 `selectedDomain` 으로 preselect
4. 사용자가 도메인 변경 가능 (선택 사항)
5. **[분류어 추가]** 클릭:
   - 현재 `currentEditWords` 에 분류어 단어 push (status='MATCHED', selected 에 wordId/wordNm/wordEngAbrvNm/wordEngNm/domainClsfNm)
   - `editingItem.recommendedDomainNm`, `recommendedDomainId`, 관련 domain 속성 덮어쓰기
   - `recalcItemStatus(editingItem)` 호출 → 미리보기·영문약어 재조합
   - 드롭다운/선택 상태 초기화

## 8. 배포·검증

### 검증 시나리오
1. 모달 열기 → 분류어 드롭다운에 100건 내외 목록 뜨는지
2. "명" 선택 → 도메인 드롭다운에 관련 도메인들 자동 로드
3. "고객" + "명" 구성으로 용어 완성 → 미리보기 "고객명 → CUST_NM"
4. 기존 추천 도메인이 있던 PARTIAL 용어 재수정 시 해당 도메인이 preselect 되는지
5. [분류어 추가] 클릭 후 드롭다운이 초기화되는지

### 영향 범위
- 읽기 전용 조회 2개만 추가 → 기존 데이터/스키마 변경 없음
- `editingItem.recommendedDomainNm` 덮어쓰기는 기존 로직(사용자가 도메인 셀렉터 변경 시와 동일) 과 동일 경로

### 빌드
- 백엔드 Controller 변경 + 프론트 Vue 변경 → q-center 전체 재빌드 (`mvn package -DskipTests`)

## 9. 2차 개선 (같은 날 발견된 허점 처리)

1차 구현 후 시나리오 테스트 중 발견된 문제와 재설계.

### 9-1. 발견된 허점
1. **도메인만 독립 수정 불가**
   - 시나리오: 분류어 + 도메인 선택해서 추가 → 확인 → 그리드 저장 → 재수정 시 도메인만 바꾸려 함
   - 문제: 도메인 드롭다운이 `selectedClsfWord.domainClsfNm` 에 묶여 있어서 분류어부터 다시 선택해야 도메인 옵션이 뜸
2. **분류어 개수 대비 UI**: 분류어가 수십~수백 건이면 `v-select` 스크롤로는 불편. 검색/자동완성 필요

### 9-2. 재설계 핵심 원칙
> **"도메인 드롭다운의 의존 대상 = 현재 용어의 마지막 위치 단어(분류어)"**
>
> 분류어 picker 의 `selectedClsfWord` 가 아니라 `currentEditWords` 맨 끝 단어의 `domainClsfNm`. 이래야 단어 리스트 상태와 정합성 유지 + 도메인만 독립 수정 가능.

### 9-3. 변경 사항

| 항목 | 1차 구현 | 2차 개선 |
|------|---------|---------|
| 분류어 picker | `v-select` | **`v-autocomplete` (검색/자동완성)** |
| 도메인 cascade 의존 | `selectedClsfWord.domainClsfNm` | **`currentEditWords[-1].domainClsfNm`** (computed `lastWordDomainClsfNm`) |
| 도메인 드롭다운 위치 | 분류어 picker 같은 줄 | **별도 줄 + 라벨 "용어 도메인 (마지막 단어 기준)"** |
| 도메인 변경 반영 | [분류어 추가] 클릭 시에만 | **즉시 반영** (`@change` → `onDomainChange` → `editingItem.recommendedDomain*` 덮어쓰기) |
| 분류어 추가 시 도메인 처리 | 선택 도메인을 함께 확정 | 단어만 추가. watcher 가 `lastWordDomainClsfNm` 변경 감지 후 도메인 목록 자동 재로드 + preselect |
| 마지막 단어가 분류어 아님 | - | 도메인 드롭다운 disabled + "마지막 단어가 분류어가 아닙니다" 안내 |

### 9-4. 흐름 (재설계 후)
```
[모달 열림]
   ↓
 기존 last word 의 domainClsfNm 계산 (computed)
   ↓ 있으면
 loadDomainsForLastWord(clsfNm) → domainsInClsf 로드 + 기존 recommendedDomainNm preselect
                                                                       
[사용자 액션 A — 도메인만 변경]
 도메인 드롭다운 @change → onDomainChange → editingItem.recommendedDomain* 즉시 덮어쓰기
 → 분류어 건드릴 필요 X

[사용자 액션 B — 분류어 변경 (새 마지막 단어)]
 [분류어 autocomplete] 검색/선택 → [분류어 추가] 클릭
 → currentEditWords 에 push
 → lastWordDomainClsfNm computed 재계산
 → watcher 발동 → loadDomainsForLastWord 재실행 → domainsInClsf 교체 + preselect

[사용자 액션 C — 일반 단어 추가 등으로 마지막 단어가 분류어가 아닌 상태]
 lastWordDomainClsfNm = '' → watcher: domainsInClsf=[], selectedDomain=null
 → 도메인 드롭다운 disabled + 빨간 안내 문구 노출
```

| 파일 | 내용 |
