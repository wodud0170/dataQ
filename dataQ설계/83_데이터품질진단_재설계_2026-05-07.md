### 2-2. 신규 테이블

**TB_QUAL_RUNNING_LOCK** (컬럼 단위 application-level 동시 실행 방지):
```sql
CREATE TABLE TB_QUAL_RUNNING_LOCK (
  DM_ID         VARCHAR(36)  NOT NULL,
  OBJ_NM        VARCHAR(200) NOT NULL,
  ATTR_NM       VARCHAR(200) NOT NULL,
  DIAG_ID       VARCHAR(50)  NOT NULL,
  USER_ID       VARCHAR(50),
  START_DT      VARCHAR(14)  NOT NULL,
  PRIMARY KEY (DM_ID, OBJ_NM, ATTR_NM)
);

COMMENT ON TABLE TB_QUAL_RUNNING_LOCK
  IS '품질 진단 컬럼 단위 동시 실행 방지 — application-level mutex (운영 DB 락 X)';
```

운영:
- 진단 시작 전 INSERT 시도 (`ON CONFLICT DO NOTHING`)
- affected=0 면 SKIP + "이미 진단 중" 알림
- 끝나면 DELETE
- START_DT > 30분 경과 lock 은 stale → 자동 해제 (재기동 시 + cron 으로 정기 청소)

| 주민등록번호 | REGEX | `^\d{6}-?[1-4]\d{6}$` |

## 5. 화면 상세

### 5-1. 도메인 룰 관리 (DSQualDomainRule.vue 신규)

**레이아웃**:
```
┌──────────┬──────────────────────────────────────────────────────┐
│ 분류 트리 │ [선택된 도메인]                              [+ 새 룰] │
│          ├────────────────────────────────────────────────────│
│ 전화번호 │  룰명          유형     파라미터        심각도 사용 │
│ 금액     │  ─────────────────────────────────────────────────│
│ 연월일   │  전화번호 형식  REGEX  ^0\d{1,2}-...  ERROR   Y    │
│ ...      │  NOT NULL      NOT_NULL              ERROR   Y    │
│          │                                                    │
│          │  [📋 카탈로그에서 가져오기]  [⬇ 엑셀 다운로드]      │
└──────────┴──────────────────────────────────────────────────────┘
```

**기능**:
- 좌측 트리 — 도메인 분류 (1단계) → 도메인 (2단계). 도메인 클릭 시 우측에 적용 룰 목록
- 우측 — 그리드 + 인라인 편집 + 룰별 ON/OFF 토글
- [+ 새 룰] 모달:
  - 룰 타입 선택 (NOT_NULL / RANGE / LENGTH / REGEX / ENUM / UNIQUE / REFERENCE / CUSTOM_SQL)
  - 타입별 전용 위젯:
    - RANGE — `min` `max` 두 input + INTEGER/DECIMAL 토글
    - ENUM — 칩 입력 (Tab/Enter 로 값 추가)
    - REGEX — textarea + 실시간 테스트 input ("이 값으로 검증해보세요")
    - LENGTH — `최소 길이` `최대 길이`
    - NOT_NULL — 파라미터 없음
    - CUSTOM_SQL — SQL 작성 (위반 행 SELECT 쿼리, validation 헬퍼)
  - 심각도 (ERROR / WARN / INFO)
  - 사용 여부
- [카탈로그에서 가져오기] — 다이얼로그 (5-2 참조)

## 6. 부하 안정성

### 6-1. 절대 원칙
- **운영 DB 락 금지** — `LOCK TABLE`, `SELECT FOR UPDATE`, `WITH (NOLOCK)` 같은 힌트 일체 없음
- 단순 SELECT 만 사용

### 6-2. application-level 동시 실행 방지

**TB_QUAL_RUNNING_LOCK** 사용:
```java
// 진단 시작 전
int lockResult = sqlSession.insert("qualLock.acquire", lockVo);
// "qualLock.acquire" 매퍼:
//   INSERT INTO TB_QUAL_RUNNING_LOCK (...) VALUES (...) ON CONFLICT DO NOTHING

if (lockResult == 0) {
  // 이미 다른 진단이 점유 중 — SKIP
  return ResponseUtil.skip("동시 진단 중인 컬럼");
}
try {
  // 실제 진단 실행
} finally {
  sqlSession.delete("qualLock.release", lockVo);
}
```

**stale lock 정리**:
- q-executor 시작 시 `DELETE FROM TB_QUAL_RUNNING_LOCK WHERE START_DT < NOW() - INTERVAL '30 minutes'`
- 5분마다 cron 으로 동일 정리

### 6-3. 쿼리 보호

**`setQueryTimeout`**:
```java
PreparedStatement ps = conn.prepareStatement(sql);
ps.setQueryTimeout(60);  // 60초 default, 모델별 override 가능
```

**READ ONLY transaction**:
```java
conn.setReadOnly(true);
// 또는 dialect 별:
//   Postgres: SET TRANSACTION READ ONLY
//   Oracle: SET TRANSACTION READ ONLY
//   MySQL: SET TRANSACTION READ ONLY (SET 형식 차이)
```
RuleSqlBuilder 에 dialect 분기 추가.

### 6-4. 글로벌 동시 N건 제한

**Java semaphore** (q-executor 단일 인스턴스 가정):
```java
@Service
public class QualDiagThrottle {
  private final Semaphore globalSlot = new Semaphore(5);  // 동시 5개

  public <T> T runWithSlot(Callable<T> task) throws Exception {
    if (!globalSlot.tryAcquire(1, TimeUnit.SECONDS)) {
      throw new TooBusyException("글로벌 동시 진단 수 초과");
    }
    try { return task.call(); } finally { globalSlot.release(); }
  }
}
```

향후 q-executor 분산 환경 시 → DB 기반 semaphore 로 전환.

### 6-5. 분할/샘플링 — 보류

## 8. 단계별 진행 계획 (기능 단위 vertical slice)

각 step 은 DDL · VO · 매퍼 · Controller · Vue · (필요 시) executor 까지 동시 작업. DDL 변경은 step 별로 발생하면 그 step 안에서 같이 갱신 (DDL_full_schema.sql + DDL_변경이력.md 한 줄).

| Step | 기능 범위 | 산출물 |
|---|---|---|
| **1** | 부하 안정성 인프라 (TB_QUAL_RUNNING_LOCK + Throttle semaphore + setQueryTimeout + READ ONLY tx) | q-executor + 매퍼 / 단위 검증 |
| **2** | 카탈로그 시스템 기본 시드 + 사용자 정의 등록 (TB_QUAL_RULE_CATALOG 컬럼 추가 + 시드 SQL 40+건 + 카탈로그 다이얼로그) | DDL 갱신 + 카탈로그 화면 동작 |
| **3** | 도메인 룰 관리 (DSQualDomainRule.vue 신규 + 트리 + 룰 타입별 위젯 + [복사]) | 화면 진입 → 룰 추가/수정/삭제 풀 흐름 |
| **4** | 검증 대상 (DSQualColRule 재작성 + effective rule + 단위 재진단) | 화면 + 백엔드 통합 |
| **5** | 진단 실행 (DSQualValueProfile 재작성 + 도메인 분류 필터 + STOMP 진행률 + Lock 통합) | 진단 풀 흐름 |
| **6** | 진단 결과 + 분류 단위 집계 (DSQualRuleResult 재작성 + 4 탭) | 결과 조회 |
| **7** | 시계열 추이 (DSQualStats 재작성 + Chart.js) | 차트 |
| **8** | 셀레니움 (test_qual_domain_rule / test_qual_run / test_qual_result) + 매뉴얼 v2.2 | 회귀 통과 |

각 step 끝에 빌드 + 수동 시연 + 셀레니움 (해당 영역) 검증. 모든 step 끝나면 풀 회귀.
