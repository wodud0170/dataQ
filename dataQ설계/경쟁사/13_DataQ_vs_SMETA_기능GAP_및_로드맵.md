## 2. GAP 요약 — 경쟁에서 지는 부분

### Critical GAP (입찰 탈락 사유)

| # | 기능 | 심각도 | 이유 |
|---|------|:------:|------|
| 1 | **엔터티 등록/관리 (논리모델 설계)** | 높음 | SMETA 핵심 기능. 이것 없으면 "메타관리 솔루션"이라 부르기 어려움 |
| 2 | **논리→물리 자동 변환** | 높음 | 표준사전 기반 물리명+타입 자동생성. 1번과 세트 |
| 3 | **DDL 자동 생성** | 높음 | 모델→DDL→DBMS 배포 흐름의 핵심 |
| 4 | **ERwin 연동 (미완성)** | 높음 | 구현했으나 미완성으로 숨김 상태. 모델링 도구 연계는 RFP 필수 |

### Important GAP (기능 경쟁력)

| # | 기능 | 심각도 | 이유 |
|---|------|:------:|------|
| 5 | **주제영역 관리** | 중간 | 엔터티의 상위 분류. 1번 구현 시 함께 필요 |
| 6 | **다단계 결재** | 중간 | 공공기관은 결재선(담당→팀장→관리자) 요구 빈번 |
| 7 | **테이블/인덱스 등록 (결재 기반)** | 중간 | 수집 외에 웹에서 직접 등록+결재 |
| 8 | **데이터타입 관리 (논리/물리 매핑)** | 중간 | 논리→물리 변환의 기반 데이터 |
| 9 | **월별 요청 건수 통계** | 낮음 | 대시보드 보강 |
| 10 | **행정표준용어 참조** | 낮음 | 공공 프로젝트에서 가산점 |

## 3. 개발 우선순위 제안

### 원칙

1. **SMETA와 기능 동등** 이상이어야 입찰에 참여할 수 있다
2. 이미 가진 **자동 추천 엔진**을 최대한 재활용하여 SMETA 대비 차별화
3. 이미 구현한 것(ERwin 연동)은 **재설계해서 살린다**

### Phase 1: 입찰 참여 가능 수준 (최우선)

| # | 기능 | 난이도 | 근거 |
|---|------|:------:|------|
| 1 | **ERwin 연동 재설계 + 메뉴 복구** | 중 | 90% 구현된 상태. 논리/물리 구분 저장 보완 후 활성화 |
| 2 | **주제영역 관리** | 낮 | 엔터티의 상위 분류. 단순 CRUD |
| 3 | **엔터티/속성 등록 (논리모델 설계)** | 고 | 주제영역→엔터티→속성 계층. 결재 연동 |
| 4 | **표준 기반 물리명 자동 생성** | 중 | 기존 자동표준화 추천 엔진 재활용 |
| 5 | **데이터타입 관리 (논리/물리 매핑)** | 중 | DBMS별 타입 매핑 테이블 관리 화면 |
| 6 | **표준 기반 물리 데이터타입 자동 결정** | 중 | 도메인→DBMS별 물리타입 매핑 |

### Phase 2: 경쟁력 확보

| # | 기능 | 난이도 | 근거 |
|---|------|:------:|------|
| 7 | **DDL 자동 생성** | 중 | CREATE TABLE/INDEX DDL 생성 |
| 8 | **다단계 결재** | 중 | 공공기관 결재선 요구 대응 |
| 9 | **테이블/인덱스 등록 (결재 기반)** | 중 | 수집 외 직접 등록 |
| 10 | **월별 통계 차트** | 낮 | 대시보드 보강 |

| 12 | **멀티시스템 지원** | 고 | 시스템별 표준 분리 관리 |

## 4. 핵심 차별화 전략

SMETA와 기능 동등을 달성한 후, **SMETA에 없는 DataQ만의 강점**으로 승부:

```
SMETA의 논리→물리 변환:
  사용자가 속성 등록 → 표준사전에서 수동으로 용어 선택 → 물리명 매핑

DataQ의 논리→물리 변환:
  사용자가 속성 논리명 입력 → 자동 형태소 분리 → 표준단어 매칭 → 
  물리명 자동 추천 (1순위/2순위) → 도메인 자동 추천 → 클릭 한 번으로 확정
```

**"표준을 모르는 사람도 논리모델을 설계하면 자동으로 표준 준수 물리모델이 나온다"**

이것이 BMT/PoC에서 시연할 수 있는 가장 강력한 차별점이다.
