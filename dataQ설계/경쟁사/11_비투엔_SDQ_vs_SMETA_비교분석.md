# 비투엔 SDQ vs SMETA 비교 분석

**작성일:** 2026-04-17  
**목적:** 비투엔소프트의 두 핵심 솔루션(SDQ, SMETA)의 관계와 기능 범위를 정확히 파악하고, DataQ의 포지셔닝에 반영

---

## 1. 제품 정의

### SMETA (에스메타) — 메타데이터 관리 솔루션

| 항목 | 내용 |
|------|------|
| 정식명 | SMETA (Smart Metadata) |
| 포지셔닝 | 전사 메타데이터 표준 관리 + 데이터 구조 관리 |
| GS인증 | 1등급 |
| 시장점유율 | 조달청 메타관리 부문 67% (2023) |
| 주요 고객 | 환경부, 한국전력공사, 우체국 차세대 등 |

**핵심 기능:**
- 표준사전 관리 (단어/용어/도메인/코드, 승인 워크플로우)
- 데이터베이스 관리 (테이블/인덱스 등록/조회)
- 데이터모델 관리 (주제영역, 엔터티, 논리→물리 자동생성)
- 결재 프로세스 (다단계 결재, 반려, 재요청)
- 표준화지원도구 (스키마 수집, 단어/용어/테이블 일괄등록)
- 영향도 분석 (도메인/단어/용어 변경 시 연관 객체 조회)
- 통계/대시보드 (표준 준수율, DBMS vs 메타 일치율)
- 기타 (통합검색, 게시판, Eclipse 플러그인, 엑셀 연동)

### SDQ (에스디큐) — 데이터 품질 관리 솔루션

| 항목 | 내용 |
|------|------|
| 정식명 | SDQ (Smart Data Quality) |
| 포지셔닝 | 데이터 품질 진단 + 경량 표준관리 통합 솔루션 |
| 활용 이력 | 공공데이터 품질관리 수준평가 공식 진단도구 (5년 연속) |
| 주요 고객 | 행정안전부, 각 지자체/공공기관 데이터 품질 진단 |

**핵심 기능 (9개 모듈):**
1. 메인 대시보드 — 품질 모니터링 시각화
2. 진단 대상 관리 — DB/테이블 설정
3. 대상 프로파일링 — 통계 데이터 수집 (분포, NULL, 속성 분석)
4. 진단 룰 설정 — 도메인 룰, 데이터 룰, 업무규칙 룰
5. 진단 스케줄러 — 주기적 자동 실행
6. 품질 진단 실행 — 수동/자동 진단
7. 진단 결과/리포트 — 엑셀 다운로드, 주제영역별/테이블별 결과
8. **표준 메타 관리** — 단어, 용어, 도메인 표준사전 (승인 워크플로우 포함)
9. 시스템 권한 관리

## 2. 핵심 질문: "SMETA에 값진단을 추가한 것이 SDQ인가?"

### 결론: **아니다. 정확하지 않은 이해다.**

SDQ와 SMETA는 **별도 독립 솔루션**이며, 서로의 확장판이 아니다.

비투엔 공식 블로그(blog.b2en.com/241)에서의 설명:
> "SDQ는 'DQ' 기능과 'META' 기능의 통합으로 데이터 값 진단 이외에 데이터 표준, 데이터 구조 영역의 진단을 수행할 수 있다"

이 말의 정확한 의미:
- SDQ는 **품질 진단을 위해 필요한 수준의 META 기능을 자체 내장**하고 있다
- 하지만 SMETA의 **전체 기능을 포함하는 것은 아니다**

### 정확한 관계도

```
┌─────────────────────────────────────────────────────┐
│                     SMETA (본격 META)                 │
│                                                      │
│  ┌──────────────┐  ┌──────────────┐  ┌────────────┐ │
│  │ 표준사전 관리  │  │ 데이터모델 관리│  │ 영향도 분석 │ │
│  │ (단어/용어/   │  │ (주제영역,    │  │            │ │
│  │  도메인/코드)  │  │  엔터티, 속성) │  │            │ │
│  └──────────────┘  └──────────────┘  └────────────┘ │
│  ┌──────────────┐  ┌──────────────┐  ┌────────────┐ │
│  │ DB 구조 관리   │  │ DDL 자동생성  │  │ ERwin 연동  │ │
│  └──────────────┘  └──────────────┘  └────────────┘ │
│  ┌──────────────┐  ┌──────────────┐                  │
│  │ 다단계 결재    │  │ Eclipse 플러그인│                 │
│  └──────────────┘  └──────────────┘                  │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│                      SDQ (DQ + 경량 META)             │
│                                                      │
│  ┌──────────────┐  ← SMETA와 겹치는 부분 (경량 버전)   │
│  │ 표준 메타 관리 │                                    │
│  │ (단어/용어/   │                                    │
│  │  도메인, 승인) │                                    │
│  └──────────────┘                                    │
│                                                      │
│  ┌──────────────┐  ┌──────────────┐  ┌────────────┐ │
│  │  값진단       │  │  표준진단      │  │ 구조진단    │ │
│  │ (도메인룰,    │  │ (용어준수,    │  │ (미사용객체, │ │
│  │  데이터룰,    │  │  도메인준수)   │  │  PK미정의,  │ │
│  │  업무규칙)    │  │              │  │  중복테이블) │ │
│  └──────────────┘  └──────────────┘  └────────────┘ │
│  ┌──────────────┐  ┌──────────────┐                  │
│  │ 프로파일링     │  │ 진단 스케줄러  │                  │
│  └──────────────┘  └──────────────┘                  │
└─────────────────────────────────────────────────────┘
```

## 3. 기능별 상세 비교

| 기능 영역                   |   SDQ   |    SMETA    | 비고                   |
| ----------------------- | :-----: | :---------: | -------------------- |
| **표준사전 관리**             |         |             |                      |
| 단어/용어/도메인 CRUD          |    O    |      O      | SDQ는 진단에 필요한 수준      |
| 코드 관리                   |    O    |      O      |                      |
| 승인 워크플로우                |    O    |      O      | SMETA가 다단계 결재 등 더 정교 |
| 금칙어/유사어 관리              |    ?    |      O      |                      |
| 행정용어사전 연계               |    ?    |      O      |                      |
| 이력정보 (변경이력 비교)          |    ?    |      O      |                      |
| **데이터 모델 관리**           |         |             |                      |
| 주제영역/엔터티/속성 관리          |    X    |    **O**    | SMETA 고유             |
| 논리→물리 모델 자동생성           |    X    |    **O**    | SMETA 고유             |
| DDL/오브젝트 자동생성           |    X    |    **O**    | SMETA 고유             |
| **DB 구조 관리**            |         |             |                      |
| 스키마 수집 (카탈로그)           | O (진단용) | **O** (관리용) | 목적이 다름               |
| DBMS vs 모델 GAP 분석       |    X    |    **O**    | SMETA 고유             |
| 테이블/인덱스 등록 (결재)         |    X    |    **O**    | SMETA 고유             |
| **영향도 분석**              |    X    |    **O**    | SMETA 고유             |
| **ERwin 연동**            |    X    |    **O**    | SMETA 고유             |
| **Eclipse 플러그인**        |    X    |    **O**    | SMETA 고유             |
| **품질 진단**               |         |             |                      |
| 값진단 (도메인룰)              |  **O**  |      X      | SDQ 고유               |
| 값진단 (데이터룰: 참조무결성, 중복)   |  **O**  |      X      | SDQ 고유               |
| 값진단 (업무규칙: 사용자 SQL)     |  **O**  |      X      | SDQ 고유               |
| 표준진단 (용어/도메인 준수)        |  **O**  |      X      | SDQ 고유               |
| 구조진단 (미사용객체, PK미정의 등)   |  **O**  |      X      | SDQ 고유               |
| 프로파일링 (분포, NULL, 통계)    |  **O**  |      X      | SDQ 고유               |
| 진단 스케줄러 (주기적 자동실행)      |  **O**  |      X      | SDQ 고유               |
| 진단 결과 리포트               |  **O**  |      X      | SDQ 고유               |
| **행안부 16개 범정부 품질진단 규칙** |  **O**  |      X      | SDQ 고유               |

### SDQ의 3가지 진단 유형 상세

#### 값진단 (Value Diagnosis)
실제 데이터 값을 검사:
- **도메인 룰**: Boolean, Range, Date, Format(정규식) 검증
- **데이터 룰**: 참조무결성, 필수값(NOT NULL), 중복값 검사
- **업무규칙**: 사용자가 직접 SQL로 정의한 커스텀 진단 규칙
- 행안부 16개 범정부 품질진단 규칙 내장

#### 표준진단 (Standards Diagnosis)
메타정보 기반으로 표준 준수 여부 검사:
- 용어 존재 여부 (표준사전에 등록된 용어인지)
- 도메인 준수 (데이터타입/길이가 표준 도메인과 일치하는지)
- 정의 일치 (컬럼 한글명이 표준용어 한글명과 일치하는지)
- SDQ 기본 검증 룰로 수행 (별도 사용자 설정 불필요)

#### 구조진단 (Structure Diagnosis)
데이터 구조의 무결성과 관리 수준 검사:
- 미사용 컬럼/테이블
- 미정의 PK
- 중복 테이블
- 구조 표준화 수준
- 변경 관리 수준
- 8개 카테고리

## 4. 비투엔의 제품 전략 해석

비투엔은 **용도별 분리 판매** 전략을 취하고 있다:

```
비투엔 데이터 솔루션 라인업:
├── SMETA     → 메타데이터 거버넌스가 주 목적인 고객
├── SDQ       → 데이터 품질 진단이 주 목적인 고객 (공공 품질평가 등)
├── SFLOW     → 데이터 통합/ETL
└── BizMeta   → 비즈니스 메타데이터
```

**고객 관점에서의 선택 기준:**

| 고객 니즈 | 추천 제품 |
|-----------|----------|
| "전사 데이터 표준을 잡고, 모델을 관리하고 싶다" | **SMETA** |
| "공공데이터 품질평가를 받아야 한다" | **SDQ** |
| "표준도 관리하고 품질 진단도 해야 한다" | **SMETA + SDQ** (둘 다 구매) |
| "표준 관리는 기본만, 품질 진단이 핵심이다" | **SDQ** (내장 META로 충분) |

## 5. DataQ와의 비교 — 우리는 어디에 위치하는가?

### DataQ의 현재 기능 커버리지

```
DataQ 현재 기능 범위:
├── 표준사전 관리 (단어/용어/도메인/코드)     ← SMETA 영역
├── 승인 워크플로우                          ← SMETA 영역
├── 데이터모델 수집/관리                     ← SMETA 영역
├── ERwin XML 임포트                        ← SMETA 영역
├── 영향도 분석                             ← SMETA 영역
├── 변경 이력 추적                          ← SMETA 영역
├── 표준화 진단 (용어/도메인 준수)             ← SDQ의 "표준진단"
├── 구조 변경 진단 (스냅샷 vs 실제 DBMS)      ← SDQ의 "구조진단" 유사
└── (없음) 값진단                           ← SDQ에만 있음
```

### 매핑 정리

| DataQ 기능 | 비투엔 대응 |
|-----------|-----------|
| TB_WORD, TB_TERMS, TB_DOMAIN | SMETA 표준사전 / SDQ 표준메타관리 |
| TB_APRV_STATS (승인 프로세스) | SMETA 결재 / SDQ 승인 워크플로우 |
| TB_DATA_MODEL, _OBJ, _ATTR | SMETA 데이터모델관리 |
| ERwin XML 임포트 | SMETA ERwin 연동 |
| 영향도 분석 | SMETA 영향도 분석 |
| TB_DIAG_JOB, TB_DIAG_RESULT | SDQ 표준진단 |
| TB_STRUCT_DIAG_* | SDQ 구조진단 (유사) |
| **(없음)** | **SDQ 값진단 (도메인룰/데이터룰/업무규칙)** |
| **(없음)** | **SDQ 프로파일링** |
| **(없음)** | **SDQ 진단 스케줄러** |

### 결론: DataQ ≒ SMETA(핵심) + SDQ(표준진단+구조진단)

DataQ는 현재:
- **SMETA의 핵심 기능**(표준사전, 모델관리, 승인, 영향도)을 대부분 갖추고 있고
- **SDQ의 표준진단과 구조진단**을 갖추고 있지만
- **SDQ의 값진단(도메인룰/데이터룰/업무규칙), 프로파일링, 진단 스케줄러**는 없다

### DataQ가 SDQ 수준의 완전한 DQ 기능을 갖추려면 추가 필요한 것

| 기능 | 설명 | 난이도 |
|------|------|--------|
| **값진단 - 도메인 룰** | Boolean, Range, Date, Format(정규식) 검증 | 중 |
| **값진단 - 데이터 룰** | 참조무결성, 필수값(NOT NULL), 중복값 검사 | 중 |
| **값진단 - 업무규칙** | 사용자 SQL 기반 커스텀 진단 | 중~고 |
| **프로파일링** | 컬럼별 분포, NULL 비율, 최대/최소/평균 등 통계 | 중 |
| **진단 스케줄러** | 주기적 자동 진단 실행 (cron 기반) | 중 |
| **진단 리포트** | 주제영역별/테이블별 품질 점수, 엑셀 리포트 | 낮~중 |
| **범정부 16개 규칙** | 행안부 공공데이터 품질진단 표준 규칙 | 중 |

## 6. 전략적 시사점

### 6.1 포지셔닝 관점

현재 DataQ는 **"SMETA 경쟁 + 표준/구조 진단"** 포지셔닝이다.

만약 값진단까지 추가하면 → **"SMETA + SDQ 통합"** 포지셔닝이 가능해진다.

비투엔 고객이 SMETA와 SDQ를 **별도 구매**해야 하는 것을, DataQ는 **하나의 솔루션**으로 제공할 수 있다는 차별점.

### 6.2 공공 입찰 관점

공공데이터 품질관리 수준평가에서는 **값진단**이 필수:
- 행안부 16개 범정부 품질진단 규칙 준수 여부 평가
- 도메인 룰, 업무규칙 진단 결과가 평가 항목에 포함
- SDQ가 5년간 공식 도구로 사용된 이유

값진단 없이는 **품질관리 수준평가 대응이 불가능**하므로, 이 기능은 공공 시장 진입의 필수 요건.

### 6.3 우선순위 제안

```
현재 상태:  DataQ = SMETA(핵심) + SDQ(표준진단+구조진단)
목표 상태:  DataQ = SMETA(핵심) + SDQ(전체) = 올인원 솔루션

추가 개발 우선순위:
1순위: 값진단 - 도메인 룰 (Range, Format 등 기본 규칙)
2순위: 값진단 - 데이터 룰 (NOT NULL, 참조무결성, 중복)
3순위: 프로파일링 (컬럼 통계 수집)
4순위: 진단 스케줄러
5순위: 값진단 - 업무규칙 (사용자 SQL)
6순위: 범정부 16개 규칙 내장
```
