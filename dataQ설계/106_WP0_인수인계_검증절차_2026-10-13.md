## 4. 결정 사항

### 4.1 계획 범위 안

- swagger 는 로그인해야 열린다.
- q-executor 는 127.0.0.1 에만 바인딩(`server.address`). 토큰 방식보다 단순해서 택했고 `SERVER_ADDRESS` 로 바꿀 수 있다.
- 401 은 `/api/**` 에만 JSON 으로 주고, 화면 경로는 지금처럼 리다이렉트. 프런트는 axios 인터셉터가 처리.
- 비밀번호
  - 사용자 상세 응답에서 뺀다.
  - `updateUser` 로 비밀번호를 바꾸는 것은 관리자만. 일반 사용자는 기존 비밀번호 변경 API 로만 바꾸고, 그 API 는 세션 사용자 것만 바꾼다.
  - 데이터 소스는 응답에서 빼고, 빈 값은 기존 유지, 테스트는 서버·포트·사용자가 저장값과 같을 때만 저장 비밀번호를 쓴다.
- 새 변경 유형 ADD_PK·DEL_PK·ADD_FK·DEL_FK (TIER1)
  - 신청 때 모델에 대기 상태로 반영한다. 추가는 DRAFT 행, 삭제는 `USE_YN='N'` 으로 감춘다.
  - 승인하면 확정, 반려하면 변경 전 값(BEFORE_JSON)으로 되돌린다.
  - PK 삭제가 대기 중인 테이블에는 새 PK 를 받지 않는다.
- 엑셀 업로드 사전은 q-executor 주소의 쿼리로 넘긴다. 공용 jar 의 전송 함수가 파일만 싣기 때문이다.
- 진단 결과 등록 사전은 진단 Job 의 사전(`TB_DIAG_JOB.DICT_ID`). 그 진단의 이슈가 이 사전 기준이라 같은 사전에 넣어야 재진단에서 해소된다.

### 4.2 계획에 없던 것 — 유지할지 판단 필요

| 추가한 것 | 영향 |
|---|---|
| 사용자 목록은 관리자만, 사용자 상세는 본인 또는 관리자만 | 일반 사용자가 다른 사용자 정보를 볼 수 없다 |
| 데이터 소스 관리(등록·수정·삭제·테스트)는 관리자만 | 메뉴도 관리자 전용이라 화면 영향은 없을 것으로 봄 |
| 비밀번호 변경은 세션 사용자 기준 | 쿼리의 사용자 ID 를 무시한다 |
| Vue 개발 서버(8080) 프록시 | 개발 환경 전용 |

## 6. 다음 세션 검증 절차

### 6.1 준비

1. 루트에서 `mvn package -DskipTests -T 1C`.
2. 서버는 **이 저장소의 `target` jar** 로 띄운다. `build.bat` 는 PC2 에서 `ndata-quality-master/...` 의 옛 jar 를 띄우므로 쓰지 않는다.
   - `q-center/target` 에서 `ND_HOME=<저장소 루트> java -jar q-center-0.0.1-SNAPSHOT.jar`
   - `q-executor/target` 에서 `ND_HOME=<저장소 루트> java -jar q-executor.jar`
3. 셀레니움까지 하려면 Edge 155 에 맞는 msedgedriver 를 받는다(다운로드는 사용자 허락). `run_all.py` 정리 단계와 테스트 25개 파일이 `docker exec dataq-db psql` 로 DB 를 보는데, PC2 에는 `dataq-db` 컨테이너가 없고 개발 DB 는 네이티브 PostgreSQL(25433)이다. PC2 에서는 네이티브 psql 로 부르게 고친 뒤 돌린다. PC2 의 Oracle 수집 시험은 `oracle-19c`(localhost:11521) 컨테이너를 쓴다(107번 환경, PC1 은 108번).
4. 시험 계정: 내장 관리자 `space`, 일반 사용자 `jyjang`. 비밀번호는 Base64 로 보낸다(로그인 화면과 같은 방식). 비밀번호 값은 이 문서에 적지 않는다.

## 7. 알려진 위험·남은 과제

| 내용 | 비고 |
|---|---|
| 세션이 끊긴 상태에서는 모든 화면의 API 호출이 401 을 받는다. 인터셉터가 한 번 안내하고 `/signin` 으로 보내며 그 요청은 끝나지 않은 채로 둔다 | 최종본 브라우저 확인 필요(§6.3-1) |
