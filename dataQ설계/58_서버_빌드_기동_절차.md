## 2. 빌드 — **반드시 루트에서 reactor 빌드**

**절대 금지: 모듈별 순차 `cd q-common && mvn install` → `cd q-center && mvn package` 방식.**
이 방식은 q-center 가 q-common 을 m2 설치본으로 참조하는데,
q-common pom 의 `systemPath=${project.basedir}/../lib/common-0.0.1-SNAPSHOT.jar` 가 Maven 3.9+ 에서
invalid 로 판정되어 **q-common 의 transitive 의존성(korean-text, scala-library, twitter-text) 이 fat jar 에서 통째로 누락**.
→ 런타임에 `/api/std/analyzeTermsBatch` 호출 시 `NoClassDefFoundError: com/twitter/penguin/korean/TwitterKoreanProcessorJava` 500 에러.

루트 reactor 빌드는 q-center 가 q-common 을 **sibling(같은 빌드 세션의 source pom)** 으로 참조하므로
invalid POM 체크 자체를 건너뛴다. 초기 커밋부터 있는 `build.bat` 이 이 방식이다. 따라 간다.

```bash
export JAVA_HOME="/c/Program Files/Java/jdk1.8.0_202"
export PATH="$JAVA_HOME/bin:$PATH"

cd "/c/Users/장재영/Desktop/dataQ"
mvn clean package -DskipTests        # 3개 모듈 전부 한 번에, 약 2~3분
```

`-q`(quiet) 옵션 쓰지 말 것. `spring-boot:repackage` 가 조용히 스킵되어 Main-Class 없는 plain jar 로 나옴 → `java -jar` 실행 시 "기본 Manifest 속성이 없습니다". `-DskipTests` 만 붙일 것.

빌드 성공 시 생성되는 fat jar:
- `q-center/target/q-center-0.0.1-SNAPSHOT.jar` (약 200MB, `BOOT-INF/lib/korean-text-4.4.jar` 포함 필수)
- `q-executor/target/q-executor.jar` (약 185MB, korean-text 포함 필수)

**검증**: 분석/표준화 추천 기능이 있는 기능을 건드렸다면 빌드 직후 반드시 확인:
```bash
unzip -l q-center/target/q-center-0.0.1-SNAPSHOT.jar | grep korean-text
# BOOT-INF/lib/korean-text-4.4.jar 가 나와야 정상. 안 나오면 reactor 아님.
```

**프론트만 수정한 경우**: `q-center/vue/front` 에서 `npm run build` 한 번만 돌리면 됨. 백엔드 재빌드 불필요.

## 3. 서버 기동

### 3-1. 실행 중인 프로세스 확인 및 종료

```bash
netstat -ano | findstr :28091   # q-center PID 조회
netstat -ano | findstr :28098   # q-executor PID 조회

taskkill //F //PID {q-center-PID}
taskkill //F //PID {q-executor-PID}
```

### 3-2. 백그라운드 기동 (PowerShell `Start-Process` + `-WorkingDirectory` + 상대경로)

**핵심**: PowerShell 의 `-ArgumentList` 에 한글 절대경로를 주면 java.exe 에 전달되는 과정에서
인코딩이 깨져 "jar 파일 접근 오류" 가 뜬다. `-WorkingDirectory` 로 프로젝트 폴더를 지정하고
`-ArgumentList` 에는 **상대경로** `target\q-center-0.0.1-SNAPSHOT.jar` 만 넘길 것.

```powershell
$env:JAVA_HOME = "C:\Program Files\Java\jdk1.8.0_202"
$centerDir = "C:\Users\장재영\Desktop\dataQ\q-center"
$execDir   = "C:\Users\장재영\Desktop\dataQ\q-executor"

Start-Process -FilePath "$env:JAVA_HOME\bin\java.exe" `
  -ArgumentList @("-jar", "target\q-center-0.0.1-SNAPSHOT.jar") `
  -WorkingDirectory $centerDir `
  -RedirectStandardOutput "$centerDir\..\q-center.log" `
  -RedirectStandardError  "$centerDir\..\q-center.err.log" `
  -WindowStyle Hidden -PassThru

Start-Process -FilePath "$env:JAVA_HOME\bin\java.exe" `
  -ArgumentList @("-jar", "target\q-executor.jar") `
  -WorkingDirectory $execDir `
  -RedirectStandardOutput "$execDir\..\q-executor.log" `
  -RedirectStandardError  "$execDir\..\q-executor.err.log" `
  -WindowStyle Hidden -PassThru
```

bash 에서 `java -jar "/c/Users/장재영/..."` 도 같은 이유로 실패. PowerShell 도 절대경로 주면 실패.
→ **반드시 `-WorkingDirectory + 상대경로` 조합 사용**.

### 3-3. 기동 확인

```bash
curl -s -o /dev/null -w "%{http_code}" http://localhost:28091/login   # 200 이면 OK
curl -s -o /dev/null -w "%{http_code}" http://localhost:28098/        # 404 도 정상 (루트 미정의)
```

기동 소요 시간: q-center 약 30~60초, q-executor 약 15~30초.

## 5. 실패 케이스 및 회피

| 증상 | 원인 | 회피 |
|------|------|------|
| `java -jar` 가 "Manifest 속성 없음" | `mvn package -q` 로 빌드해서 repackage 안 됨 | `-q` 빼고 재빌드 |
| `java -jar` 가 "jar 접근 오류" (한글 깨짐) | bash 가 한글 경로 인코딩 못 함 | PowerShell `Start-Process` 사용 |
| `mvn spring-boot:run` 매번 npm 재설치 | frontend-maven-plugin 이 test-compile 단계에 npm 재실행 | 직접 `java -jar target/*.jar` 기동 |
| `mvn spring-boot:repackage` 가 "Source file must not be null" | 프로젝트별 직접 호출은 플러그인이 원본 jar 위치 못 찾음 | `mvn package` 안에서 자동 repackage 되게 맡길 것 |
| systemPath ERROR (Maven 3.9+) → jar 에 korean-text 누락 → 분석 API 500 | 모듈별 순차 빌드를 하면 q-common POM 이 invalid 로 찍혀 transitive 차단. **"무시 가능" 아님** | 2절대로 **루트 reactor** 빌드만 사용. `cd q-common && mvn install` 같은 방식 금지 |
| q-executor 기동 로그에 STOMP Connection refused | q-center 가 아직 안 올라옴 | q-center 먼저 기동되면 자동 연결됨 (무시 가능) |
