## 2. 빌드 순서 (q-common → q-center → q-executor)

**중요: `-q`(quiet) 옵션 쓰지 말 것**. `-q` 로 빌드하면 `spring-boot:repackage` 가 조용히 스킵되어
target jar 에 `Main-Class` 가 없는 plain jar 로 나와 `java -jar` 실행 시
"기본 Manifest 속성이 없습니다" 에러 발생. 반드시 `-DskipTests` 만 붙여 사용.

```bash
export JAVA_HOME="/c/Program Files/Java/jdk1.8.0_202"
export PATH="$JAVA_HOME/bin:$PATH"

# 1. q-common (공용 라이브러리) 먼저 install
cd "/c/Users/장재영/Desktop/dataQ/q-common" && mvn install -DskipTests

# 2. q-center (프론트 포함 - npm install + npm run build 자동 실행됨, 약 3~5분)
cd "/c/Users/장재영/Desktop/dataQ/q-center"  && mvn package -DskipTests

# 3. q-executor
cd "/c/Users/장재영/Desktop/dataQ/q-executor" && mvn package -DskipTests
```

빌드 성공 시 생성되는 fat jar:
- `q-center/target/q-center-0.0.1-SNAPSHOT.jar` (약 195MB)
- `q-executor/target/q-executor.jar`

**프론트만 수정한 경우**: `q-center/vue/front` 에서 `npm run build` 한 번만 돌리면 됨. 백엔드 재빌드 불필요.

## 3. 서버 기동

### 3-1. 실행 중인 프로세스 확인 및 종료

```bash
netstat -ano | findstr :28091   # q-center PID 조회
netstat -ano | findstr :28098   # q-executor PID 조회

taskkill //F //PID {q-center-PID}
taskkill //F //PID {q-executor-PID}
```

### 3-2. 백그라운드 기동 (PowerShell 사용 — 한글 경로 문제 회피)

```powershell
$env:JAVA_HOME = "C:\Program Files\Java\jdk1.8.0_202"

Start-Process -FilePath "$env:JAVA_HOME\bin\java.exe" `
  -ArgumentList @("-jar", "C:\Users\장재영\Desktop\dataQ\q-center\target\q-center-0.0.1-SNAPSHOT.jar") `
  -RedirectStandardOutput "C:\Users\장재영\Desktop\dataQ\q-center.log" `
  -RedirectStandardError  "C:\Users\장재영\Desktop\dataQ\q-center.err.log" `
  -WindowStyle Hidden -PassThru

Start-Process -FilePath "$env:JAVA_HOME\bin\java.exe" `
  -ArgumentList @("-jar", "C:\Users\장재영\Desktop\dataQ\q-executor\target\q-executor.jar") `
  -RedirectStandardOutput "C:\Users\장재영\Desktop\dataQ\q-executor.log" `
  -RedirectStandardError  "C:\Users\장재영\Desktop\dataQ\q-executor.err.log" `
  -WindowStyle Hidden -PassThru
```

bash 의 `java -jar "/c/Users/장재영/..."` 은 한글 경로 인코딩 문제로 "jar 파일 접근 오류" 가 남.
→ **반드시 PowerShell `Start-Process` 사용**.

### 3-3. 기동 확인

```bash
curl -s -o /dev/null -w "%{http_code}" http://localhost:28091/login   # 200 이면 OK
curl -s -o /dev/null -w "%{http_code}" http://localhost:28098/        # 404 도 정상 (루트 미정의)
```

기동 소요 시간: q-center 약 30~60초, q-executor 약 15~30초.

## 5. 실패 케이스 및 회피

| 증상 | 원인 | 회피 |
|------|------|------|
| `java -jar` 가 "Manifest 속성 없음" | `mvn package -q` 로 빌드해서 repackage 안 됨 | `-q` 빼고 재빌드 |
| `java -jar` 가 "jar 접근 오류" (한글 깨짐) | bash 가 한글 경로 인코딩 못 함 | PowerShell `Start-Process` 사용 |
| `mvn spring-boot:run` 매번 npm 재설치 | frontend-maven-plugin 이 test-compile 단계에 npm 재실행 | 직접 `java -jar target/*.jar` 기동 |
| `mvn spring-boot:repackage` 가 "Source file must not be null" | 프로젝트별 직접 호출은 플러그인이 원본 jar 위치 못 찾음 | `mvn package` 안에서 자동 repackage 되게 맡길 것 |
| systemPath ERROR (Maven 3.9+) | pom.xml 의 상대경로 systemPath 를 Maven 3.9+ 가 엄격 거부 | 에러 로그는 나지만 실제 빌드는 성공 (무시 가능) |
| q-executor 기동 로그에 STOMP Connection refused | q-center 가 아직 안 올라옴 | q-center 먼저 기동되면 자동 연결됨 (무시 가능) |
