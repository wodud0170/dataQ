# 승인 프로세스 재설계

**작성일**: 2026-04-15
**상태**: 설계

---

## 1. 현재 문제점

### 1.1 권한 관리
- TB_USER.ADM_YN(boolean)으로 관리자/일반 구분
- 사용자 관리 화면(MMUser.vue)이 탭 구조 (Tab1: 비번변경, Tab2: 사용자관리) — 관리자가 일반 사용자를 체계적으로 관리하기 어려움
- 사용자 상세 정보(권한, 등록일, 최근 활동) 확인 불가

### 1.2 승인 프로세스
- 승인 상태가 4단계 (0:요청 → 1:검토중 → 2:승인 → 3:반려) — 불필요하게 복잡
- "검토중" 상태의 실효성 없음 (누가 언제 검토 시작했는지 추적 안 됨)
- 일괄등록(엑셀) 시 관리자/일반 구분 없이 APRV_YN='Y' 하드코딩 (일반 사용자도 자동 승인)
- 용어 APRV_YN=NULL 버그 (registerTermsBatch에서 미설정)

### 1.3 이력 추적
- 관리자가 직접 등록한 건과 승인을 통해 등록된 건의 구분이 불가
- 변경 이력 화면에서 "누가" 등록했는지는 보이지만 "관리자 직접등록"인지 "승인 경유"인지 구분 안 됨

## 2. 재설계 방향

### 2.1 권한 체계 (단순화 유지)

| 구분 | 권한 | 등록 시 승인 | 비고 |
|------|------|------------|------|
| 관리자 | ADM_YN = true | **즉시 승인 (APRV_YN='Y')** | 모든 등록 행위에 적용 |
| 일반 사용자 | ADM_YN = false | **승인대기 (APRV_YN='N')** | 관리자 승인 후 반영 |

적용 대상: 단어, 용어, 도메인, 도메인그룹, 도메인분류, 코드, 코드데이터 — **모든 표준 데이터**

### 2.2 승인 상태 (4단계 → 2단계)

```
현재:  0(요청) → 1(검토중) → 2(승인) 또는 3(반려)
변경:  0(승인대기) → 2(승인) 또는 3(반려)
```

"검토중(1)" 상태 제거. 관리자가 승인 화면에서 바로 승인 또는 반려.

### 2.3 화면별 역할

| 화면 | 대상 | 기능 |
|------|------|------|
| **관리 > 사용자** (재설계) | 관리자 전용 | 사용자 목록 → 상세 (권한 조정, 계정 관리) |
| **관리 > 승인** (기존 개선) | 관리자 전용 | 승인대기 목록 → 승인/반려 처리 |
| **마이페이지 > 요청 현황** (기존) | 일반 사용자 | 본인 신청 목록 + 승인/반려 결과 확인 |
| **데이터 표준 사전 > 변경 이력** (기존 확장) | 전체 | 등록/수정/삭제 이력 + 관리자 직접등록 표시 |

## 4. 승인 프로세스 플로우

### 4.1 관리자 등록

```
관리자가 단어/용어/도메인 등록
    │
    ├─ APRV_YN = 'Y' (즉시 승인)
    ├─ TB_APRV_STATS 미생성 (승인 프로세스 불필요)
    └─ TB_CHANGE_HISTORY에 기록 (CHANGE_USER_ID = 관리자ID, 비고: '관리자 직접등록')
```

### 4.2 일반 사용자 등록

```
일반 사용자가 단어/용어/도메인 등록
    │
    ├─ APRV_YN = 'N' (승인대기)
    ├─ TB_APRV_STATS 생성 (APRV_STAT = 0, REQ_USER_ID = 사용자ID)
    └─ TB_CHANGE_HISTORY에 기록 (비고: '사용자 등록 (승인대기)')
    
관리자가 승인 화면에서 처리
    │
    ├─ 승인 (APRV_STAT = 2)
    │   ├─ APRV_YN = 'Y' 로 변경
    │   └─ TB_CHANGE_HISTORY에 기록 (비고: '관리자 승인')
    │
    └─ 반려 (APRV_STAT = 3)
        ├─ APRV_YN = 'N' 유지
        └─ TB_CHANGE_HISTORY에 기록 (비고: '관리자 반려: [사유]')
```

### 4.3 일괄등록 (엑셀)

```
관리자 일괄등록 → 전체 APRV_YN = 'Y'
일반 사용자 일괄등록 → 전체 APRV_YN = 'N', TB_APRV_STATS 일괄 생성
```

### 4.4 자동 표준화 추천 등록 (registerTermsBatch)

```
관리자 실행 → 등록된 단어/용어 전체 APRV_YN = 'Y'
일반 사용자 실행 → 전체 APRV_YN = 'N', TB_APRV_STATS 생성
```

## 5. 변경 이력 관리자 직접등록 표시

### 5.1 TB_CHANGE_HISTORY 확장

현재 SUMMARY 컬럼에 자유 텍스트로 기록 중. 관리자 직접등록 여부를 구분하기 위해:

**방안 A: SUMMARY에 키워드 포함**
- 관리자 등록: `"[관리자] 단어 등록: 사용자"`
- 일반 사용자 등록: `"단어 등록: 사용자 (승인대기)"`
- 승인 처리: `"[승인] 단어 승인: 사용자 (처리자: admin)"`

**방안 B: CHANGE_SOURCE 컬럼 추가**
```sql
ALTER TABLE TB_CHANGE_HISTORY ADD COLUMN IF NOT EXISTS CHANGE_SOURCE VARCHAR(20);
-- ADMIN_DIRECT: 관리자 직접등록
-- USER_REQUEST: 일반 사용자 등록 (승인대기)
-- ADMIN_APPROVE: 관리자 승인
-- ADMIN_REJECT: 관리자 반려
-- BULK_UPLOAD: 일괄등록
-- AUTO_RECOMMEND: 자동 표준화 추천
```

→ **방안 B 권장**: 필터링/통계에 활용 가능

### 5.2 변경 이력 화면 확장

```
현재 필터:  [대상: 단어/용어/도메인] [유형: 등록/수정/삭제]
추가 필터:  [등록 경로: 전체/관리자직접/사용자신청/일괄등록/자동추천]
```

## 6. 승인 화면 개선 (MMApproval.vue)

### 6.1 상태 필터 단순화

```
현재:  [승인대기] [검토중] [승인완료] [반려]
변경:  [승인대기] [승인완료] [반려]
```

"검토중" 탭 제거.

### 6.2 승인/반려 처리

| 기능 | 현재 | 변경 |
|------|------|------|
| 개별 승인 | 상세 패널에서 처리 | 동일 |
| 개별 반려 | 상세 패널에서 사유 입력 | 동일 |
| 일괄 승인 | 체크박스 선택 → 승인 | 동일 |
| 일괄 반려 | 체크박스 선택 → 반려 | 반려 사유 입력 다이얼로그 |

### 6.3 승인 시 연관 체크

- **용어 승인 시**: 구성 단어 중 미승인 단어 있으면 경고 (기존 유지)
- **단어 반려 시**: 해당 단어를 사용하는 미승인 용어 경고 (기존 유지)

## 7. APRV_YN 설정 통일 (수정 대상)

### 7.1 현재 문제점

| 경로 | 현재 동작 | 문제 |
|------|----------|------|
| 단건 등록 (단어/용어/도메인) | 관리자=Y, 일반=N | 정상 |
| 엑셀 일괄등록 | 무조건 Y | **일반 사용자도 자동 승인** |
| 자동표준화 registerTermsBatch | 용어 APRV_YN 미설정 (NULL) | **승인 목록 미노출** |
| 도메인그룹/분류 일괄등록 | 무조건 Y | **일반 사용자도 자동 승인** |

### 7.2 수정 방향

모든 등록 경로에서 동일 규칙 적용:

```java
String aprvYn = sessionService.isAdmin() ? "Y" : "N";
vo.setAprvYn(aprvYn);

// 일반 사용자면 TB_APRV_STATS도 생성
if ("N".equals(aprvYn)) {
    createApprovalRequest(vo);
}
```

### 7.3 수정 대상 파일

| 파일 | 수정 내용 |
|------|----------|
| ExcelUploadService.java | uploadWords/uploadTermsList/uploadDomains 등에서 관리자 여부 체크 |
| DataStandardController.java | registerTermsBatch에서 APRV_YN 설정 + TB_APRV_STATS 생성 |
| DataStandardController.java (q-executor) | uploadDomainGroups/uploadDomainClsfs에서 관리자 여부 체크 |
