## 수정된 버그 목록

### BUG-1: [CRITICAL] DiagController - READY 좀비 Job

**파일**: `q-center/src/main/java/qualitycenter/controller/DiagController.java`

**문제**: q-executor 호출 실패 시 (서버 다운, 네트워크 에러 등) Job이 READY 상태로 영구 잔류
- Job INSERT는 성공했지만 executor 요청이 실패 → DB에 READY 상태 좀비 레코드
- 이후 진단 이력에 READY 상태 Job이 계속 쌓임

**수정 내용**:
```java
// webClientHandler.postData()에 .onErrorResume() 추가
.onErrorResume(e -> {
    // executor 호출 실패 시 Job 상태를 ERROR로 변경
    StdDiagJobVo errorJob = new StdDiagJobVo();
    errorJob.setDiagJobId(jobVo.getDiagJobId());
    errorJob.setStatus("ERROR");
    sqlSessionTemplate.update("diag.updateDiagJobStatus", errorJob);
    result.setResultInfo(500, "진단 서버 연결 실패: " + e.getMessage());
    return Mono.just(result);
});
```

### BUG-2: [HIGH] DiagController - 동일 수집건 중복 Job 생성

**파일**: `q-center/src/main/java/qualitycenter/controller/DiagController.java`, `q-common/src/main/resources/mapper/stnd/diag.xml`

**문제**: 동일한 수집건(clctId)에 대해 READY/RUNNING 상태인 Job이 이미 있는데도 새 Job 생성 가능
- 사용자가 빠르게 여러 번 클릭하거나, 여러 브라우저 탭에서 동시 요청 시 발생
- 같은 데이터에 대해 병렬 진단 실행 → 결과 중복/불일치

**수정 내용**:
1. `diag.xml`에 `selectActiveDiagJobCount` 쿼리 추가:
```sql
SELECT COUNT(*) FROM TB_DIAG_JOB
WHERE DM_CLCT_ID = #{clctId}
AND STATUS IN ('READY', 'RUNNING')
```

2. `startDiag()` 시작 부분에 중복 체크:
```java
int activeCount = sqlSessionTemplate.selectOne("diag.selectActiveDiagJobCount", jobVo.getClctId());
if (activeCount > 0) {
    result.setResultInfo(409, "이미 진행 중인 진단이 있습니다.");
    return Mono.just(result);
}
```

### BUG-3: [HIGH] DSDataDiag.vue - 진단 시작 중복 클릭 무방비

**파일**: `q-center/vue/front/src/components/DSDataDiag.vue`

**문제**: "진단 시작" 버튼 클릭 후 API 응답 전까지 0.1~1초간 버튼이 활성 상태
- `isRunning`은 RUNNING 상태만 체크 → READY 상태에서는 버튼 활성
- API 응답 오기 전 재클릭 → 중복 Job 생성

**수정 내용**:
- `data`에 `starting: false` 플래그 추가
- 버튼에 `:disabled="... || starting"` + `:loading="starting"` 추가
- `startDiag()` 진입 시 `this.starting = true`, `.finally()` 에서 `false`로 복귀

### BUG-4: [HIGH] DSTermRecommend.vue - 분석/등록 중복 클릭 무방비

**파일**: `q-center/vue/front/src/components/DSTermRecommend.vue`

**문제**: "분석 시작" 버튼과 "용어 등록" 버튼 모두 API 호출 중 재클릭 가능
- 분석: 동일 입력으로 분석 API 2회 호출 → 불필요한 서버 부하
- 등록: 동일 데이터로 registerTermsBatch 2회 호출 → 용어/단어 중복 등록 위험

**수정 내용**:
- `data`에 `isAnalyzing: false`, `isRegistering: false` 플래그 추가
- 분석 버튼: `:disabled="... || isAnalyzing"` + `:loading="isAnalyzing"`
- 등록 버튼: `:disabled="... || isRegistering"` + `:loading="isRegistering"`
- 각 메서드 진입 시 플래그 `true`, `.finally()`에서 `false` 복귀

### BUG-5: [HIGH] DataStandardController - registerTermsBatch NPE 위험

**파일**: `q-center/src/main/java/qualitycenter/controller/DataStandardController.java`

**문제 1** (라인 1985): `lastWordId`가 null일 때 형식단어 검증을 건너뜀
- wordId도 null이고 newWordIndex에 해당하는 신규 단어 등록도 실패한 경우
- 형식단어 검증 없이 용어 등록 진행 → 표준 위반 데이터 생성

**문제 2** (라인 2025-2033): wordId가 null인 채로 selectWordInfoById 호출 시도
- 신규 단어 등록이 실패하여 `newWordIdMap.get()`이 null 반환
- null wordId로 DB 조회 → 예기치 않은 동작

**수정 내용**:
```java
// 문제 1: lastWordId null일 때 명시적 에러
if (lastWordId == null) {
    throw new RuntimeException("마지막 단어의 ID를 확인할 수 없습니다. 단어 등록 후 다시 시도해주세요.");
}

// 문제 2: 용어-단어 관계 등록 시 wordId null 체크
if (tw.getWordId() == null) {
    throw new RuntimeException("단어 ID를 확인할 수 없습니다. 단어 등록 후 다시 시도해주세요. (순서: " + tw.getWordOrd() + ")");
}
```
