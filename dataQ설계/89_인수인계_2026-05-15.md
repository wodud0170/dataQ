# 89. 인수인계 — 2026-05-15 세션 종료 시점

## 1. 직전까지 한 작업 — 88번 §16 한글 변환 이력

§16 (한글 변환 이력 — 매핑 정의서 작성용) 의 **코드 작업은 완료, 실 UI 검수 미실시** 상태로 세션 종료. 마지막 커밋 `a0fa244` 까지 적용됨.

### 완료 항목 (커밋 적용됨)
- DDL: `TB_TERM_RESOLVE_HISTORY` 테이블 + 컬럼 (DDL_full_schema.sql 반영)
- 컨트롤러: `TermResolveHistoryController` (list / excel)
- 매퍼: `termResolve.xml` (insert / selectList — TB_TERMS / TB_DOMAIN JOIN 으로 현재 dataType/dataLen 노출)
- 후크: `DataStandardController.registerTermsBatch` 성공 분기에 `recordResolveHistory(...)` 추가
- 화면: `DSTermResolveHistory.vue` — 검색 패널 (2줄), 한글명 변경 chip, 엑셀 다운로드 버튼
- DSTermRecommend.vue: `_originalInput` 보존 + 입력/등록 한글 분리 컬럼 표시

### 디자인 결정 (기록)
- **데이터타입/길이는 snapshot 안 함** — INSERT 단순화, SELECT 때 `TB_TERMS → TB_DOMAIN` JOIN 으로 현재값 노출
  - 이유: snapshot 저장 시 도메인 변경 후 이력 값이 stale 됨. 매핑 정의서는 "현재 상태" 가 필요
- **OGNL String 비교**: `<if test='"Y".equals(nmChangedYn)'>` 형식 사용 (`'Y'.equals(...)` 는 char 라 실패)
- **CSS scoped 재정의 필수**: `.splitTopWrapper`, `.tableSpt` 는 DSWord 의 scoped style → 다른 컴포넌트에서 재선언 필요

### B. §16 변환 이력 화면 실 검수 — **PASS 판정 전까지 끝난 게 아님**
- [ ] 서버 기동 후 화면 접속 → 검색 패널 레이아웃 (글씨 짤림/줄바꿈 없음) 확인
- [ ] 표준화 추천 → 등록 액션 후 변환 이력에 row 실제로 생기는지 확인 (registerTermsBatch hook)
- [ ] 데이터타입/길이 컬럼이 TB_DOMAIN 의 현재값으로 나오는지 (JOIN 정상 동작)
- [ ] 한글명 변경 / 유지 chip 분류 정확한지 (`isChanged()` 로직)
- [ ] 엑셀 다운로드 — minWidth/배치 OK, 실제 xlsx 정상 생성
- [ ] 관리자 / 일반 사용자 구분 (사용자 필드 노출, 본인 것만 보이기)
- [ ] 페이징 selector 위치 (오른쪽 정렬)

이 항목들은 단순 HTTP 200 확인이 아니라 **Playwright 로 스크린샷 + 클릭 검증** 까지 해야 PASS. [[feedback-ui-test-depth]] 메모리 참조.
