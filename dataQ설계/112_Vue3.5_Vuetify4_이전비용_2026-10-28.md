# 112. Vue 3.5 + Vuetify 4 이전 비용

| 항목 | 내용 |
|---|---|
| 작성일 | 2026-10-28 |
| 대상 | `q-center/vue/front` (Vue 2 + Vuetify 2) → Vue 3.5 + Vuetify 4. 10-28 npm 최신 안정판은 Vue 3.5.44, Vuetify 4.3.1 |
| 기준 | 지금 코드를 grep 으로 센 값. 공수는 **추정치**(경험치 기반, 버퍼 별도). 기능은 그대로, 화면 동작도 그대로 옮기는 것이 범위 |

---

## 0. 요약

- **화면 이전만 80~117인일, 버퍼 20% 포함 96~140인일.** 2명이 이 일만 하면 약 2.5~3.5개월이다.
- **Spring Boot 3·Java 17 이전**(백엔드)은 따로 15~25인일, **PostgreSQL 16 이상 이전**은 3~5인일이다. 111번 0단계(90~130인일)는 낮게 잡혔다 — 셋을 합치면 **98~147인일, 버퍼 포함 118~176인일**이다(111번 고침).
- 점진 이전(호환 빌드 `@vue/compat`)은 쓸 수 없다. Vuetify 2 가 Vue 3 위에서 돌지 않고, 화면 코드 대부분이 Vuetify 다. **한 번에 옮기고 그동안 화면 기능 개발은 멈춘다.**
- 금액 = 인일 × 투입 인력 일 단가(예: KOSA SW기술자 평균임금 등급별 일 단가).

## 3. 기간·방식

| 인원 | 화면만 (버퍼 포함 96~140) | 0단계 전체 (118~176) |
|---|---|---|
| 1명 전담 | 약 5~7개월 | 약 6~9개월 |
| 2명 전담 | 약 2.5~3.5개월 | 약 3~4.5개월 |

- **한 번에 옮긴다.** 이전 기간에는 별도 브랜치에서 작업하고, 그동안 기존 화면 기능 개발은 멈춘다. 병행하면 같은 화면을 두 번 고쳐야 한다. 백엔드 결함 조치는 병행할 수 있다.
- **순서**: 1 빌드 → 2 골격 → 6 시험 공통 헬퍼 → 4·3 화면(작은 화면부터, 대형 6개는 마지막) → 5 모양 → 7 검수.
- 다른 일(RAMS 등)과 시간을 나누면 위 기간은 그만큼 늘어난다.

## 4. 위험

| 위험 | 대응 |
|---|---|
| `v-data-table` API 차이로 대형 화면(용어·코드·컬럼)이 예상보다 오래 걸림 | 대형 6개 중 하나(DSWord)를 먼저 시범 이전해 1주 안에 공수를 다시 잡음 |
| treeselect 대체 부품이 기존 동작(검색·다중 선택)을 못 맞춤 | 사용 화면이 1개라 직접 구현 범위로 잡음 |
| Vuetify 4 디자인 차이로 "화면이 달라졌다" 는 사용자 반응 | 테마·밀도 기본값을 지금 화면에 가깝게 먼저 맞추고 시작 |
| 외부 jar `common` 이 Spring 6 에서 안 돎 | 백엔드 이전 첫 주에 확인, 필요하면 소스 확보 |
| GS인증 이후 화면이 바뀌어 재시험 범위가 커짐 | 인증 일정과 겹치지 않게 시점 결정 |
| 이전 중 기능 동결이 길어짐 | 시범 이전 결과로 기간 확정 뒤 시작 |

권장: **DSWord(1,934줄, 표·대화상자·업로드 포함) 시범 이전 3~5인일**로 위 추정을 먼저 검증한다.
