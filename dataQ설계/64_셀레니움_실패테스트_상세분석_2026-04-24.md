## 1. `test_53_upload_attrs` — 🟢 테스트 stale

### 의도

컬럼(속성) 엑셀 업로드 기능 E2E:
1. 로그인
2. API 로 논리 모델 + 테이블 1건 선행 생성
3. 테스트용 xlsx 생성 (openpyxl, 3행 — PK 1/FK 1 포함)
4. **컬럼 화면 → [엑셀 업로드] → 파일 선택 → preview 다이얼로그 오픈 확인 → [등록 실행] 클릭 → commit**
5. API 로 TB_DATA_MODEL_ATTR 에 3행 등록됐는지, PK/nullable 일치하는지 검증

### 실패 지점

```
STEP: 4. UI 업로드 → preview → commit
  [SHOT] 04a_model_selected
  [SHOT] 04b_preview_dialog        ← 다이얼로그 캡처 시도
  >> FAIL: preview 다이얼로그 오픈 실패
  File "test_53_upload_attrs.py", line 216
    raise RuntimeError("preview 다이얼로그 오픈 실패")
```

스크린샷 `04a_model_selected` 는 찍힘 → **모델 선택까지는 성공**.
`04b_preview_dialog` 도 찍히는데 코드 흐름상 다이얼로그 대기 직전에 촬영된 것 → **촬영 후 대기 타임아웃**.

### 원인 분석

1인 개발 맥락에서 회귀 가능성은 제거. 짝 테스트 `test_53_upload_tables` (테이블 엑셀 업로드) 는 PASS 이므로 **업로드 인프라 전체가 망가진 건 아니고, 컬럼 쪽 UX 가 최근 변경됐을 것**이 가장 유력.

가능 시나리오:
- `DSDatamodelStatusColumn.vue` 의 업로드 버튼/파일 input 이 옮겨졌거나 숨김 처리 방식이 바뀜.
- preview 다이얼로그 트리거 타이밍/이벤트 이름 변경 (예: watcher → 명시적 open 호출로 바뀜).
- 파일 input 이 v-dialog 내부로 이동해 테스트 기존 셀렉터 범위 밖으로 빠짐.

테스트 코드 기대 vs 현 UI 실제:
- 테스트: `input[type='file']` 찾아 `send_keys(xlsx 경로)` → 일정 시간 대기하면 자동으로 preview 다이얼로그 뜰 것이라 가정.
- 실제: 그 가정이 깨졌을 가능성.

### 검증·수정 방향

1. **실제 UI 수동 확인** — 컬럼 화면에서 엑셀 업로드 돌려 preview 가 정상적으로 뜨는지 확인.
   - 뜨면 → 테스트의 파일 input 셀렉터/트리거 방식만 갱신.
   - 안 뜨면 → 그때 처음으로 기능 쪽 디버깅.
2. 수동 확인이 정상이면 `test_53_upload_attrs.py` step 4 의 업로드 핸들링 코드를 현 UI 구조에 맞춰 재작성.

## 2. `test_logical_model_e2e` — 🟡 테스트 설계 + 데이터

### 의도

논리모델 전체 라이프사이클:
1. 로그인
2. 논리 모델 생성 (한글 모델명)
3. 테이블 추가 (한글명만 입력 → TMP_TBL_N 자동 물리명)
4. **컬럼 5건 추가 + 표준 변환 자동 적용** — `사용자명`/`고객명`/`등록일시`/`주소`/`전화번호` 를 한글명으로만 입력, 시스템이 TB_TERMS 매칭해 영문 물리명·타입·길이·도메인 자동 채움
5. 이후 DDL 생성까지

### 실패 지점

```
STEP: 4-5. 컬럼 추가 + 표준 적용(용어/도메인 자동)

  [warn] '사용자명' 추가 중 예외: element click intercepted:
    Element <button ... disabled="disabled" ...
            id="btn-add-col-row" ...>...</button>
    is not clickable at point (627, 236).
    Other element would receive the click: <div ... class="row" ...>...</div>

  [warn] '고객명' 추가 중 예외: ... (동일 에러)
  [warn] '등록일시' 추가 중 예외: ... (동일 에러)
  [warn] '주소' 추가 중 예외: ... (동일 에러)
  [warn] '전화번호' 추가 중 예외: ... (동일 에러)

  >> FAIL: 용어사전 매칭 0건 — 후보(['사용자명', '고객명', '등록일시', '주소', '전화번호'])
           모두 표준 적용 실패. TB_TERMS 확인 필요
```

5개 한글명 모두 동일 에러. 핵심은 **`btn-add-col-row` 버튼이 `disabled="disabled"` 상태로 고정**되어 클릭이 뒤쪽 `div.row` 에 막힘.

### 원인 분석

**"논리모델 컬럼 추가 재설계"** (`53_논리모델_컬럼추가_그리드편집_재설계.md` 참조) 규칙:

> 물리명·타입은 수동 작성 불가, 표준사전 변환으로만 생성.
> 한글명 단일 입력 → resolveStandard → 용어/도메인/물리명/타입 자동 채움.
> 변환 실패 시 `TMP_COL_{순번}` + `VARCHAR(255)` 자동 비표준 저장.

`[+컬럼 추가]` 버튼 활성 조건 = **한글명을 입력하고 resolveStandard 가 유효 결과를 리턴한 상태**.
TB_TERMS 에 위 5개 한글명 중 하나라도 승인(`APRV_YN='Y'`) 으로 등록돼 있지 않으면 resolveStandard 응답이 비매칭 → 버튼 계속 `disabled`.

실제 `TB_TERMS` 쿼리로 확인 필요:

```sql
SELECT TERMS_NM, APRV_YN, USE_YN
  FROM TB_TERMS
 WHERE TERMS_NM IN ('사용자명','고객명','등록일시','주소','전화번호');
```

결과 비었거나 `APRV_YN='N'` 섞여 있으면 확정.

### 검증·수정 방향

- **즉시 검증**: 위 SQL 돌려서 등록 현황 확인.
- **수정 옵션 A (테스트 쪽)**: `test_logical_model_e2e.py` 에 **setup fixture** 추가 — 테스트 시작 전 필요한 용어 5건을 API 로 생성/승인, teardown 에서 제거.
- **수정 옵션 B (데이터 쪽)**: 개발/테스트 DB 시드로 TB_TERMS 에 위 5건 상시 승인 상태로 유지. 운영에서는 실제 데이터 기반이라 테스트용 시드는 개발 DB 한정.

A 가 일반적으로 더 안전 (테스트 격리).

## 3. `test_reject_physical_delete` — 🟢 셀렉터 stale (기능 정상)

### 의도

**반려된 단어는 물리 삭제** 되는지 회귀 검증:
1. `jyjang` 계정으로 단어 등록 신청
2. `space` 계정(관리자)으로 로그인해 **반려** 처리
3. 검증 3가지:
   - 단어 사전에서 해당 단어가 **안 보임** (물리 삭제됐다는 뜻)
   - 승인 이력 탭에 **반려 기록 존재**
   - **동일 단어명 재등록** 가능 (물리 삭제됐다는 간접 증명)
4. 정리 (남은 단어 삭제)

### 실패 지점

```
===== STEP 2: space 로그인 → 단어 반려 =====
  PASS: STEP2-1: 승인 목록에서 단어 발견
  반려 버튼 클릭됨        ← ✅
  반려 사유 입력됨        ← ✅
  반려 확인 클릭됨        ← ✅
  FAIL: STEP2-2: 반려 처리 완료   ← ❌ 여기서만 실패

===== STEP 3: 반려 후 검증 =====
  PASS: STEP3-1: 반려된 단어 물리 삭제 (단어 사전에서 미노출)   ← ✅
  PASS: STEP3-2: 승인 이력에 반려 기록 존재                     ← ✅
  PASS: STEP3-3: 반려 후 동일 단어명 재등록 성공                ← ✅
```

### 원인 분석

핵심: **반려 기능 자체는 정상 동작**.
- STEP2 에서 반려 버튼 → 사유 입력 → 확인 클릭까지 **모든 인터랙션 성공**.
- 뒤따른 STEP3 세 검증 (물리 삭제 / 이력 존재 / 재등록 가능) **모두 PASS** → 반려 처리가 실제로 완결됨.

STEP2-2 "반려 처리 완료" 만 fail 한 이유는 그 스텝의 **완료 어설션이 찾던 조건** (예: 토스트 텍스트, URL 변화, 특정 엘리먼트 사라짐) 이 현재 UI 와 어긋남.

### 검증·수정 방향

- `test_reject_physical_delete.py` 에서 STEP2-2 어설션 코드 확인.
- 현 UI 의 반려 성공 신호(토스트 문구/뱃지 변화/행 즉시 제거 여부) 에 맞춰 어설션 업데이트.
- **기능 수정 불필요** — 테스트 코드만 갱신.
