NavidM Meta 대 SMETA

비투엔의 메타데이터 관리 제품 SMETA 를 우리 제품과 기능 단위로 맞대어 보았습니다. 우리 쪽은 102번 기능명세서, SMETA 쪽은 비투엔이 2025년 4월에 낸 사용자 교육자료를 기준으로 삼았고, 83개 항목마다 판정과 근거 위치를 달았습니다.

한눈에

  1. 두 제품은 출발점이 반대입니다.SMETA 는 사람이 표준과 테이블을 메타에 등록하고 결재로 통제하는 등록부입니다. 우리는 실제 DB 를 수집해 표준에 맞게 고쳐 나가는 정비 도구입니다. 그래서 기능 폭은 SMETA 가 넓고, 정비 작업의 깊이는 우리가 깊습니다.
  2. 표준사전 자체는 거의 대등합니다.단어·용어·도메인·금칙어·복수 사전·엑셀 일괄등록은 맞먹습니다. 비어 있는 곳은 코드 유형(계층·파생·통합), 도메인 그룹 다단계, 공통표준 골라 넣기, 개인정보·암호화 표시입니다.
  3. 공공 입찰에서 먼저 걸릴 열세는 네 가지입니다.다단계 결재선, 역할별 권한, 범정부 데이터 플랫폼 연계, Tibero 수집. 넷 다 공공기관 사업에서 요구가 잦은 항목입니다.
  4. 우리가 앞서는 곳은 "정비 작업" 쪽에 모여 있습니다.한글 컬럼명 수천 건 일괄 표준화, 진단 결과에서 바로 고치는 스크립트, 사전마다 다른 표준화 관례, DB 직접 반영. 다만 이 중 다수는 SMETA 교육자료에 나오지 않았다는 뜻이지 SMETA 에 없다는 확인이 아닙니다. 영업 자료에 쓰기 전에 데모로 확인해야 합니다.

    같은 이름의 기능이 다른 일을 합니다

    기능표만 맞대면 대등해 보이는 항목도 일하는 순서가 반대라 실제 쓰임이 다릅니다. 이 차이를 먼저 잡아야 아래 판정이 읽힙니다.

    SMETA설계를 등록하고 결재로 통제한다

    1. 표준사전과 테이블을 화면·엑셀·모델링 도구로 메타에 등록 요청
    2. 다단계 결재선을 거쳐 승인
    3. 승인된 메타로 DBMS 별 DDL 을 만들어 DB 담당자에게 넘김
    4. 담당자가 직접 DB 에 실행하고 반영 완료를 표시
    5. 배치 통계로 메타와 실제 DB 의 차이(GAP)를 점검하고 다시 등록

    실제 DB 에 대한 표준 진단·구조 진단·값 진단은 별도 품질 제품 SDQ, 통합 대시보드·통합 검색은 포털 제품 SPORTAL 몫으로 나눠 팝니다 (p.8).

    NavidM Meta실제 DB 를 수집해 표준으로 정비한다

    1. 운영 DB 에 접속해 테이블·컬럼·인덱스·제약조건을 수집
    2. 표준사전 기준으로 컬럼마다 표준 진단
    3. 진단 결과에서 바로 고치는 스크립트와 용어 등록, 한글 컬럼명 일괄 표준화
    4. 스키마에 영향을 주는 변경만 결재, 나머지는 즉시 반영
    5. 승인 후 [DB 반영] 으로 대상 DB 에 직접 실행, 구조 변경 진단으로 변화 감시

    표준 진단·구조 진단·대시보드를 한 제품 안에 둡니다. 데이터 품질(값) 진단만 DQ 제품으로 분리했습니다.

    예: 표준 준수율은 양쪽 다 있지만 재는 대상이 다릅니다. SMETA 는 메타에 등록된 테이블·컬럼을 표준과 비교하고(p.80), 우리는 실제 DB 에서 수집한 컬럼을 비교합니다(DG-B04). 이미 운영 중인 DB 가 표준을 얼마나 지키는지는 우리 쪽이 바로 답하고, 설계 단계의 통제는 SMETA 쪽이 촘촘합니다.

    양쪽에 있고 SMETA 쪽이 범위나 깊이에서 앞섬
    SMETA만
    SMETA 교육자료에 있고 우리 코드에는 없음

    비교 방법

    • SMETA: 교육자료 96쪽 전체 텍스트를 뽑고, 화면으로만 설명한 쪽은 쪽 이미지를 직접 보고 기능을 뽑음
    • 우리: 102번 기능명세서 544행 전부를 훑고, 판정이 갈리는 행은 원문과 코드로 다시 확인
    • 같은 이름이어도 일하는 방식이 다르면 비고에 적음 (예: 이음동의어, 준수율)
    • 각 행에 SMETA 쪽 번호와 우리 기능ID 를 달아 되짚을 수 있게 함

    다루지 않은 것

    • 데이터 품질(값) 진단 — 우리 DQ, SMETA 쪽 SDQ 로 양쪽 모두 별도 제품
    • SPORTAL(포털)·SDQ 를 합친 제품군 비교
    • 가격, 성능, 실제 사용성, 레퍼런스 규모
