## 2. 98번 표준사전 세트 — 1~4단계 완료

설계 전문: [98_표준사전_세트_설계_2026-09-03.md](98_표준사전_세트_설계_2026-09-03.md)

### 왜 했나

국가기록원(RAMS) SMETA 자료를 올리려는데 기존 사전과 섞인다. 그리고
**일괄등록이 중복을 실패가 아니라 skip 으로 넘긴다** ([ExcelUploadService.java:103](../q-common/src/main/java/com/ndata/quality/service/ExcelUploadService.java)).
뜻이 다른 같은 영문약어가 조용히 누락되고 "성공" 으로 보고된다.

### 한 일

| 단계 | 내용 |
|---|---|
| 1 | `tb_std_dict` 신설 + 6개 사전 테이블에 `dict_id` + 유니크 8개 복합 재정의 + **이름 참조 FK 4개 복합화** |
| 2 | 매퍼 42개 사전 스코프 + **이름만으로 하는 조인 13곳** 수정 |
| 3 | 사전 선택기(6화면) · 사전 관리 화면 · 모델 등록/수정 · 진단 실행 · 스케줄 차단 |
| 4 | 형식단어 규칙을 사전 속성으로 (2단계에 포함) |

### 설계하면서 뒤집힌 판단 3개 (같은 실수 반복 방지)

1. **전역 시스템설정 → 사전 속성** — 형식단어 관례는 사전마다 다르다. 시스템 속성이 아니다.
   만들던 `tb_sys_config` 는 걷어냈다.
2. **진단 결과 초기화 → 하지 않음** — 지난 진단은 "그때 그 사전으로 잰 이력" 이라 의미가 있다.
   그리고 준수율은 `attr` 플래그가 아니라 `TB_DIAG_JOB`+`TB_DIAG_RESULT` 에서 나오므로
   플래그를 지워도 준수율은 안 변하고 컬럼 화면 표시만 사라진다. 손해만 있었다.
3. **RAMS 별도 인스턴스 → 안 감** — 세트를 만들 거면 그 작업이 통째로 버려진다.

### 조심할 것 — 이름만으로 하는 조인

필터보다 이게 먼저 터진다.

```sql
-- 이러면 RAMS 용어에 DEFAULT 도메인이 붙는다
LEFT JOIN TB_DOMAIN D ON T.DOMAIN_NM = D.DOMAIN_NM
```

13곳 모두 `AND T.DICT_ID = D.DICT_ID` 를 붙였다. 그중 4곳은
`TB_DATA_MODEL_ATTR a JOIN TB_TERMS t ON t.TERMS_NM = a.ATTR_NM_KR` 형태라
`TB_DATA_MODEL m` 을 끼워 `t.DICT_ID = m.DICT_ID` 로 묶었다.

**새 쿼리를 쓸 때 사전 테이블을 이름으로 조인하면 반드시 `DICT_ID` 도 같이 묶을 것.**

### 조심할 것 — `<include refid>` 안은 grep 에 안 잡힌다 (2026-09-09 추가)

`terms.xml` 의 `termsInfoSelectBody` · `termsSingleSelectBody` 두 `<sql>` 조각에
`TB_TERMS A LEFT OUTER JOIN TB_DOMAIN B on A.DOMAIN_NM = B.DOMAIN_NM` 이
숨어 있었다. 조각을 쓰는 `<select>` 본문에는 테이블명이 없어서,
"select 블록에서 테이블명 찾기" 식 스캔에 **5개 쿼리가 통째로 빠졌다.**

- `selectTermsByNm` · `selectTermsInfoByNm` · `selectApprovedTermsByNm`
  · `selectApprovedTermsByEngNm` (+ 이미 처리한 `selectTermsByEngNm`)

매퍼를 훑을 때는 `<sql id=...>` 조각과 `<include refid=...>` 를 **먼저** 펼쳐볼 것.

```bash
grep -n '<sql id=' q-common/src/main/resources/mapper/stnd/*.xml
grep -n '<include refid=' q-common/src/main/resources/mapper/stnd/*.xml
```

### 조심할 것 — `.dockerignore` 는 ASCII 만

`docker compose build` 가 이 오류로 죽는다.

```
header key "exclude-patterns" contains value with non-printable ASCII characters
```

BuildKit 이 `.dockerignore` 패턴을 gRPC 헤더로 보내는데 한글이 들어가면 거부한다.
`dataQ설계/` → `dataQ*/` 처럼 **와일드카드로 우회**했다 (2026-09-03 수정).
패턴을 추가할 때 한글 디렉터리는 ASCII 접두사 + `*` 로 쓸 것.

### 조심할 것 — XML 파싱은 통과해도 SQL 은 깨진다

`search.xml` 에서 사고가 났다. `LIMIT 20` 앞에 필터를 넣는 일괄 치환이
`ORDER BY` **뒤에** 조건을 붙였고, 사전 컬럼이 없는 `TB_DATA_MODEL_ATTR` 까지 물었다.
XML 파싱은 멀쩡히 통과한다. **매퍼를 일괄 수정하면 SQL 을 실제로 DB 에 돌려볼 것.**

### 아직 기본 사전으로 도는 곳

컨트롤러 일부가 `dictService.nameParam(null, ...)` 로 **기본 사전을 명시 조회**한다.
조용히 전역을 뒤지지 않도록 일부러 이렇게 뒀다.

```bash
grep -rn "nameParam(null" q-center/src q-common/src
```

화면이 사전을 보내기 시작하면 `null` 자리에 요청값을 넣으면 된다.

**SMETA 양식 ≠ 우리 양식이라 변환이 필요하다.** 매핑은 이미 분석해 뒀다.

| 우리 단어양식 (열 순서) | SMETA 단어목록 |
|---|---|
| No / 제정차수 / 단어명 / **단어영문약어명** / 단어영문명 / 단어설명 / 형식단어여부 / 도메인분류명 / 이음동의어 / 금칙어 / 요청시스템 / 표준여부 | No / 요청유형 / 단어명 / 영문명 / **영문약어명** / 단어설명 |

- 영문약어·영문명 **순서가 반대**다. 그대로 넣으면 안 된다.
- SMETA 에 `형식단어여부` 가 없다. 도메인목록의 `분류어` 열(SN, ID 등)에 있는 영문약어를
  형식단어로 도출해야 한다. 형식단어면 `도메인분류명` 이 필수다 (ExcelUploadService 검증).
- 용어의 `용어영문명`(VOL, NM …)이 우리의 `용어영문약어명` 에 해당한다.
- 용어 등록은 `용어영문약어명` 을 `_` 로 쪼개 **구성단어가 전부 사전에 있어야** 통과한다.
  그래서 단어를 먼저 올려야 한다.
