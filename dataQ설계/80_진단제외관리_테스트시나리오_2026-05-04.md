# 80. 진단 제외 관리 — 통합 테스트 시나리오

**작성일**: 2026-05-04
**대상 기능**: [79번 진단 대상 제외 관리](79_진단대상_제외관리_설계_2026-05-04.md)
**테스트 목적**: 구현 후 회귀 검증을 위한 시나리오 확정. 모수 제외 / cascade / 사유 / ALTER 후 구조 진단 / ON 복귀까지 풀 사이클.
**작성 시점**: 구현 착수 전 — TDD 식 시나리오 선확정

## 1. 시나리오 개요 — 12 Phase

```
[Setup]
P1.  Oracle 에 IMSI_* 3 테이블 생성
P2.  데이터 모델에 수집

[제외 설정]
P3.  단건 OFF (테이블) + 사유
P4.  일괄 OFF (테이블 복수) + 사유
P5.  단건 OFF (컬럼) + 사유
P6.  일괄 OFF (컬럼 복수) + 사유

[표준화 진단 — 모수 제외 검증]
P7.  표준화 진단 실행 → OFF 모수 제외 + 준수율 영향 검증

[구조 변경 진단 — ALTER 무시 검증]
P8.  구조 변경 진단 1차 (baseline)
P9.  ALTER TABLE — OFF 테이블/ON 테이블 변경
P10. 구조 변경 진단 2차 — OFF 변경은 결과에 없고, ON 변경만 등장

[ON 복귀]
P11. 모두 ON 토글 → 사유 NULL 클리어 → 재진단 시 모수/결과 복귀

[Cleanup]
P12. 테이블 DROP / 데이터 정리
```

### P7. 표준화 진단 실행 — 모수 제외 + 준수율 영향 검증

**현재 상태 요약**:
- IMSI_TEST_001: 테이블 STND OFF (cascade — 모든 컬럼 진단 안 됨)
- IMSI_TEST_002: 테이블 STND ON, 컬럼 CODE/VALUE STND OFF, REG_DT STND ON
- IMSI_TEST_003: 모두 ON

**Action**:
- UI: 표준 진단 → [실행] 또는 API: `POST /api/diag/run`
- 진단 완료 대기

**Verify (분모/분자)**:
```sql
-- 진단 결과에 등장한 IMSI_* 컬럼만
SELECT OBJ_NM, ATTR_NM, NON_STND_TYPE
  FROM TB_DIAG_RESULT WHERE DIAG_JOB_ID = (
    SELECT MAX(DIAG_JOB_ID) FROM TB_DIAG_JOB WHERE DM_ID='...' AND STATUS='DONE'
  ) AND OBJ_NM LIKE 'IMSI_%';

-- 기대 결과:
-- IMSI_TEST_001 의 모든 컬럼: 등장 X (테이블 OFF cascade)
-- IMSI_TEST_002.CODE, VALUE: 등장 X (컬럼 OFF)
-- IMSI_TEST_002.REG_DT: 등장 가능 (필드 표준 위반 시)
-- IMSI_TEST_003.* : 모두 진단 대상 — 위반 시 등장
```

```sql
-- 진단 메타 — 제외 카운트
SELECT EXCLUDED_OBJ_CNT, EXCLUDED_ATTR_CNT
  FROM TB_DIAG_JOB WHERE DIAG_JOB_ID = (...);
-- EXCLUDED_OBJ_CNT = 1 (IMSI_TEST_001 의 5 컬럼 cascade 제외)
-- EXCLUDED_ATTR_CNT = 5 (TEST_001 cascade) + 2 (TEST_002 의 CODE/VALUE) = 7
```

```sql
-- 준수율 계산 시 분모/분자 제외 검증
SELECT TOTAL_CNT, ISSUE_COL_CNT
  FROM TB_DIAG_JOB WHERE DIAG_JOB_ID = (...);
-- TOTAL_CNT 가 OFF 컬럼 수만큼 줄어있어야 함 (IMSI 외 다른 모델 컬럼은 그대로)
```

**UI Verify**:
- 진단 결과 화면에 "표준 진단 대상 아님: 7건" 카운트 표시
- 위반 결과 그리드에 IMSI_TEST_001.* 가 보이지 않음
- 모델 준수율 통계가 OFF 컬럼 빠진 채로 계산

- IMSI_TEST_002: 테이블 STRUCT OFF
- IMSI_TEST_003: 테이블 STRUCT OFF

**Action**:

**Verify**:

```sql
-- baseline 1행 생성
```

### P9. ALTER TABLE — OFF 와 ON 테이블 모두 변경

**Action** (Oracle 직접):
```sql
-- IMSI_TEST_002 (구조 OFF) 에 컬럼 추가
ALTER TABLE IMSI_TEST_002 ADD NEW_COL VARCHAR2(50);

-- IMSI_TEST_003 (구조 OFF) 의 ETC 컬럼 길이 변경
ALTER TABLE IMSI_TEST_003 MODIFY (ETC VARCHAR2(100));

-- IMSI_TEST_001 (구조 ON) 의 XYZ_DATA 컬럼 길이 변경
ALTER TABLE IMSI_TEST_001 MODIFY (XYZ_DATA VARCHAR2(200));

-- IMSI_TEST_001 의 NAME 컬럼 (컬럼 STRUCT OFF) 길이 변경
ALTER TABLE IMSI_TEST_001 MODIFY (NAME VARCHAR2(100));
```

**그 다음 데이터 모델 재수집** — 메타가 갱신되어야 진단이 변경 감지.

### P10. 구조 변경 진단 — 2차 (변경 검증)

**Action**:
- 구조 변경 진단 [실행]

**Verify**:
```sql
SELECT * FROM TB_STRUCT_DIAG_DETAIL
 WHERE STRUCT_DIAG_ID = (SELECT MAX(STRUCT_DIAG_ID) FROM TB_STRUCT_DIAG_HISTORY WHERE DATA_MODEL_ID='...')
   AND OBJ_NM LIKE 'IMSI_%';

-- 기대 결과:
-- IMSI_TEST_002.NEW_COL: 등장 X (테이블 STRUCT OFF cascade)
-- IMSI_TEST_003.ETC: 등장 X (테이블 STRUCT OFF cascade)
-- IMSI_TEST_001.XYZ_DATA: 등장 O (테이블/컬럼 모두 STRUCT ON)
-- IMSI_TEST_001.NAME: 등장 X (컬럼 STRUCT OFF)
```

→ **OFF 된 변경은 진단 결과에 안 잡힘** — 핵심 검증 포인트.

### P11. ON 복귀 + 재진단

**UI**:
1. 진단 제외 관리 → 일괄 [표준 ON] / [구조 ON] 으로 IMSI_TEST_001/002/003 모두 복귀
2. 컬럼 단위도 복귀 (IMSI_TEST_001.NAME, IMSI_TEST_002.CODE/VALUE)

**Verify (DB)**:
```sql
SELECT COUNT(*) FROM TB_DATA_MODEL_OBJ
 WHERE OBJ_NM LIKE 'IMSI_%'
   AND (STND_DIAG_TARGET_YN = 'N' OR STRUCT_DIAG_TARGET_YN = 'N');
-- 0 (모두 ON)

SELECT COUNT(*) FROM TB_DATA_MODEL_OBJ
 WHERE OBJ_NM LIKE 'IMSI_%'
   AND (STND_DIAG_TARGET_REASON IS NOT NULL OR STRUCT_DIAG_TARGET_REASON IS NOT NULL);
-- 0 (사유 NULL 클리어)
```

**재진단**:
- 표준 진단 재실행 → IMSI_* 모든 컬럼이 진단 모수에 포함 (위반 시 결과에 등장)
- 구조 변경 진단 재실행 → IMSI_TEST_002.NEW_COL / IMSI_TEST_003.ETC 변경 사항 등장

### P12. Cleanup

```sql

DROP TABLE IMSI_TEST_001;
DROP TABLE IMSI_TEST_002;
DROP TABLE IMSI_TEST_003;

-- dataq-db (모델에서 OBJ/ATTR 정리는 다음 수집에서 자동 처리)
```

## 4. 셀레니움 자동화 — 권장 구조

```python
"""
test_diag_target_imsi.py — 진단 제외 관리 통합 시나리오 (Phase 1~12)

전제:
  - oracle-xe 컨테이너 기동
  - q-center / q-executor 정상
  - 테스트용 모델 (예: CAMS) 의 데이터소스가 oracle-xe 가리킴
"""
import time, requests, base64, traceback
from selenium import webdriver

BASE = "http://localhost:28091"
results = []

def step(name, fn):
    print(f"\n=== {name}")
    try: fn(); results.append((name, "PASS")); print("  >> PASS")
    except Exception as e: traceback.print_exc(); results.append((name, "FAIL"))

def main():
    # P1. Oracle DDL — sqlplus 실행
    step("P1. Oracle IMSI_* 3 테이블 생성", lambda: _exec_oracle_ddl())

    # P2. 데이터 모델 수집
    step("P2. 데이터 모델 재수집", lambda: _collect_model())

    # P3~P6. 제외 토글 (API + UI 둘 다 검증)
    step("P3. 단건 OFF — IMSI_TEST_001 표준", lambda: _toggle_obj("STND", "N", "단건 OFF 테스트", "IMSI_TEST_001"))
    step("P4. 일괄 OFF — TEST_002/003 구조 + 사유 입력", lambda: _toggle_obj_batch("STRUCT", "N", "일괄 OFF 사유 입력 테스트", ["IMSI_TEST_002","IMSI_TEST_003"]))
    step("P5. 컬럼 단건 OFF — TEST_001.NAME 구조 + 사유 빈칸", lambda: _toggle_attr("STRUCT", "N", "", "IMSI_TEST_001", "NAME"))
    step("P6. 컬럼 일괄 OFF — TEST_002.CODE/VALUE 표준", lambda: _toggle_attr_batch("STND", "N", "컬럼 일괄 OFF", "IMSI_TEST_002", ["CODE","VALUE"]))

    # P7. 표준화 진단 + 모수 제외
    step("P7. 표준화 진단 — IMSI_TEST_001.* 결과 미등장 / 카운트=7", lambda: _run_stnd_diag_and_verify())

    # P8. 구조 진단 baseline
    step("P8. 구조 변경 진단 1차 (baseline)", lambda: _run_struct_diag())

    # P9. ALTER TABLE
    step("P9. ALTER TABLE — OFF/ON 테이블 변경", lambda: _alter_imsi_tables())

    # P10. 구조 진단 2차
    step("P10. 구조 변경 진단 2차 — TEST_002/003 변경 미등장, TEST_001.XYZ 변경 등장", lambda: _run_struct_diag_and_verify())

    # P11. ON 복귀 + 재진단
    step("P11. 모두 ON 복귀 + 재진단", lambda: _all_on_and_rerun())

    # P12. Cleanup
    step("P12. Cleanup — DROP IMSI_*", lambda: _cleanup_oracle())

if __name__ == "__main__":
    main()
    p = sum(1 for _, st in results if st == "PASS")
    f = sum(1 for _, st in results if st == "FAIL")
    print(f"\n{'='*60}\n결과: {p} PASS / {f} FAIL\n{'='*60}")
    for n, st in results: print(f"  [{st}] {n}")
```

## 7. 수동 시연 절차 (외부 시연용)

위 12 Phase 를 GUI 로 천천히 따라가면서 보여주는 시연 시나리오. 자동화 외에 BMT/PoC 시연 시 사용.

1. (사전) Oracle 에 IMSI_* 생성 — DBA 가 사전 준비
2. UI 로그인 (space)
3. 데이터 모델 → IMSI_* 가 보임 확인
4. 진단 제외 관리 → 검색 "IMSI" → 3 테이블 표시
5. 단건 OFF / 일괄 OFF / 컬럼 OFF 차례로 시연 (사유 모달 보여주기)
6. 표준 진단 실행 → 결과 화면에서 "대상 아님 7건" 표시 확인
7. 구조 진단 실행 → baseline 저장
8. (브레이크) 백엔드에서 ALTER TABLE 실행
9. 구조 진단 재실행 → OFF 한 변경은 결과 없음 / ON 한 변경은 결과 등장
10. ON 복귀 → 재진단 → 결과 다시 등장

## 9. 함정 / 주의

1. **수집 후 진단** — ALTER 후 반드시 데이터 모델 재수집해야 메타에 반영. 수집 안 하면 진단도 변화 못 잡음.
2. **컬럼 단위 OFF + 테이블 단위 ON** 케이스 — 테이블은 진단 대상이지만 그 테이블 안 일부 컬럼만 제외. cascade 와 분리.
3. **사유 빈칸** — 모달에서 [적용] 가능. NULL 저장. 사용자 우려 사항 점검.
4. **품질 진단** — 매퍼 통합 보류. 본 시나리오는 표준/구조 만 검증. 품질 항목은 79번 §5-3 핸드오버 노트 따라 추후 추가.
5. **이전 진단 결과** — OFF 했어도 과거 진단 이력은 보존 (감리 측면). 다음 진단부터만 영향.
