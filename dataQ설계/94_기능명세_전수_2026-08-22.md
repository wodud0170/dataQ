`dm-collect.xml` 의 실제 수집 쿼리는 **8개뿐**:

- Oracle: Objs / Attrs / Indexes / Constraints (4)
- MariaDB: Objs / Attrs (2)
- Cubrid: Objs / Attrs (2)
- **PostgreSQL 수집 쿼리 0건**, **인덱스·제약조건 수집은 Oracle 전용**

`29_인덱스_제약조건_수집_설계.md` §3.3-3.4 는 PostgreSQL 쿼리를 정의해 두었으나 코드에 반영되지 않았고, `33_인덱스_제약조건_수집_현황분석.md` §3.4 가 "PostgreSQL 부재" 로 이미 지적한 상태다.

| 3 | **API 는 있으나 화면 진입 경로 없는 7종** (§0-2) | 죽은 코드인지, 메뉴만 붙이면 되는지 판정 필요 |
| 4 | 매뉴얼에 있으나 미구현인 기능 (§0-1, §1-1, §2-1, §3-1) | 매뉴얼을 고칠지 기능을 만들지 결정 필요 |
| 5 | 나머지 기능의 런타임 스모크 | 셀레니움 스위트 확장 |

### 4-2. 검증 방식

- **API 레벨**: `requests` 세션으로 실호출 → 응답 코드·본문 구조 검증 (`93_런타임_점검결과` 의 스모크 스크립트 패턴 재사용)
- **UI 레벨**: 셀레니움 (`dataQ설계/테스트/selenium/`) — 46개 파일이 이미 존재하며 2026-08-22 기준 전부 통과 상태
- **DB 레벨**: `docker exec dataq-db psql` 로 부수효과 확인

### 4-3. 문서 정리 과제

stale 로 판명된 문서 5종(`66`, `26`, `85`, `90` 일부, `84` 메뉴명)에 **"이 문서는 YYYY-MM-DD 시점 스냅샷이며 현행이 아님"** 배너를 달거나 갱신해야 한다. 특히 `84_시스템_수동테스트_절차서` 의 컬럼명 오기(§0-5 #1)는 그대로 따르면 검증이 실패하므로 즉시 수정 대상이다.
