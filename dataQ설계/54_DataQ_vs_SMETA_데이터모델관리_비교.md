# DataQ vs SMETA — 데이터 모델 관리 기능 비교

**작성일:** 2026-04-21
**기준:** DataQ 현재 상태 (53번 설계 Phase 1~6 구현 완료 후)
**목적:** SMETA(비투엔)의 데이터 모델 관리 기능과 직접 비교. 보유 기능, 격차, 차별점을 재정리.
**참고:** 2026-04-17에 작성된 전사 기능 GAP 분석 문서 `경쟁사/13_DataQ_vs_SMETA_기능GAP_및_로드맵.md`의 "데이터모델 관리" 섹션을 갱신·심화.

---

## 0. 요약 한 줄

- **SMETA**: 주제영역→엔터티→속성 계층의 **논리 모델을 웹에서 직접 설계**하고 표준사전·도메인 기반으로 **물리 모델(DDL)을 자동 생성**. 결재 기반 워크플로우 중심.
- **DataQ**: 수집 기반 + 53번 설계 구현으로 **그리드 편집·TSV 붙여넣기·엑셀 업로드·선택 컬럼 물리 변환**까지 확보. 여전히 **주제영역·엔터티 계층·DDL 자동 생성**은 미흡.

## 1. 제품 개요 비교

| 항목 | SMETA | DataQ |
|------|-------|-------|
| 공급사 | 비투엔 | 내부 개발 (나라아이넷) |
| 시장 지위 | 조달청 데이터 거버넌스 솔루션 3년 연속 1위 | 신규 진입 |
| 기본 철학 | 결재 기반 중앙 통제 + 사전→모델→DBMS 파이프라인 | 수집 기반 현행 분석 + 자동 표준화 추천 |
| 주요 연계 | ERwin, Eclipse 플러그인, AWS/빅데이터 | PostgreSQL·Oracle 등 9종 DBMS 수집 |

## 2. 데이터 모델 관리 기능 비교

### 2-1. 모델 계층 구조

| 기능 | SMETA | DataQ | 상태 |
|------|:-----:|:-----:|:----:|
| 주제영역(Subject Area) 관리 | O | X | GAP |
| 엔터티 등록/조회 | O | △ | DataQ 는 수집된 "테이블(OBJ)" 단위만 있음. 논리 엔터티 개념 부재 |
| 속성 등록/조회 | O | O | 53번 설계로 그리드 편집 가능 |
| 관계(Relationship) 정의 | O | △ | FK 업로드는 플래그만 저장, CONSTRAINT 물리 저장은 미완 |
| 모델 버전 관리 | O | O | `TB_DATA_MODEL.ver` 필드 존재 |

### 2-2. 모델 생성·편집

| 기능 | SMETA | DataQ | 상태 |
|------|:-----:|:-----:|:----:|
| 웹에서 논리 모델 직접 설계 | O | **O (신규)** | 53번 Phase 3~6 구현 |
| 테이블 추가(논리) | O | O | `/api/dm/addObj` (물리명 비면 TMP_TBL_N 자동) |
| 컬럼 그리드 인라인 편집 | △ | **O (신규)** | 53번 Phase 2 — `DSDatamodelStatusColumn.vue` |
| 빈 행 10개 일괄 추가 | X | **O (신규)** | 엑셀 감성 UX — DataQ 차별점 |
| TSV 붙여넣기 (엑셀→그리드) | X | **O (신규)** | `onPaste` handler, Ctrl+C/V 지원. DataQ 차별점 |
| 엑셀 업로드(논리 테이블 일괄) | O | **O (신규)** | 53번 Phase 5 — 미리보기→commit 2단계 |
| 엑셀 업로드(논리 컬럼 일괄) | O | **O (신규)** | 53번 Phase 5 — FK 참조 2-pass 매핑 |

| ERD 드로잉 (네이티브 캔버스) | X | X | 양쪽 모두 네이티브 없음. SMETA는 ERwin에 위임 |

### 2-3. 논리→물리 변환

| 기능 | SMETA | DataQ | 상태 |
|------|:-----:|:-----:|:----:|

| 선택 컬럼만 변환 (배치) | △ | **O (신규)** | 53번 — 체크박스 다중 선택 + 일괄 변환 |
| 표준사전 기반 물리 타입 자동 결정 | O | X | GAP. 도메인→DBMS별 타입 매핑 필요 |

| 매칭 재시도/수동 보정 | O | △ | 실패 시 수동 편집 가능하나 재매칭 버튼은 없음 |

## 3. 데이터 모델 관리 관점 — 격차 재정리

### A. 여전히 GAP (우선순위 높음)

1. **주제영역 계층 (Subject Area)** — 엔터티의 상위 분류. SMETA 입찰 필수
2. **엔터티 개념 도입** — 현재는 "수집된 테이블(OBJ)"만 있음. "웹에서 설계한 논리 엔터티"와 "수집된 물리 테이블"의 2계층 분리 필요. 상세는 55번 문서 참고
3. **관계(Relationship) 객체** — FK 업로드가 플래그만 저장. `TB_DATA_MODEL_CONSTRAINT` INSERT 완성 필요 (53번 후속)
4. **DDL 완전 생성** — 제약조건·FK·인덱스 포함한 CREATE 문 전체
5. **도메인→물리 타입 자동 결정** — 현재는 VARCHAR(255) 고정
6. **ERwin 연동 재설계** — SMETA는 공식 연계, DataQ는 파서 구현했으나 미완 상태

### B. 53번으로 해소된 GAP

1. ~~엑셀 업로드(논리 모델 일괄)~~ → Phase 5 완료
2. ~~웹 그리드 인라인 편집~~ → Phase 2 완료
3. ~~선택 컬럼만 물리 변환~~ → Phase 4 완료

### C. DataQ 우위 (유지·강화)

1. **TSV 붙여넣기** — 엑셀 → 그리드 Ctrl+C/V. SMETA 없음
2. **빈 행 N개 일괄 추가** — 엑셀 감성 UX
3. **자동 표준화 추천** — 형태소 분리 + 약어 추천
4. **구조 진단** — 실시간 DBMS vs 메타 비교
5. **일괄 코멘트 스크립트** — 45번 DDL 생성

## 4. 사용자 시나리오 비교

### 시나리오 1: "빈 모델에서 고객 관리 테이블 20개 설계"

**SMETA 플로우**
1. 주제영역 "고객관리" 등록 → 결재
2. 엔터티 "고객마스터" 등록 → 결재
3. 속성 20개를 속성 등록 화면에서 하나씩 추가 → 결재
4. 논리→물리 변환 실행 → 물리 모델 생성
5. DDL 생성 → DBMS 배포 신청

**DataQ 플로우 (53번 이후)**
1. 데이터 모델 신규 생성 (주제영역 없음)
2. 테이블 화면에서 **엑셀 업로드** (테이블 20개 한 번에)
3. 컬럼 화면에서 **엑셀 업로드** 또는 **TSV 붙여넣기** (컬럼 일괄)
4. 체크박스로 선택 후 **[선택 컬럼 물리모델 변환]**
5. DDL 다운로드 → 수동 배포

**평가**: DataQ 가 데이터 입력 속도는 우위. 단 **주제영역·결재 체계가 없어 거버넌스 관점은 열위**.

### 시나리오 2: "기존 DBMS 역공학 후 표준화"

**SMETA 플로우**
1. 스키마 수집
2. 표준 단어/용어 일괄등록 (수동 매칭)
3. 테이블별 비표준 컬럼 확인 → 수정 요청 → 결재

**DataQ 플로우**
1. 스키마 수집
2. **자동 표준화 추천 실행** (형태소 분리 + 약어 매칭)
3. 진단 결과에서 **즉시 일괄등록**
4. 비표준 컬럼은 **[선택 컬럼 물리모델 변환]** 으로 후처리

**평가**: DataQ 압도적 우위. 자동 추천 엔진은 SMETA 가 따라잡기 어려운 차별화 포인트.

## 5. 로드맵 제안 (데이터 모델 관리 관점)

### Phase A — 거버넌스 기본 (입찰 최소 요건)

1. **주제영역 CRUD** (`TB_SUBJECT_AREA`) — 단순 계층
2. **엔터티 개념 분리** — 기존 `TB_DATA_MODEL_OBJ` 에 `entity_type` (논리/물리) 추가 또는 별도 테이블
3. **관계 객체 완성** — 53번 Phase 5b 후속, `TB_DATA_MODEL_CONSTRAINT` INSERT

### Phase B — DDL 완성

4. **CREATE 문 완전 생성** — 제약조건·FK·인덱스 포함
5. **도메인→물리 타입 매핑 테이블** (`TB_DOMAIN_PHYSICAL_TYPE`) — DBMS별
6. **변환 시 물리 타입 자동 결정** — `resolveAttrs` 확장

### Phase C — ERwin 연동 재설계

7. 기존 파서 살림 + 논리/물리 구분 저장
8. 메뉴 복구

### Phase D — 결재 강화

9. **다단계 결재선** — 공공기관 RFP 필수
10. **모델 변경 결재** — 현재는 표준만 결재 대상

## 6. 결론

53번 설계 구현으로 **데이터 입력·편집 UX 는 SMETA 와 동등 이상**으로 올라왔습니다. 특히 TSV 붙여넣기·빈 행 추가·선택 일괄 변환은 DataQ 고유 장점입니다.

단, **거버넌스 체계 (주제영역·엔터티 계층·다단계 결재·DDL 완전 생성)** 가 여전히 공공 조달 입찰의 탈락 사유가 될 수 있으므로 Phase A·B 를 우선 착수할 필요가 있습니다.

SMETA 를 기능 체크리스트로 100% 따라가기보다, **자동 표준화 추천 + 엑셀 감성 UX** 라는 DataQ 의 철학을 유지하면서 **최소 거버넌스 요건** 만 보강하는 방향을 권장합니다.
