## 0. 왜 재설계인가 + 입력 규모별 경로 분리

50번 Phase B가 제공하는 **모달 다이얼로그 + 한 행씩 변환** 흐름의 문제:

| 문제 | 현상 |
|---|---|
| 입력 속도 | 엑셀에서 설계안을 수십~수천 행으로 관리 중인데 한 행씩 모달 여닫는 건 너무 느림 |
| 변환 타이밍 | 용어사전 완비 상태에서 등록한다고 전제할 수 없음 — 등록 시점 강제 변환은 UX를 막음 |
| 비표준 알림 | `alert`/`swal` 팝업은 목록성 정보에 부적합. 어느 행이 왜 실패했는지 한눈에 못 봄 |
| 논리/물리 혼재 | 사용자가 편집 가능한 영역(논리)과 시스템이 채우는 영역(물리)이 한 그리드에 섞여 수정 권한이 헷갈림 |
| 대량 등록 | 그리드에 복붙해도 수백~수천 컬럼 짜리 기존 설계 엑셀은 현실적으로 그리드로 못 넣음 |

### 입력 규모별 경로 분리

| 규모 | 경로 | 근거 |
|---|---|---|
| **소량** (테이블 1~2개, 수십 컬럼) | **그리드 인라인 편집** + TSV 붙여넣기 | 가볍게 수정/추가하는 데 적합. 매번 엑셀 파일 만드는 것이 오히려 번거로움 |
| **대량** (수십 테이블, 수천 컬럼) | **엑셀 업로드** | 설계자가 이미 엑셀로 설계 관리 중. 양식만 맞추면 모델 통째로 한 방에 등록 |

두 경로는 동일 모델/테이블에 병행 가능. 업로드 후 남은 일부를 그리드에서 수정하는 식.

## 1. 변경 요약 (before → after)

| 항목 | 기존 (50번 Phase B) | 신규 (53번) |
|---|---|---|
| 컬럼 추가 진입점 | `[+ 컬럼 추가]` 버튼 → 모달 다이얼로그 | `[+ 컬럼 추가]` → 그리드 맨 아래 빈 행 추가 |

| 저장 단위 | 행 단위 (한 번에 한 컬럼) | **배치 저장** (수천 행 한 번에) |

# Part A. 그리드 인라인 편집 (소량 경로)

## 2. UX 플로우 — 그리드

### 2-1. 기본 경로 — 수동 입력

1. `[+ 컬럼 추가]` 클릭 → 그리드 맨 아래 **빈 행** 1줄 추가 (편집 가능)
2. 사용자가 행의 **논리 영역** 셀을 편집 (한글명·PK여부·NULL여부 등)
3. 원하는 만큼 행을 추가하며 입력
4. `[저장]` 버튼 클릭 → 신규/수정 행을 **배치로** 서버 저장
   - 이 시점 표준 변환 시도 없음
   - 물리 영역은 비거나 `TMP_COL_N` 임시값, `TERMS_STND_YN='N'`

### 2-2. 붙여넣기 경로 — 엑셀/TSV

1. 엑셀에서 여러 셀 Ctrl+C
2. 그리드 임의 셀에 포커스 + Ctrl+V
3. 탭(`\t`) / 개행(`\n`/`\r\n`)으로 split → 붙여넣기 시작 셀부터 **오른쪽·아래로 채움**
4. 시작 셀이 빈 행이면 필요한 만큼 빈 행 자동 추가
5. 붙여넣은 행은 "편집됨" 상태로 마킹
6. 저장은 2-1과 동일

### 2-3. 표준 변환 경로 — 그리드 상단 툴바

1. 그리드 좌측 **행 선택 체크박스** 활성화
2. 변환할 행 선택 (전체 선택 포함)
3. 상단 툴바 `[선택 컬럼 물리모델 변환]` 버튼 클릭
4. 서버 `POST /api/dm/resolveAttrs` 호출 — 51번 API 재사용
5. 응답을 그리드 **우측 물리 영역**에 즉시 반영
   - matched: 초록 배경, 물리명·타입·길이 채움, `TERMS_STND_YN='Y'`
   - unmatched: 빨간 배경 + 우측 "변환 불가 사유" 셀에 원인 표시
6. 변환 결과는 서버 쪽에서 UPDATE 처리되므로 별도 저장 버튼 불필요
7. `[비표준만 보기]` 토글로 실패 건만 필터링

### 2-4. 추가 트리거

- `[+ 빈 행 10개 추가]` — 복붙 편의용 (선택적)
- `[선택 행 삭제]` — 체크된 행 soft-delete
- `[비표준만 보기]` — `TERMS_STND_YN='N'` 필터

## 3. 그리드 컬럼 구성

좌(논리) / 우(물리)를 **시각적으로 구분**. Vuetify `v-data-table` custom header grouping 또는 배경색/굵은 border 구분선.

### 3-1. 선택 영역 (왼쪽 끝)
| 컬럼 | 타입 |
|---|---|
| ☐ 선택 | 체크박스 |
| 순번 | readonly (ATTR_ORD) |

### 3-2. 논리 영역 (편집 가능)
| 컬럼 | 타입 | 필수 |
|---|---|---|
| 한글명 | text | **Y** |
| 설명 | text |  |
| PK | checkbox |  |
| NULL 허용 | checkbox |  |
| 기본값 | text |  |
| FK | checkbox |  |
| 참조 테이블(한글) | autocomplete | FK=Y일 때 **Y** |
| 참조 컬럼(한글) | autocomplete | FK=Y일 때 **Y** |
| 삭제 규칙 | select (`CASCADE`/`SET NULL`/`NO ACTION`) | FK=Y면 기본 `NO ACTION` |

- 참조 테이블/컬럼 옵션은 **현재 모델의 기존 테이블/컬럼 + 같은 그리드 내 미저장 행** 포함
- 입력 중엔 느슨한 검증만, 저장 시점에 §6-6 2-pass로 엄격 검증

### 3-3. 물리 영역 (readonly — 변환 결과만)
| 컬럼 | 타입 | 비고 |
|---|---|---|
| 물리명 (ATTR_NM) | readonly | 변환 전엔 빈칸/임시값 |
| 데이터 타입 | readonly | 변환 결과 |
| 길이 | readonly | 변환 결과 |
| 소수점 | readonly | 변환 결과 |
| 표준여부 | 아이콘 | ✓(초록) / ✗(빨강) |

### 3-4. 변환 상태 영역 (오른쪽 끝, 신규)
| 컬럼 | 타입 | 비고 |
|---|---|---|
| 변환 불가 사유 | readonly text | 예: "용어사전에 '사용자명' 없음", "도메인 매핑 없음" |

### 3-5. 행 상태 시각화
- 신규 편집 중(미저장) 행: 연한 노란 배경
- 저장됨 + 표준: 기본 배경
- 저장됨 + 비표준: **연한 빨간 배경(#FFEBEE) + ⚠ 아이콘**

## 4. 붙여넣기 스펙

### 4-1. 파싱 규칙
- 구분자: 행 `\n`/`\r\n`, 열 `\t` (엑셀 기본 클립보드 포맷)
- 시작 셀 기준 오른쪽·아래로 채움
- **논리 영역 범위 벗어나면 잘라냄** (물리는 readonly)
- 빈 행에 붙여넣기 시 필요한 만큼 행 자동 생성
- 기존 셀 값은 덮어씀
- 체크박스 컬럼은 `Y/N`, `TRUE/FALSE`, `1/0`, `✓/빈칸` 모두 허용

### 4-2. 기술 선택지
| 방안 | 장점 | 단점 |
|---|---|---|
| A. `v-data-table` + `@paste` 리스너 직접 구현 | 기존 스택 유지, 의존성 없음 | 편집 포커스/range 처리 직접 구현 |
| B. 별도 그리드 라이브러리 (`ag-grid`/`handsontable`/`revogrid`) | 붙여넣기·셀 레인지·키보드 내비 내장 | 신규 의존성, 라이선스·번들 크기 검토 |

**1차 권장: 방안 A**. 붙여넣기 스펙이 명확(엑셀 TSV 한정)하고 컬럼 구성이 고정이라 커스텀 비용이 크지 않음.

### 4-3. 경계 조건
| 케이스 | 동작 |
|---|---|
| 헤더 행 포함 | 수동 제거. 추후 "헤더 무시" 체크박스 검토 |
| 1열만 | 시작 셀 컬럼부터 아래로만 채움 |
| 빈 셀 | 건너뜀 (기존 값 유지) |
| 너무 많은 행 (1000+) | **그리드가 아니라 엑셀 업로드 경로 사용 권장**. Part B 참고 |

# Part B. 엑셀 업로드 (대량 경로)

## 5. 진입점 & 업로드 단위

### 5-1. 화면별 업로드 (엑셀은 **시트 1개만** 사용)

테이블 화면과 컬럼 화면이 분리되어 있으므로 **각 화면이 자기 데이터만 받는다**. 시트간 조인이 없어 구조가 단순하고, 사용자가 작업 중인 화면 맥락 그대로 올릴 수 있음.

| 화면 | 업로드 범위 | 진입점 | 시트 |
|---|---|---|---|
| **테이블 목록** ([DSDatamodelStatusTable.vue](../q-center/vue/front/src/components/DSDatamodelStatusTable.vue)) | 현재 모델의 테이블 여러 개 | 테이블 그리드 툴바 `[엑셀 업로드]` | 시트 1개 (테이블만) |
| **컬럼 목록** ([DSDatamodelStatusColumn.vue](../q-center/vue/front/src/components/DSDatamodelStatusColumn.vue)) | 현재 모델 안 **여러 테이블의 컬럼을 한 번에** (엑셀의 `테이블명(한글)`로 그루핑) | 컬럼 그리드 툴바 `[엑셀 업로드]` | 시트 1개 (컬럼만, 테이블명 컬럼 포함) |

둘 다 옆에 **`[양식 다운로드]` 버튼** 배치 — 헤더 오타로 파싱 실패하는 흔한 문제 방지.

**전형적 흐름**:
1. 테이블 화면에서 `[엑셀 업로드]` → 모델 안 테이블 수십 개를 **한 파일**로 등록
2. 컬럼 화면으로 이동 → `[엑셀 업로드]` → 방금 등록된 여러 테이블의 수천 컬럼을 **한 파일**로 등록 (엑셀 각 행에 소속 테이블명 포함)
3. 그리드에서 `[선택 컬럼 물리모델 변환]` 한 번으로 전체 표준 변환

컬럼 화면에 "현재 선택된 테이블" 개념은 있지만, 업로드는 **선택된 테이블에 국한되지 않고** 모델 전체 대상 — 업로드 버튼 hover 시 "엑셀의 테이블명(한글) 기준으로 여러 테이블의 컬럼을 한꺼번에 등록합니다" 툴팁 표기.

### 5-2. 업로드 흐름 (공통)

```
[엑셀 선택] → 파싱 요청(preview) → 미리보기 모달 → [확인 & 저장](commit) → 저장 결과 요약
    ↓                ↓                      ↓                  ↓                    ↓
  .xlsx        서버에서 시트1 파싱        행별 에러·경고       서버 저장        "테이블 12개 저장"
  multipart    + 검증                     색상 표시            saveAttrs/OBJ     또는 "컬럼 340개 저장"
```

- **미리보기 단계 필수**: 수백~수천 행을 즉시 DB에 꽂으면 오탈자 복구가 어려움. 저장 전 사용자가 전체를 한 번 확인
- 미리보기 모달 안에서 **에러/경고 행은 빨간/노란 배경** (alert 금지)
- 저장은 **트랜잭션 1개** — 전부 성공 또는 전부 롤백

## 6. 엑셀 양식 스펙

### 6-0. 공통 원칙 (매우 중요)

- **시트 1개**만 사용. 파서는 첫 시트를 읽음. 시트명은 임의
- 헤더는 **1행 고정**. 설명/주석 행을 앞에 두지 말 것
- 헤더는 **한글** 기준 (1차). 영문 대응은 추후
- **물리명·데이터타입·길이·소수점·NULL허용·기본값은 엑셀·그리드 어디서도 받지 않는다 (수동 편집 전면 금지)**
  - 근거: 사용자가 물리명을 직접 채우면 용어사전과 불일치하는 비표준이 **그대로 들어옴**. 50번 §0 "물리명·데이터타입은 사용자가 작성하지 않는다" 원칙 위배
  - **논리명 → 물리명 변환 경로만 허용**. 이게 표준 체계가 의미 있는 유일한 방식
  - 이 값들은 업로드/추가 후 **[선택 컬럼 물리모델 변환]** 트리거로 한 번에 자동 결정 (51번 `resolveAttrs` API 사용)
  - 변환 실패 건만 비표준(`TERMS_STND_YN='N'`, `TMP_COL_N` 임시명)으로 남고, 그리드에서 빨간색으로 추적됨. 이 경우 **용어 등록 → 재변환**만 해결 경로
- 사용자가 양식 템플릿을 **반드시 내려받아** 사용하도록 유도. 헤더 오타 방지 + 허용 헤더 고정

### 6-1. 테이블 목록 양식 — 테이블 화면에서 업로드

**양식 파일명**: `dataq_tables_template.xlsx`
**헤더** (1행):

| 헤더 | 필수 | 비고 |
|---|---|---|
| 소유자 | **Y** | OBJ_OWNER. 동명 테이블을 OWNER별로 분리 저장하기 위한 **필수 검증 키**. 논리모델은 규약상의 가상 오너(예: `LOGICAL`) 사용 권장 |
| 테이블명(한글) | **Y** | OBJ_NM_KR. (소유자, 테이블명) 조합이 모델 내 유일 |
| 설명 | - | OBJ_DESC |

- **테이블 물리명은 받지 않음** — 저장 시 서버가 `TMP_TBL_N` 임시 부여
- 이 업로드는 **OBJ 등록만** 수행. 각 테이블의 컬럼은 컬럼 화면에서 별도 업로드
- 이미 존재하는 (소유자, 테이블명) 조합은 **스킵 + 경고** (수정은 UI에서 삭제 후 재업로드)

### 6-2. 컬럼 목록 양식 — 컬럼 화면에서 업로드 (여러 테이블 커버)

**양식 파일명**: `dataq_attrs_template.xlsx`
**헤더** (1행):

| 헤더 | 필수 | 비고 |
|---|---|---|
| 소유자 | **Y** | OBJ_OWNER. 다른 OWNER의 동명 테이블을 원천 차단하기 위한 **필수 검증 키**. 엑셀 1파일에 여러 OWNER 섞임 가능 |
| 테이블명(한글) | **Y** | 이 컬럼이 속한 테이블. **엑셀 한 파일에 여러 테이블 섞기 가능**. 파서는 (소유자, 테이블명)으로 그루핑 |
| 컬럼명(한글) | **Y** | ATTR_NM_KR |
| 컬럼 순서 | - | ATTR_ORD. 비우면 (소유자, 테이블명) 그룹 내 엑셀 등장 순서 |
| PK여부 | - | **`Y`만 인식**. 빈칸/`N`/`FALSE` 등 나머지는 전부 "PK 아님". 복합 PK는 여러 행에 `Y` |
| FK여부 | - | **`Y`만 인식**. `Y`면 아래 참조 3종 필수 |
| 참조 테이블(한글) | FK=Y면 **Y** | 같은 엑셀 파일 내에 있거나 현재 모델 DB에 기존재해야 함 |
| 참조 컬럼(한글) | FK=Y면 **Y** | 위 참조 테이블의 컬럼 |
| 삭제 규칙 | - | `CASCADE` / `SET NULL` / `NO ACTION`. 비우면 `NO ACTION` |

- **컬럼 물리명·데이터타입·길이·소수점·NULL허용·기본값은 받지 않음** (§6-0 참고)
- NULL 허용 기본값: PK면 `N`, 아니면 `Y` (후처리 자동)
- 엑셀의 (소유자, 테이블명) 조합이 **현재 모델(dataModelId)에 존재하거나 같은 파일 내 테이블 양식에 있어야** 함
- 이미 존재하는 (소유자, 테이블명, 컬럼명) 조합은 **스킵 + 경고**
- FK 제약명(`CONSTRAINT_NM`)은 서버가 `FK_{테이블}_{컬럼}` 형식으로 자동 생성 — 사용자 입력 없음
- 업로드 성공 후: 자동 변환이 아직 안 된 상태. 그리드에서 **[선택 컬럼 물리모델 변환]** 한 번으로 전체 변환 권장

### 6-3. 파싱 규칙

- **첫 번째 시트만** 읽음. 2번째 이후는 무시 + 상단 안내
- 헤더는 **1행 고정**. 빈 행/설명 행 앞에 금지
- 빈 행은 건너뜀
- PK여부는 **대소문자 무시 `Y`만** 인식 (엄격). `1/TRUE/✓` 등 다른 표기는 경고 후 "PK 아님" 처리 (명확성 우선)
- 숫자 셀(컬럼 순서)이 문자열이면 숫자 파싱 시도. 실패 시 경고 → `null`
- 최대 행: 1차 제한 없음. 메모리 이슈 나면 chunk 처리 도입

### 6-4. 검증 룰

| 룰 | 레벨 | 동작 |
|---|---|---|
| 필수 소유자/한글명(테이블·컬럼) 비어있음 | 에러 | 해당 행 스킵 |
| 테이블 양식: (소유자, 테이블명) 조합 시트 내 중복 | 에러 | 해당 행들 에러 마킹 |
| 컬럼 양식: (소유자, 테이블명, 컬럼명) 조합 시트 내 중복 | 에러 | 해당 행들 에러 마킹 |
| 컬럼 양식: (소유자, 테이블명) 조합이 DB·같은 파일 양쪽에 없음 | 에러 | "테이블 먼저 등록 필요" 메시지 |
| 컬럼 양식: 엑셀 소유자와 DB 내 동명 테이블의 OWNER 불일치 | 에러 | "소유자 불일치로 저장 불가" 메시지 |
| FK=Y인데 참조 테이블/참조 컬럼 누락 | 에러 | 해당 행 스킵 |
| FK 참조 테이블·컬럼이 DB·같은 파일 양쪽에 없음 | 에러 | "참조 대상 없음" 메시지 |
| FK 삭제 규칙 값이 허용 외 | 경고 | `NO ACTION`으로 치환 |
| DB에 이미 존재하는 조합 | 경고 | 기본 스킵. 미리보기에서 노랑 |
| PK/FK여부가 `Y` 외 의미있는 값 | 경고 | `N` 처리 + "Y만 인식" 안내 |
| 컬럼 순서 숫자 아님 | 경고 | `null`로 치환 후 저장 (등장 순서 기반 자동) |
| 2번째 이후 시트에 데이터 있음 | 경고 | 무시. 미리보기 상단 안내 |

> FK 참조 검증은 **행 단위 삽입 순서와 무관** — §6-6 "FK 2단계 저장" 참고.

### 6-5. 업로드 후 흐름 — 기존 **표준 진단** 메뉴 재활용 (확정)

§12 미결이던 "표준 미일치 처리 방향"은 **안A(표준 진단 메뉴 유도)**로 확정 — 업로드 전용 비표준 리스트 화면을 새로 만들지 않고, 이미 운영 중인 표준 진단 파이프라인을 그대로 쓴다.

**근거**:
- 기존 `TB_DIAG_JOB`/`TB_DIAG_RESULT` + 진단 준수율 계산식(CLAUDE.md)과 그대로 통합됨
- 대시보드 준수율이 업로드 직후 자연스럽게 반영됨
- 새 화면 개발·테스트 비용 제거

**연계 대상**:
- 프론트 화면: [DSDataDiag.vue](../q-center/vue/front/src/components/DSDataDiag.vue) (진단 실행) / [DSDataDiagResult.vue](../q-center/vue/front/src/components/DSDataDiagResult.vue) (진단 결과/이슈 리스트)
- 백엔드 Worker: [q-executor/.../service/std/DiagService.java](../q-executor/src/main/java/qualityexecutor/service/std/DiagService.java) / [DataStandardService.java](../q-executor/src/main/java/qualityexecutor/service/std/DataStandardService.java)

**흐름**:
1. 컬럼 업로드 commit 완료 → 전부 비표준(`TERMS_STND_YN='N'`, `TMP_COL_N`, `VARCHAR(255)`)으로 저장
2. 저장 결과 토스트에 **`[표준 진단 보기]` CTA** — 클릭 시 현재 데이터모델을 컨텍스트로 **기존 표준 진단 화면으로 이동** (deep link: `dataModelId` 쿼리/props)
3. 사용자는 기존 진단 화면에서:
   - 진단 Job 실행(또는 업로드 commit 시 서버가 자동 Job 큐잉 — 세부는 Phase 5에서 결정)
   - 이슈 리스트 확인 (비표준 컬럼 한 건씩 원인 표시)
   - 필요한 **용어/도메인 등록** → 승인
4. 용어 등록 후 컬럼 그리드로 돌아와 **`[선택 컬럼 물리모델 변환]`** 으로 `resolveAttrs` 호출 → 매칭된 컬럼만 표준으로 업데이트
5. 재진단으로 준수율 확인 (선택)

**업로드 직후 진단 Job 자동 큐잉은 하지 않는다 (확정)**: 진단은 **필수 프로세스가 아님** — 사용자가 필요할 때 진단 화면에서 실행하면 됨. 자동 큐잉은 사용자에게 불필요한 부하만 남기고 정작 필요하지 않을 때 리소스를 태움. `[표준 진단 보기]` **CTA 딥링크로 자연스러운 연계**만 제공.

### 6-6. FK 2단계 저장 (순서 무관 처리)

FK는 **참조 테이블·컬럼이 같은 업로드 파일 내에 있을 수도 있고 DB에 기존재할 수도 있음**. 엑셀 행 순서를 신경 쓰지 않아도 되도록 **서버에서 2-pass 처리**:

| Pass | 대상 | 동작 |
|---|---|---|
| **Pass 1** | OBJ / ATTR | 파싱·검증한 모든 테이블/컬럼을 insert. CONSTRAINT는 건드리지 않음 |
| **Pass 2** | CONSTRAINT | FK=Y 행만 모아 참조 대상 검증 후 TB_DATA_MODEL_CONSTRAINT insert. 이 시점엔 Pass 1에서 방금 올린 테이블도 DB에 있으므로 "파일 내 참조"도 자동 해결 |

**Pass 2 참조 검증**:
- 같은 파일 또는 이미 DB에 있는 (소유자, 테이블명, 컬럼명) 조합이면 통과
- 복합 FK(참조 컬럼 여러 개)는 `CONSTRAINT_NM` 단위로 묶어서 저장 — 서버가 자동 부여
- `REF_TABLE_NM` / `REF_COLUMN_NM` 은 Pass 1에서 확정된 **물리명**을 조회해 저장 (엑셀은 한글명만 받으므로 한글→물리 매핑 후 기록)

**트랜잭션**: Pass 1 + Pass 2 모두 **단일 트랜잭션**. Pass 2에서 에러 발생 시 Pass 1까지 롤백해 "절반만 저장된 상태" 방지.

**그리드 인라인 편집 시 FK**:
- 참조 테이블/참조 컬럼은 autocomplete. 옵션은 현재 모델의 기존 테이블/컬럼 + **미저장 행 포함**
- 입력 중에는 검증하지 않음 (미저장 행 참조 허용). 저장 버튼 클릭 시 동일 2-pass로 검증
- 유효하지 않은 참조가 있으면 미리보기/인라인 메시지로 행별 표시 (alert 금지)

**활용 컴포넌트**: [DdlGenerator.java:182-211](../q-center/src/main/java/qualitycenter/service/ddl/DdlGenerator.java#L182)의 constraint 저장/읽기 구조를 그대로 활용 — `CONSTRAINT_TYPE='R'`, `REF_TABLE_NM`, `REF_COLUMN_NM`, `DELETE_RULE` 컬럼 재사용.

## 7. 백엔드 영향

### 7-1. 기존 엔드포인트 상태
- `POST /api/dm/addAttr` / `updateAttr` / `deleteAttr` — 단건. **유지**, `saveAttrs`의 헬퍼로 재사용
- `POST /api/dm/resolveAttrs` (51번) — **그대로 사용**

### 7-2. 신규 엔드포인트

#### (1) `POST /api/dm/saveAttrs` — 그리드 배치 저장
요청:
```json
{
  "dataModelId": "...",
  "objNm": "TMP_TBL_1",
  "attrs": [
    { "mode": "ADD",    "attrNmKr": "사용자명", "pkYn": "N", "nullableYn": "Y" },
    { "mode": "UPDATE", "attrNm": "CUST_NM", "attrNmKr": "고객명", "pkYn": "Y" },
    { "mode": "DELETE", "attrNm": "TMP_COL_3" }
  ]
}
```
- mode별 기존 단건 헬퍼 반복 호출
- **트랜잭션 1개**로 묶음. 전부 성공/전부 롤백
- 응답: `{ "saved": 3, "added": 1, "updated": 1, "deleted": 1, "attrs": [...최신 attrs] }`

#### (2) `POST /api/dm/uploadTables` — 테이블 목록 엑셀 파싱 + 저장
- `multipart/form-data`: `file` (xlsx), `dataModelId`, `mode` (`preview` | `commit`)
- `mode=preview`: 저장하지 않고 파싱 + 검증 결과만 반환
- `mode=commit`: 실제 저장 (OBJ insert, 필요 시 `TMP_TBL_N` 자동 부여)
- 파서는 **첫 시트만** 사용
- 응답:
```json
{
  "tables": [{ "objNmKr":"고객정보", "objNm":"TMP_TBL_1", "warnings":[] }, ...],
  "errors":   [{ "row":5,  "message":"한글명이 비어있음" }],
  "warnings": [{ "row":12, "message":"이미 존재하는 한글명 '주문' — 스킵" }],
  "summary": { "total":15, "toInsert":12, "skipped":3 }
}
```

#### (3) `POST /api/dm/uploadAttrs` — 컬럼 목록 엑셀 파싱 + 저장 (여러 테이블 커버)
- `multipart/form-data`: `file`, `dataModelId`, `mode`
- **`objNm` 파라미터 없음** — 대상 테이블은 엑셀의 (소유자, 테이블명) 조합으로 결정
- 파서는 **첫 시트만** 사용. 행을 (소유자, 테이블명)으로 그루핑
- 서버 저장은 **2-pass**로 수행 (§6-6 참고):
  - Pass 1: 각 그룹을 대상 테이블별 `saveAttrs` mode=ADD 배치로 변환해 ATTR insert
  - Pass 2: FK=Y 행을 모아 `TB_DATA_MODEL_CONSTRAINT` insert (REF는 한글→물리 매핑 후 저장)
- 저장되는 ATTR 값은 **최소**: `OBJ_OWNER`, `OBJ_NM_KR`, `ATTR_NM_KR`, `ATTR_ORD`, `PK_YN`, `FK_YN`, `NULLABLE_YN`(PK면 N, 아니면 Y), `TERMS_STND_YN='N'`, 임시 `ATTR_NM=TMP_COL_N`, 기본 `DATA_TYPE='VARCHAR'` / `DATA_LEN=255`
- CONSTRAINT 값: `CONSTRAINT_TYPE='R'`, `CONSTRAINT_NM=FK_{테이블}_{컬럼}` 자동, `REF_TABLE_NM`/`REF_COLUMN_NM`/`DELETE_RULE`
- Pass 1 + Pass 2는 **단일 트랜잭션**
- 응답:
```json
{
  "attrs": [{"objOwner":"LOGICAL","objNmKr":"고객정보","attrNmKr":"고객명","attrNm":"TMP_COL_7"}, ...],
  "constraints": [{"constraintNm":"FK_주문_고객ID","refTableNm":"TMP_TBL_3","refColumnNm":"TMP_COL_1"}, ...],
  "errors":   [{"row":23, "message":"(LOGICAL, 주문) 조합이 모델과 파일 양쪽에 없음"}],
  "warnings": [{"row":11, "message":"PK여부 '1' 은 Y만 인식됨 — PK 아님으로 처리"}],
  "summary": { "total":340, "toInsertAttrs":335, "toInsertFks":18, "skipped":5, "groups":12 }
}
```

#### (4) `GET /api/dm/uploadTemplate?scope=tables|attrs`
- 서버에서 양식 xlsx를 스트리밍 다운로드
- `resources/templates/` 아래 고정 템플릿 2종 (`dataq_tables_template.xlsx`, `dataq_attrs_template.xlsx`)

### 7-3. 엑셀 파싱 라이브러리 + 용량 상한

- **Apache POI** 사용 (JDK 8 호환, Spring Boot 2.7 환경에서 검증된 선택)
- Maven 의존성 추가 필요 여부는 q-common/q-center `pom.xml` 검토 후 확정 (Phase 5 착수 시 1분 작업)
- **xlsx만 지원**. xls/xlsm/xlsb는 거부 (수용 시 변환 이슈·매크로 보안 이슈 피함)

**업로드 용량·행 상한** (결정):
- 엑셀 파일 크기: 최대 **20MB**
- 엑셀 행 수: 최대 **20,000행** (테이블·컬럼 공통)
- 근거: 실제 설계 파일은 아무리 커도 수천~2만 컬럼 수준. 2만 행이면 xlsx 통상 5~8MB. 20MB는 편집용 서식 포함한 여유값
- Spring 설정: `spring.servlet.multipart.max-file-size=20MB`, `spring.servlet.multipart.max-request-size=25MB`
- 상한 초과 시 업로드 버튼 클릭 직후 프론트에서 **사전 차단** — 서버 왕복 없이 에러 메시지 (alert 금지, 인라인 배너)

**그리드 인라인 편집 상한**:
- 한 화면당 **100행**까지 추가 허용
- 초과 시 `[+ 컬럼 추가]` 버튼 비활성 + "100건을 초과하는 대량 입력은 엑셀 업로드를 사용하세요" 인라인 안내

- `<input type="file" accept=".xlsx">` 숨김 + 버튼 클릭 시 open
- 미리보기 모달 컴포넌트는 공통으로 만들고 scope만 props로 받는 구조

### 8-2. 미리보기 모달
- v-dialog + v-data-table (또는 스트리밍 큰 리스트용 `v-virtual-scroll`)
- 탭: `요약` / `테이블 목록` / `컬럼 목록` / `에러·경고`
- `요약`: "12개 테이블, 340개 컬럼. 에러 2건, 경고 5건"
- `에러·경고`: 행 클릭 시 해당 위치로 스크롤
- `[확인 & 저장]` 버튼은 **에러가 0건일 때만 활성**. 경고는 무시하고 진행 가능
- `[취소]` 버튼

### 8-2-A. 미리보기 모달 탭 구성 (화면별)
- **테이블 목록 업로드**: `요약` / `테이블 목록` / `에러·경고`
- **컬럼 목록 업로드**: `요약` / `컬럼 목록` / `에러·경고`
- `[확인 & 저장]` 버튼은 **에러 0건**일 때만 활성. 경고는 무시하고 진행 가능

### 8-3. 저장 후
- 결과 토스트/배너:
  - 테이블 업로드 완료 시: "테이블 12개 저장 완료 (스킵 3건)"
  - 컬럼 업로드 완료 시: "테이블 12개에 컬럼 340개 저장 완료 (스킵 5건)"
- 화면 자동 갱신 (해당 그리드 refresh)
- **저장 직후 컬럼은 전부 비표준 상태** (물리명 `TMP_COL_N`, `TERMS_STND_YN='N'`) — §6-0 원칙
- 토스트 옆 **`[표준 진단 보기]` CTA** 제공 → 기존 표준 진단 화면([DSDataDiag.vue](../q-center/vue/front/src/components/DSDataDiag.vue))으로 `dataModelId`를 컨텍스트로 넘겨 딥링크
- 사용자는 진단 화면에서 이슈 확인 → 용어/도메인 등록 → 그리드로 돌아와 `[선택 컬럼 물리모델 변환]`으로 `resolveAttrs` 일괄 호출
- 그리드에서 비표준 행은 빨간색으로 남고, 언제든 재시도 가능
