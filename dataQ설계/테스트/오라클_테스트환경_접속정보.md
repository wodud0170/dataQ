# Oracle 테스트 환경 접속 정보

**최종 수정일**: 2026-04-19

## Docker 컨테이너

| 항목 | 값 |
|------|-----|
| 이미지 | gvenzl/oracle-xe:21-slim-faststart |
| 컨테이너명 | oracle-xe |
| 포트 | 1521 (호스트) → 1521 (컨테이너) |
| 접속방식 | **Service Name** |
| Service Name (PDB) | XEPDB1 |
| SID (CDB) | XE |
| 구조 | CDB + PDB (XEPDB1) |
| Character Set | **AL32UTF8** (UTF-8, 한글 저장 가능) |

> 이전 이미지(doctorkirk/oracle-19c)는 DB character set이 WE8MSWIN1252로 고정되어 한글 저장이 불가능했음. AL32UTF8 지원 이미지로 교체함.

## 의도적 오류 요약 (진단 오류율 확인용)

- 비표준 약어: GOODS_ID, GOODS_NAME, PRICE, REG_DATE, START_DATE, END_DATE, PHONE_NUMBER, HIRE_DATE
- 테이블 접두어 누락: COMPANY_INFO, DELIVERY_LOG
- 풀네임 컬럼: COMPANY_ID, COMPANY_NAME, CEO_NAME, ADDRESS, TELEPHONE, DELIVERY_ID, ORDER_NO, DELIVERY_DATE, CUSTOMER_NAME, DELIVERY_ADDR, STATUS

## DataQ 데이터소스 등록

1. 관리 > 데이터 소스 > 추가
2. DBMS: Oracle, 접속방식: **Service Name** (이전 'SID' 아님!)
3. 호스트: localhost, 포트: 1521, Service Name: XEPDB1
4. 계정: TESTUSER / test123
5. 데이터 모델 등록 시 스키마 선택: SALES_APP, HRM_APP, INV_APP

## 초기화 / 재생성 절차

```bash
# 기존 컨테이너 제거
docker stop oracle-xe && docker rm oracle-xe

# 새 컨테이너 기동 (AL32UTF8 기본)
docker run -d --name oracle-xe -p 1521:1521 \
  -e ORACLE_PASSWORD=oracle \
  gvenzl/oracle-xe:21-slim-faststart

# 기동 완료 대기 (healthy 까지 약 1~2분)
docker logs -f oracle-xe

# 초기화 SQL 적재
docker cp dataQ설계/테스트/init_oracle_testdb.sql oracle-xe:/tmp/
docker exec -it oracle-xe bash -c \
  "NLS_LANG=AMERICAN_AMERICA.AL32UTF8 sqlplus -s 'sys/oracle@localhost:1521/XE as sysdba' @/tmp/init_oracle_testdb.sql"
```
