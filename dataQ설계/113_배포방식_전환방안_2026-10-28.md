## 0. 요약

- 배포물을 **OS별 설치 패키지**(Windows 설치 프로그램, Linux tar.gz·rpm)로 바꾼다. JRE·JDBC 드라이버를 넣어 고객 서버에 Java·Docker 를 따로 깔지 않는다.
- 두 서버(q-center·q-executor)는 **OS 서비스**로 등록해 부팅 때 자동 기동한다. 설정은 jar 밖 `conf/` 에, 로그는 `logs/` 에 둔다.
- 메타 저장소는 **고객 PostgreSQL 을 기본**으로 하고, 필요하면 패키지에 PostgreSQL 을 같이 넣는 선택지를 둔다. 스키마는 **기동 때 자동 생성·업그레이드**(Flyway)로 바꿔, 지금의 DB 스냅샷 이미지와 손으로 돌리는 sync SQL 을 없앤다.
- 첫 실행 때 웹 화면에서 DB 접속·관리자 생성·라이선스를 설정한다.
- Docker 이미지는 **선택 배포물로 남긴다**(설치판과 이미지를 같이 내는 도구가 많다).
- 공수 **31~49인일**(두 서버 유지). 한 프로세스로 합치면 +10~15인일.

## 1. 지금 배포 방식

| 항목 | 지금 | 문제 |
|---|---|---|
| 배포물 | `docker save` 로 만든 이미지 tar → 고객 서버에서 `docker load` → `docker-compose.deploy.yml` 로 3개 컨테이너 기동 | 고객 서버에 Docker 가 있어야 한다. 기관 서버 정책상 Docker 를 못 쓰면 배포할 방법이 없다 |
| DB | `docker/dataq-db/Dockerfile` — timescaledb pg13 이미지에 **개발 DB 의 PGDATA 스냅샷**을 그대로 넣음 | 개발·시험 데이터가 같이 나간다. PostgreSQL 13 은 지원 종료. 고객 DB 를 쓸 수 없다 |
| 스키마 변경 | `dataQ설계/sync/PC_align_*.sql` 를 사람이 순서대로 실행 | 버전마다 어떤 스크립트를 돌렸는지 고객 쪽에서 추적하기 어렵다 |
| 설정 | `application.properties` 가 jar 안. 로그 경로 `c:/temp/logs` 고정, 컨테이너는 환경 변수로 덮어씀 | 설치 위치마다 다시 빌드하거나 환경 변수를 맞춰야 한다 |
| 실행 위치 의존 | `ND_HOME`, `lib/drivers.xml`·`lib/jdbc/` 를 작업 폴더 기준으로 찾음 | 서비스로 띄우면 작업 폴더가 달라져 드라이버를 못 찾는다 |
| 비밀값 | compose 환경 변수·Dockerfile 에 DB 비밀번호. q-executor 는 jasypt `ENC()` 인데 키가 공용 jar 상수(110번 1.10) | **공개 저장소의 Dockerfile 에 DB 비밀번호가 들어 있다** — 그 비밀번호를 쓰는 환경은 바꿔야 한다 |
| 개발 PC | `build.bat`(포트 정리 → mvn → 3창 기동) | 배포와 무관하지만 PC2 는 옛 jar 를 띄움(107번) |

## 2. 바꿀 모습

### 2.1 설치 폴더

```
NavidM-Meta/                     (예: C:\NavidM-Meta, /opt/navidm-meta)
├─ bin/        start·stop·status, 서비스 등록·해제 스크립트
├─ conf/       application.yml (포트·DB 접속·로그·저장 경로), logback.xml
├─ jre/        jlink 로 만든 전용 JRE (버전 고정)
├─ lib/        q-center.jar, q-executor.jar, common jar
├─ jdbc/       DBMS 드라이버 + drivers.xml
├─ logs/       일자별 로그
├─ data/       업로드·내려받기 임시 파일, (비정형 도입 시) 파생물
└─ backup/     업그레이드 전 자동 백업
```

- 경로는 모두 **설치 폴더 기준**으로 바꾼다(`ND_HOME` = 설치 폴더, 작업 폴더 의존 제거).
- 비밀번호는 설치 때 입력받아 **설치마다 새로 만든 키**로 암호화해 `conf/` 에 저장한다.

### 2.2 배포물

| OS | 배포물 | 서비스 |
|---|---|---|
| Windows Server | 설치 프로그램(.exe 또는 .msi — jpackage 또는 Inno Setup) | Windows 서비스(WinSW 또는 Apache Commons Daemon) |
| Linux (RHEL·Rocky 계열 등) | tar.gz + 설치 스크립트, 필요하면 rpm | systemd 유닛 |
| 공통 | 폐쇄망용 오프라인 패키지 하나(외부 다운로드 없음), 무결성 해시 | — |
| 선택 | Docker 이미지 + compose (DB 스냅샷 없이 빈 DB 에서 자동 생성) | — |

JDBC 드라이버(Oracle·SQL Server·MariaDB·Cubrid 등)는 재배포 라이선스를 드라이버마다 확인해 넣을지, 고객이 `jdbc/` 에 넣게 할지 정한다.

### 2.3 메타 저장소 DB

- **기본**: 고객이 준비한 PostgreSQL(16 이상)에 접속 정보만 넣는다.
- **선택**: 패키지에 PostgreSQL 을 포함해 설치 프로그램이 같이 설치·서비스 등록(작은 기관·시범용).
- **스키마 자동 관리(Flyway)**: 기동 때 비어 있으면 생성, 이전 버전이면 순서대로 업그레이드, 시드(기본 사용자·룰 카탈로그·단어사전)도 같이. 적용 이력이 DB 의 이력 테이블에 남는다.
  - 지금 CLAUDE.md 의 **DDL 단일 진실 정책**(pg_dump 덤프 + 변경이력 + sync 스크립트)을 "Flyway 마이그레이션 파일이 진실, 덤프는 확인용" 으로 바꾸는 일이다 — **정책 변경이라 승인이 필요하다.**
  - 첫 마이그레이션은 지금 스키마(`docker/dataq-db/initdb/01_schema.sql`)를 기준선으로 쓴다.

### 2.4 첫 실행·운영

- **첫 실행 설정 화면**: DB 접속 확인 → 스키마 생성 → 내장 관리자 생성(지금 있는 "관리자가 없을 때만 생성" 기능) → 라이선스 입력(의존성 `license3j` 는 있으나 코드에서 쓰지 않음 — 검증 로직 필요).
- **상태 확인**: `bin/status`, 웹의 시스템 정보(버전·DB 버전·스키마 버전·q-executor 연결 상태).
- **업그레이드**: 새 버전 설치 프로그램을 같은 폴더에 실행 → `conf/`·`data/` 보존 → DB 자동 백업(`pg_dump` → `backup/`) → 서비스 재기동 → Flyway 업그레이드. 실패하면 백업으로 되돌리는 절차를 매뉴얼에.
- **로그**: `logs/` 일자별 롤링·보관 일수 설정.

### 2.5 프로세스 구성

- **1차 (권장)**: 두 서버를 그대로 두고 설치 프로그램 하나가 두 서비스를 같이 등록한다. 코드 변경이 가장 적다.
- **2차 (선택)**: q-executor 를 q-center 안에 모듈로 넣어 **서비스 하나**로. 일반적인 도구처럼 프로세스가 하나가 되지만, 지금 두 서버 사이 HTTP 호출·STOMP 연결(109번 #6 때 확인한 경로)을 내부 호출로 바꿔야 한다. 대규모 수집만 실행기를 따로 띄우는 옵션을 남긴다.

## 4. 시점

- 배포 전환은 화면·백엔드 갱신(112번)과 **따로 할 수 있다.** 설정 외부화·Flyway·설치 프로그램은 갱신 뒤에도 그대로 쓴다.
- JRE 를 패키지에 넣으므로, Spring Boot 3·Java 17 이전 뒤에 하면 JRE 를 한 번만 바꾸면 된다. 먼저 하면 지금 Java(컴파일 1.8, 실행 11)로 만들고 갱신 때 JRE 만 바꾼다.
- 권장: **1~2(설정 외부화·Flyway)를 먼저** — 지금 배포에도 바로 도움이 되고, 이후 갱신·비정형 작업의 DB 변경도 이 방식으로 관리된다. 3~7 은 다음 고객 배포 일정에 맞춘다.

## 5. 결정이 필요한 것

| 항목 | 선택지 | 권장 |
|---|---|---|
| 대상 OS | Windows Server / Linux / 둘 다 | 둘 다(고객 기관에 따라 다름) |
| 메타 저장소 | 고객 PostgreSQL 만 / PostgreSQL 포함 선택지 | 고객 PostgreSQL 기본 + 포함 선택지 |

| Docker 이미지 | 없앰 / 선택 배포물로 유지 | 유지(빈 DB 자동 생성으로) |
| JDBC 드라이버 | 패키지에 포함 / 고객이 넣음 | 라이선스 확인 뒤 드라이버별로 |
