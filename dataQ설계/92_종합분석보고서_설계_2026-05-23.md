# 종합 분석 보고서 출력 — 기획 설계 (2026-05-23)

> 이전 설계: [23_데이터모델_리포트_설계.md](23_데이터모델_리포트_설계.md) (2026-04-02), [37_분석보고서출력_설계.md](37_분석보고서출력_설계.md) (2026-04-13)
> 두 문서는 표준화/구조 진단 결과 중심. 본 문서는 범위를 확장 — **DBA + 개발자 모두에게 유용한 데이터 모델 종합 점검 보고서**.
> 23/37 의 핵심 섹션은 본 문서의 일부 시트로 흡수.

---

## 1. 개요

### 1-1. 목적

데이터 모델의 모든 메타·표준화·구조·변경 정보를 **단일 xlsx 파일에 여러 시트로** 출력. 사용자는 시트별로 골라서 검토하거나, 외부 보고/감사 자료로 그대로 활용.

### 1-2. 대상 사용자

| 사용자 | 활용 시나리오 |
|---|---|
| **DBA** | PK 누락·FK 인덱스 누락·큰 테이블 등 운영 점검표 / 신규 모델 인수 시 구조 검토 |
| **개발자** | 컬럼 명세서·DDL·FK 관계·표준 준수 여부 / 신규 기능 개발 전 사전 조사 |
| **표준화 담당자** | 표준 미준수 컬럼·미등재 단어·승인 대기 현황 |
| **품질 담당자** | 진단 결과 추이·이슈 분포 |
| **경영진/감사** | 종합 준수율·변경 활동 요약 |

### 1-3. 차별점 (23/37 대비)

| 항목 | 23/37 | 본 설계 |
|---|---|---|
| 시트 수 | 4~6 | **~20** (필요 시 선택) |
| 영역 | 표준화 + 구조 진단 | + **DBA 점검** + **거버넌스** + **DDL** + **품질** |
| 출력 형식 | 화면+PDF+Excel | **xlsx 단일** (다중 시트). PDF 는 옵션 |
| 프리셋 | 없음 | **5종 프리셋** (전체/DBA/표준화/거버넌스/품질) + 커스텀 |
| 시각화 | 차트 (게이지·파이) | xlsx 의 내장 차트 + 색상 코딩 + 조건부 서식 |

## 2. 메뉴 위치

```
분석                                ← 신규 대메뉴 (37번과 동일)
  └─ 종합 분석 보고서
```

아이콘 후보: `mdi-file-chart` 또는 `mdi-clipboard-text-search`

**왜 신규 대메뉴인가**
- 기존 메뉴는 관리·실행 용도 (등록·진단 등)
- 보고서는 **조회·출력** 성격이라 분리
- 향후 다른 보고서 (표준 사전 보고서, 사용자 활동 보고서 등) 확장 가능

## 3. 시트 구성

기본 구성 = 약 20 시트, **선택형** 출력. 카테고리 6개 (A~F).

### 3-A. 모델 개요 (필수)

| 시트 | 내용 | 데이터 소스 |
|---|---|---|
| **A1. 표지·요약** | 모델명·시스템·DBMS·데이터소스·수집일·테이블/컬럼/인덱스/제약 수·표준 준수율·최종 진단일 | TB_DATA_MODEL + 집계 |
| **A2. 테이블 목록** | 소유자·테이블명·한글명·업무영역·컬럼수·인덱스수·코멘트·tablespace·BIZ_AREA | TB_DATA_MODEL_OBJ |

### 3-B. 구조 메타 (전수)

| 시트 | 내용 |
|---|---|
| **B1. 컬럼 전수** | 테이블·컬럼·한글·타입·길이·소수점·PK·FK·NULL·기본값·코멘트·표준여부·매칭단어·매칭용어·도메인 |
| **B2. 인덱스** | 테이블·인덱스명·유형(BTREE/UNIQUE)·고유여부·컬럼순서 |
| **B3. 제약조건** | 종류(PK/FK/UQ/CK)·이름·참조 테이블·참조 컬럼·삭제규칙·갱신규칙 |
| **B4. FK 관계** | 부모 테이블·자식 테이블·매핑 컬럼·참조 무결성 (그래프 표) |

### 3-C. 표준화 현황

| 시트 | 내용 |
|---|---|
| **C1. 표준 준수율** | 전체 + 테이블별 준수율 (이슈 컬럼수 / 전체 컬럼수), 막대그래프 |
| **C2. 비표준 컬럼** | 이슈 유형별 (용어 미존재 / 한글명 불일치 / 타입 불일치 / 길이 불일치) 전수 + 추천 용어 |
| **C3. 미등재 단어** | 스키마 토큰 중 TB_WORD 에 없는 토큰 + 등장 컬럼 수 + 추천 등록 |
| **C4. 누락 메타** | 한글명 누락·코멘트 누락·도메인 미적용 컬럼 |

### 3-D. ★ DBA 점검 (DBA 가치 최대)

| 시트 | 내용 | 점검 의미 |
|---|---|---|
| **D1. PK 없는 테이블** | PK 미정의 테이블 목록 | DBA 즉시 조치 — 무결성 위험 |
| **D2. FK 인덱스 누락** | FK 컬럼인데 인덱스 없는 것 | 조인 성능 위험 |
| **D3. 동일 한글·영문 충돌** | 같은 한글명이 여러 영문 토큰으로 (또는 그 역) | 명명 일관성 |
| **D4. 큰 테이블/긴 컬럼** | 컬럼 100+ 테이블, LONG/CLOB/4000 컬럼 | 성능·정규화 검토 |
| **D5. 이름 규칙 위반** | snake_case 깨짐, 30자 초과, 예약어 충돌 | 표준 위반 |
| **D6. 데이터 타입 분포** | 타입별 사용 빈도 (VARCHAR2 78%, NUMBER 15%...) | 일관성 점검 |
| **D7. NULL 허용 PK/FK** | 논리적으로 NULL 불가인데 NULL 허용 | 무결성 위험 |

### 3-E. 변경 / 거버넌스

| 시트 | 내용 |
|---|---|
| **E1. 최근 변경 컬럼** | 최근 N일 (기본 30일) 추가·수정·삭제 컬럼 (88번 거버넌스 변경이력) |
| **E2. 승인 대기** | DRAFT/REQUESTED 상태 컬럼·테이블 (변경 거버넌스) |
| **E3. 변경 활동 요약** | 사용자별·테이블별 변경 건수 통계 |

### 3-F. 진단 결과

| 시트 | 내용 |
|---|---|
| **F1. 표준화 진단 최신** | 가장 최근 TB_DIAG_JOB 의 결과 요약 |
| **F2. 구조 변경 진단** | 마지막 구조 진단 (TB_STRUCT_DIAG_HISTORY/DETAIL) — DDL 차이 |
| **F3. 데이터 품질 진단** | TB_QUAL_RESULT (도메인 룰·업무 규칙 위반) |

### 3-G. DDL (옵션)

| 시트 | 내용 |
|---|---|
| **G1. DDL 출력** | CREATE TABLE + INDEX + CONSTRAINT 통합 스크립트 (현재 DdlGenerator 활용) |

## 4. 프리셋 & 커스터마이즈

### 4-1. 5 프리셋

| 프리셋 | 포함 시트 | 사용 시나리오 |
|---|---|---|
| **전체 종합** | A·B·C·D·E·F·G (전부) | 신규 모델 인수, 종합 감사 |
| **DBA 점검** | A1·A2 + B2·B3·B4 + D1~D7 + G1 | DBA 정기 점검 |
| **표준화 현황** | A1·A2 + B1 + C1~C4 | 표준화 담당자 월간 보고 |
| **거버넌스** | A1 + E1~E3 + F2 | 관리자 변경 감사 |
| **데이터 품질** | A1 + C1 + F1·F3 | 품질 담당자 진단 보고 |
| **커스텀** | 사용자가 체크박스로 선택 | 자유 |

### 4-2. 필터 옵션

- **모델 선택** (필수) — 단일 모델 또는 다중 모델 (다중은 v2)
- **수집 시점** — 최신 / 특정 수집 시점 선택
- **소유자 필터** — 특정 스키마만 포함
- **업무영역 필터** — 특정 BIZ_AREA 만
- **기간** — 변경 이력·진단 추이 기간 (기본 30일)

## 6. 백엔드 API 명세 (개략)

### 6-1. 메인 엔드포인트

```http
POST /api/report/generate
Content-Type: application/json

{
  "dataModelId": "...",
  "clctId": null,          # null = latest
  "ownerFilter": ["CAMS"],
  "bizAreaFilter": null,
  "preset": "DBA",         # or "ALL"/"STD"/"GOV"/"QUAL"/"CUSTOM"
  "sheets": ["A1","A2","D1",...],   # CUSTOM 시 명시
  "options": {
    "historyDays": 30,
    "includeCharts": true,
    "colorCoding": true,
    "alsoPdf": false
  }
}

→ Response: { reportId: "...", downloadUrl: "/api/report/download/..." }
```

### 6-2. 시트별 데이터 조회 — 기존 mapper 재활용

| 시트 | 활용 매퍼 |
|---|---|
| A1·A2 | `datamodel.selectDataModelById`, `datamodel.selectDataModelObjList` |
| B1 | `datamodel.selectDataModelAttrList` |
| B2 | `datamodel.selectIndexList` |
| B3 | `datamodel.selectConstraintList` |
| B4 | FK 조회 신규 (혹은 B3 가공) |
| C1~C4 | `diag.selectDiagResultByJob`, `word.selectMissingWords` |
| D1~D7 | **신규 매퍼 필요** — DBA 점검 쿼리들 |
| E1~E3 | `changehistory.selectRecentChanges`, `approve.selectPending` |
| F1~F3 | `diag.*`, `structdiag.*`, `qualDiag.*` |
| G1 | `DdlGenerator` 활용 |

### 6-3. xlsx 생성 — 라이브러리

- **Apache POI** (현재 q-center 에 사용중인지 확인 필요)
- 또는 **EasyExcel** (대용량 친화)
- 시트별 헤더 스타일 + 색상 코딩 + 차트 임베디드

### 6-4. 비동기 처리

- 작은 모델 (테이블 50 이하): 동기 처리, 즉시 다운로드
- 큰 모델 (테이블 100+): 비동기 처리 → 작업 ID 발급 → 진행률 표시 → 완료 시 알림
- TB_REPORT_JOB (신규 테이블) 로 상태 관리

## 7. DB 변경

### 7-1. 신규 테이블 (선택적)

**TB_REPORT_JOB** — 보고서 생성 작업 추적 (대용량 비동기용)

```sql
CREATE TABLE quality.tb_report_job (
  report_id      varchar(40) PRIMARY KEY,
  data_model_id  varchar(40) NOT NULL,
  preset         varchar(20),
  sheets         text,                    -- JSON array
  status         varchar(20),             -- REQUESTED/RUNNING/DONE/ERROR
  user_id        varchar(40),
  req_dt         timestamp DEFAULT now(),
  done_dt        timestamp,
  file_path      text,
  file_size      bigint,
  err_msg        text
);
```

### 7-2. 기존 테이블 변경 없음

모든 데이터는 기존 TB_DATA_MODEL_* / TB_DIAG_* / TB_QUAL_* / TB_CHANGE_HISTORY 에서 조회. **DDL 변경 무 → DDL_full_schema.sql 갱신 불필요** (TB_REPORT_JOB 추가 시에만).
