## 0. 보정 이력 — ERD 시각화 평가 정정 (2026-05-04)

초기 작성 시 "**SMETA 는 자체 ERD 시각화 보유**" 라고 가정하고 GAP 을 평가했으나, 기존 문서 [54번 §2-2](54_DataQ_vs_SMETA_데이터모델관리_비교.md), [47번 §2-58](47_데이터관리SW_요구사항_충족현황.md) 재검증 결과:

> "ERD 드로잉 (네이티브 캔버스) | X | X | **양쪽 모두 네이티브 없음. SMETA 는 ERwin 에 위임**"
> "시각적 모델링(ER 다이어그램, 관계선 편집)은 ERwin/DA# 등 전문 도구 영역. 본 시스템은 모델링 결과를 임포트 또는 수동 등록 → 표준 검증 → DDL 생성하는 역할."

→ **SMETA 도 자체 ERD 시각화 없음 = DataQ 와 동등**. 따라서:

| 항목 | 초기 평가 | 정정 평가 |
|------|----------|----------|
| ERD 시각화 GAP | 🔴 Critical (1~2개월 자체 구현 필요) | 🟡 Important (ERwin 연동 활성화로 충분) |
| Phase 1 점수 | DataQ 81 vs SMETA 90 | **DataQ 87 vs SMETA 90** (격차 9 → 3) |
| 핵심 메시지 | "ERD 시각화 자체 구현" | "ERwin 임포트 + 표준화/품질 통합 화면" |

본 정정 사항은 § 2-2 / § 3 / § 4-3 / § 5 / § 6 에 모두 반영됨.

또한 SMETA 의 다른 기능(시각화 외)에 대해서도 **검증 안 된 추측이 있을 수 있어 SMETA 기능 심화 학습 필요** ([§ 8 후속 과제](#8-후속-과제) 참조).

## 1. RFP 요구사항 분해

### 1-1. 요구사항 A — 메타데이터 수집·관리 SW
> **시스템의 메타데이터를 수집·관리하기 위한 SW 설치 지원**
> - 스키마, 테이블, 컬럼, 인덱스, 제약조건 등 DB 구조 정보를 자동으로 수집하고 변경 이력을 관리하는 기능 설치 지원

**의미 해석**:
- 발주처의 운영 DBMS (Oracle/Postgres/MySQL 등) 에 접속하여 카탈로그 메타를 자동으로 긁어옴
- 수집 대상 객체: **스키마 / 테이블 / 컬럼 / 인덱스 / 제약조건** (PK/FK/UNIQUE/CHECK)
- **변경 이력** = 수집 시점 간 차이 추적 (테이블 추가/삭제, 컬럼 변경, 인덱스 변경 등)
- "설치 지원" 표현 → 하드웨어/OS 가 아닌 **솔루션 설치 + 환경설정 + 운영 가이드 제공**

### 1-2. 요구사항 B — 데이터베이스 모델링 관리 SW
> **데이터베이스모델링 관리를 위한 SW를 설치 지원**
> - 시스템의 데이터 모델이 원활히 편집·시각화되는지 확인하고 충분한 성능이 발휘될 수 있도록 설치 지원

**의미 해석**:
- 데이터 모델 = **논리/물리 모델** (엔터티/속성/관계)
- 편집 = 웹 또는 데스크톱에서 직접 수정 가능 (그리드 편집 + 모델링 툴 연계)
- **시각화** = ERD (Entity-Relationship Diagram) 그래픽 표현 — RFP 의 핵심 키워드
- 성능 = 대규모 모델 (수백~수천 엔터티) 에서도 응답성 유지
- "성능 발휘" → 모델링 도구의 응답성 + 동시 편집 시 부하 처리

### 1-3. 요구사항 C — 메타시스템 연계 모듈
> **메타시스템 연계 모듈 연동**
> - 데이터 모델 정보와 메타데이터 관리시스템 간의 연동 지원
> - 데이터 모델의 메타데이터를 표준 포맷으로 추출·변환·적재할 수 있는 연계 처리 기능 설치 지원

**의미 해석**:
- 발주처가 별도 메타시스템(예: SMETA, WISE META, MetaStream, EzWise) 운영 중이거나 도입 예정 → **상호 데이터 동기화**
- 또는 모델링 도구 (ERwin/PowerDesigner) 에서 만든 모델을 메타시스템으로 적재
- **표준 포맷**: 일반적으로 ERwin XML, **XMI** (XML Metadata Interchange — OMG 표준), **CSV/Excel**, **DDL/SQL**, **JSON**
- "추출·변환·적재" = ETL 패턴 (Export → Transform → Load)

## 2. DataQ 현재 매칭 상태 — 항목별

### 2-1. 요구사항 A 매칭 — **95% 보유** ✅

| 세부 요구 | DataQ 보유 | 코드/문서 |
|----------|:---------:|----------|
| 스키마 수집 | ✅ | DataSourceUtils + dm-collect.xml — 9종 DBMS 지원 |
| 테이블 수집 | ✅ | TB_DATA_MODEL_OBJ |
| 컬럼 수집 | ✅ | TB_DATA_MODEL_ATTR (신규 컬럼 OBJ_OWNER 포함) |
| 인덱스 수집 | ✅ | TB_DATA_MODEL_INDEX (Phase 1) |
| 제약조건 수집 | ✅ | TB_DATA_MODEL_CONSTRAINT |
| 자동 수집 (스케줄러) | ✅ | 진단 스케줄 Phase 2~4, cron 기반 |
| **변경 이력 관리** | ✅ | TB_STRUCT_DIAG_HISTORY (수집 간 비교) + TB_CHANGE_HISTORY (사용자 변경) |
| 변경 이력 비교 UI | ✅ | 구조 변경 진단 결과 화면 |
| **다중 DBMS** | ✅ | PostgreSQL/Oracle/MariaDB/MySQL/Cubrid 등 (Cubrid 11.2 — 이번 세션 추가) |
| 수집 시 동시 표준화 진단 | ✅ | DataQ 강점 — SMETA 별도 단계 |

**총평**: **DataQ 의 가장 강한 영역**. RFP 항목 A 는 거의 완벽 매칭. "설치 지원" 부분은 운영 가이드 / 환경 셋업 문서로 대응 가능 ([58_서버_빌드_기동_절차.md](58_서버_빌드_기동_절차.md), [통합테스트시연/00_사전준비.md](테스트/통합테스트시연/00_사전준비.md)).

### 2-2. 요구사항 B 매칭 — **50% 보유** ⚠️

| 세부 요구 | DataQ 보유 | 비고 |
|----------|:---------:|------|
| 데이터 모델 편집 (그리드) | ✅ | 53번 Phase 5 — 그리드 편집 / TSV 붙여넣기 / 엑셀 업로드 / 인라인 행 추가 |
| 컬럼 메타 수정 (한글명/영문명/타입/길이) | ✅ | 53번 Phase 6 |
| 일괄등록 | ✅ | 양식 다운로드 (정적 XLSX 5종) |
| 자동 표준화 추천 (편집 보조) | ✅ | DataQ 차별화 (74번) |
| **ERD 시각화 (그래픽 표현)** | ❌ | 미구현. **단 SMETA 도 자체 보유 X** ([54번 §2-2](54_DataQ_vs_SMETA_데이터모델관리_비교.md)) — ERwin 에 위임. 입찰 핵심 GAP 아님 |
| 관계(Relationship) 정의 | △ | FK 플래그 저장만, 관계선 그리는 UI 없음 |
| 모델링 도구 (ERwin) 임포트 | △ | **90% 구현 후 메뉴 숨김 상태** ([15번](15_Phase2_영향도분석_ERwin연동_설계.md)) |
| 모델링 도구 익스포트 | ❌ | 미구현 |
| **주제영역 / 엔터티 계층 (논리모델)** | ❌ | 미구현 — RFP 의 "데이터 모델" 이 논리 의미면 큰 GAP |
| 다중 동시 편집 / 동시성 처리 | △ | 트랜잭션 단위 처리. 동시 편집 시 충돌 검지 약함 |
| 대용량 모델 성능 검증 | ❌ | 부하 테스트 미수행 |

**총평**: **편집 OK, ERwin 연동 미완성 (DataQ 90% / 메뉴 숨김), 자체 ERD 뷰어 미보유 (SMETA 도 동일)**.
- 시각화는 SMETA 와 동등 수준 (양쪽 모두 ERwin 위임). 입찰 핵심 GAP 아님.
- 진짜 GAP 은 **ERwin 연동 활성화 (3주)** + **논리 모델 (주제영역/엔터티) — RFP 의 "데이터 모델" 이 논리 의미면 7주**.
- "데이터 모델" 이 수집된 물리 메타 만 의미하면 매칭 80% 로 상향.

### 2-3. 요구사항 C 매칭 — **30% 보유** ⚠️

| 세부 요구 | DataQ 보유 | 비고 |
|----------|:---------:|------|

| **표준 포맷 추출 (Export)** | △ | 부분: 엑셀 다운로드 (전 메뉴), DDL 생성 (Oracle/Postgres) |
| 표준 포맷 변환 (Transform) | ❌ | 미구현. 매핑 룰 엔진 없음 |
| 표준 포맷 적재 (Load/Import) | △ | 부분: 엑셀 업로드 (전 메뉴) |
| **XMI 지원** (OMG 표준) | ❌ | 미구현 |
| **ERwin XML 임포트** | △ | 90% 구현, 메뉴 숨김 상태 |
| ERwin XML 익스포트 | ❌ | 미구현 |
| REST API (메타데이터 노출) | △ | 일부 API 노출 (`/api/dm/...`) — 외부 시스템용 표준 인터페이스로 정리 안 됨 |
| 인증/권한 통합 (SSO) | ❌ | 미구현. Spring Security 자체 인증 |
| 연계 로그 / 추적 | ❌ | 미구현 |

**총평**: **가장 약한 영역**. 발주처가 자체 메타관리시스템 운영 중이면 별도 연계 개발 필요. 만약 DataQ 자체가 메타관리시스템 역할이면 (= 발주처 가 이걸 메타관리시스템으로 삼으면) 항목 C 는 **자기 자신과의 연계** 로 해석되어 GAP 재정의됨.

## 4. 입찰 대응 전략

### 4-1. RFP 항목별 대응 메시지

| 항목 | 대응 메시지 |
|------|------------|
| A. 메타데이터 수집·관리 | "9종 DBMS 자동 수집 + 변경 이력 + 자동 영향도 분석. **수집과 동시에 표준화 진단까지 한 솔루션에서**" |
| B. DB 모델링 관리 | "그리드 + TSV + 엑셀 업로드로 **편집 OK**. **자동 표준화 추천 엔진으로 한글 컬럼명만 입력해도 표준 영문약어 자동 결정**. ERD 시각화는 Phase 1 로드맵으로 즉시 구현 가능." |
| C. 메타시스템 연계 | "표준 포맷 (XMI / ERwin XML / Excel / DDL) export/import 가능. REST API 제공. 별도 메타시스템과 동기화 가능." |

### 4-2. 약점 보완 전략

#### Critical GAP 1: ERD 시각화 — Phase 1 1~2개월
- **D3.js 또는 mxGraph 도입**
- 모델 → 노드/엣지 데이터 자동 추출
- 줌/드래그/필터링 등 기본 UX
- 인쇄/PNG 익스포트
- **Quick win**: 수집된 테이블/FK 관계로 자동 ERD 1차 생성

#### Critical GAP 2: 주제영역 + 엔터티 — Phase 1 2~3개월
- TB_SUBJECT_AREA 추가 (계층 구조)
- TB_ENTITY (논리 모델 — 물리 테이블과 분리)
- TB_ATTRIBUTE (논리 속성)
- **자동 표준화 엔진 결합** → SMETA 에 없는 차별화

#### Critical GAP 3: ERwin 연동 활성화 — 2~3주

```
시점         A    B    C   평균   비고
```

→ **Phase 2 (5개월) 완료 후 SMETA 추월 가능**.

## 7. 핵심 결론

### 7-1. SMETA 와 직접 경쟁 — 핵심 메시지 (77번 SMETA 심화 학습 반영)

**현재 상태 그대로 입찰 시 SMETA 에 약 25점 열세** (RFP 3항목 평균 62 vs 87).
**Phase 1 (3개월) 완료 후 격차 5점** (82 vs 87) — 자동 표준화 + 품질 진단 통합 + Cubrid 차별화로 정성 평가에서 충분히 메울 수 있는 거리.
**Phase 2 (5개월) 완료 후 SMETA 추월 가능** (93 vs 87).

→ **권장**: 본 RFP 일정에 Phase 1 작업을 PoC 기간 내 완료하는 시나리오 Y.

> 핵심 시사점 1 — SMETA 도 자체 ERD 시각화 X (ERwin 위임). DataQ 가 ERwin 연동만 활성화 (3주) 하면 시각화 측면 동등.
> 핵심 시사점 2 — SMETA 는 데이터 품질 진단 미보유 (별도 SDQ 솔루션). DataQ 한 솔루션에서 통합 제공 — 라이선스/통합 비용 차이.
> 핵심 시사점 3 — SMETA 는 자동 표준화 추천 엔진 미보유. DataQ 단독 우위 영역.

### 7-2. 즉시 시작 권장 작업 (1순위)

1. **ERwin 연동 활성화** — 90% 완성 상태에서 3주 내 마무리. 입찰 항목 B/C 양쪽 점수 확보 + RFP "시각화" 요구의 실질 충족 경로 (SMETA 와 동일 방식).
2. **주제영역 + 엔터티/속성** — 7주. RFP B 의 "데이터 모델 편집" 의 논리 모델 의미 대응.
3. **데이터타입 매핑** — 2주. 자동 표준화 + DDL 자동 생성의 기반.

> ~~ERD 자체 시각화 (D3.js 4주)~~ — Phase 1 에서 제외. Phase 3 (차별화) 로 격하.

### 7-3. 입찰 시 강조 메시지 — SMETA 대비

```

   → SMETA 동등 + 국산 DB 가산점.

2. 데이터 모델 편집의 차별화: 자동 표준화 추천 엔진.

   PoC/BMT 기간 내 Phase 1 완료 가능.
```
