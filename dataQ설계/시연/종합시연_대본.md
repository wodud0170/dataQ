> "모델을 만들기 전에 표준 사전이 잘 정의돼 있는지 먼저 확인합니다."

> "행안부 표준 단어 약 3,300건이 기본 탑재되어 있고, 사용자 단어가 그 위에 누적됩니다. 등록일자 / 영문약어 / 형식단어 / 승인 여부 — 4개 필터를 조합해 원하는 단어 집합을 즉시 추려낼 수 있습니다."

### 3-2. 용어 등록 v2 (자동 분석)

**[액션]**
1. `데이터 표준 사전 > 용어` → [등록] 클릭 → 모달
2. **한글 용어명**: `회원전화번호` 입력
3. 1초 디바운스 후 자동 분석 결과 표시:
   - 토큰: 회원 / 전화 / 번호 (3개)
   - 각 토큰 매칭 후보 + 영문약어 자동 합성: `MBR_TEL_NO`
   - 도메인 유형 자동 cascade (마지막 단어 `번호` → 도메인 `번호`)
4. [등록] → 용어 사전에 추가

> "DP 점수 + 동의어 cascade + 미신뢰 토큰 재검색으로 정확한 단어 분리 결과를 얻습니다. 사용자가 영문약어를 일일이 매핑할 필요가 없습니다."

**[케이스 시연]**
1. **AUTO**: `회원전화번호` → 모든 토큰 매칭, 즉시 등록 가능
2. **PARTIAL**: `시연단어일자` → '시연단어' MATCHED + '일자' MATCHED, 그러나 합성 영문 약어 검증 → 등록 가능
3. **FAILED**: `라랄라룰루` → 모든 토큰 미인식, 등록 차단 + 안내
4. **REGISTERED**: 다시 `회원전화번호` 입력 → 이미 등록됨 swal

## 4. 모델 ① — 논리 모델 (10분)

> "이제 첫 번째 모델을 만들겠습니다. **데이터소스 없이**, 사용자가 직접 한글 컬럼명만 입력해 자동 표준화로 물리화하는 시나리오입니다."

### 4-1. 모델 등록

**[액션]**
1. 좌측 `데이터 모델 > 데이터 모델 관리` → [등록] 클릭
2. 모달:
   - 모델명: `논리모델`
   - 데이터소스: **(선택 안 함)** — 논리 모델 의도
   - 버전: `1.0`
3. [저장] → 빈 모델 생성 + 데이터 모델 관리 목록에 추가

> "데이터소스 미선택 → 자동 수집 없이 빈 모델만 생성됩니다. 사용자가 그리드에서 직접 테이블·컬럼을 채워 넣는 흐름입니다."

### 4-2. 테이블 추가

**[액션]**
1. `데이터 모델 > 테이블` → 데이터모델명 드롭다운에서 `논리모델` 선택 → [조회]
2. 0건 표시. [등록] 클릭 → 모달
3. 모달 입력:
   - 소유자: `USER1`
   - 테이블 영문명: `TB_MEMBER` (자동 대문자)
   - 테이블 한글명: `회원`
4. [저장] → 테이블 1건 추가

### 4-3. 컬럼 추가 + 자동 표준화 (한글명 기준)

**[액션 — 컬럼 추가]**
1. `데이터 모델 > 컬럼` → 데이터모델명 `논리모델` 선택 → [조회] (0건)
2. **추가 대상** 드롭다운에서 `USER1.TB_MEMBER (회원)` 선택
   - **검색 필터(소유자/테이블 영문/한글)가 자동 세팅** 시연 포인트
3. [컬럼 추가] 또는 [+10행] 클릭 → 빈 신규 행 생성
4. 한글명만 입력 (영문명/타입/길이는 비워둠):
   - `회원ID`
   - `회원명`
   - `회원전화번호`
   - `가입일자`
   - `회원여부`

**[액션 — 멀티 paste]**
1. `dataQ설계/시연/data/시연_컬럼한글명_paste.txt` 파일을 메모장으로 열고 **전체 선택 + 복사**
   - (또는 `시연_컬럼_샘플.xlsx` 의 컬럼한글명 컬럼 10건을 엑셀에서 직접 복사)
2. 그리드의 신규 행 첫 한글명 칸 클릭 → Ctrl+V
3. **10건이 10개 행에 자동 분배** 시연 포인트 — 100행 상한 안내 swal 도 시연 가능
4. 영문명 / 타입 / 길이 / 소수점 / 순서 / 디폴트 — 모든 필드 paste 가능 (각 필드는 자동 변환: 숫자 필드는 parseInt, 영문명/타입은 자동 UPPER)

**[액션 — 한글명 기준 표준화]**
1. 5개 행 모두 체크 → [한글명 기준 표준화] 버튼
2. **사전 confirm 모달** — "선택한 5건의 컬럼을 처리합니다. 한글명 → 영문명/타입/길이/소수점 자동 채움" → [실행]
3. 그리드 셀에 새 값 즉시 채워짐:
   - `회원ID` → `MBR_ID` / VARCHAR / 20 / 0
   - `회원명` → `MBR_NM` / VARCHAR / 100 / 0
   - `회원전화번호` → `MBR_TEL_NO` / VARCHAR / 13 / 0
   - `가입일자` → `JOIN_DT` / DATE / 0 / 0
   - `회원여부` → `MBR_YN` / CHAR / 1 / 0
4. swal: "변환 결과: 5/5. 값이 그리드에 채워졌습니다. **저장 버튼을 눌러야 DB 에 반영됩니다**" (dryRun 강조)

## 11. 마무리 + 차별화 (3분)

### 11-1. 한눈 정리

> "오늘 시연한 흐름 한 장 요약:

> ② 모델 3종 — 논리(수동 입력+자동 표준화) / 수집(DBMS) / XMI(외부 도구) 모두 동일 그리드 흐름
> ③ 표준 진단 + 자동 표준화 — 한글명/영문명 양방향, dryRun 안전
> ④ 구조 변경 진단 — 외부 ALTER 자동 감지

> ⑥ 자동화 — 스케줄 + 회귀 + 모델 cascade
> ⑦ 거버넌스 — 권한 / 승인 / 변경 이력 영구 보관"

### 11-2. RFP SFR-22 매핑

> "RFP A (메타 수집·관리) — DataQ 직접 책임. 다중 DBMS 자동 수집 + 변경 이력 + XMI 임포트.
> RFP B (DB 모델링 관리) — ERwin 영역. DataQ 는 ERwin 결과물을 임포트해 표준화·DDL 라인으로 연계.
> RFP C (메타시스템 연계) — DataQ 직접 책임. 추출 (Excel/DDL) + 적재 (Excel/XMI) + REST API."

### 11-3. 차별화

> "한국 표준 직접 반영 (행안부 형식단어/분류어). DP 점수 + 동의어 cascade 로 자동 표준화 정확도 강화. 데이터 품질 4개 영역 통합 (도메인 룰 + 프로파일 + 업무 규칙 + 시계열). 운영 안전 장치 — 모델/컬럼 cascade rename, dryRun 표준화, 진단 제외 관리, 모델 삭제 cascade. 약 100여 케이스 자동 회귀."

## 부록 C — 문제 발생 시 fallback

| 상황 | 대응 |
|---|---|
| 로그인 실패 (DB 연결 X) | `docker restart dataq-db` |
| 진단 시 STOMP/실행 실패 | q-executor 재기동 (28098) |
| Oracle 수집 실패 | `docker restart oracle-xe` + 데이터소스 [연결 테스트] |
| 카탈로그 모달 무한로딩 | `.catch + .finally` 보강됨 — 새로고침 + 콘솔 에러 확인 |
| 표준화 결과 안 채워짐 | 한글명/영문명 입력 확인 (dryRun 응답 items 매칭) |
| 컬럼 표준화 시 0/0 결과 | 사용자 입력값과 DB 의 영문명 mismatch 가능 — 새로 영문명 입력해서 재시도 |

## 부록 D — Q&A 예상 질문

1. **신규 환경 구축?** → `dataQ설계/DDL_full_schema.sql` 1 파일 실행 + 매뉴얼 v2.2 참조.
2. **다른 DBMS 추가?** → `lib/common-0.0.1-SNAPSHOT.jar` 의 `drivers.xml` + DataSourceUtils 분기. Cubrid 사례 참조.
3. **권한 세분화?** → 현재 admin/user 2단계. RBAC 확장은 사용자 관리 화면 베이스에 권한 매트릭스 추가 가능.
4. **자동 표준화 정확도?** → 행안부 표준 단어 3,300건 + DP 점수 + 동의어 cascade. 미등록 단어는 인라인 등록 후 재분석.
5. **컬럼 영문명 잘못 변경 시?** → 영문명 변경 cascade rename 자동 (INDEX/CONSTRAINT/FK_PARENT_ATTR 동시 갱신).
6. **삭제한 모델의 변경 이력은?** → 영구 보존 (감사 / 컴플라이언스 목적). 모델 본체는 USE_YN='N' soft-delete.
7. **진단 결과 다운로드?** → 동적 POI 생성, 검색 필터 그대로 반영. 한국어 파일명 RFC 5987.
8. **대용량 모델에서 그리드 응답성?** → fixed-header + 페이징 + 멀티 paste 100행 단위. 수집·진단은 q-executor 워커 분리로 웹 부하 격리.
