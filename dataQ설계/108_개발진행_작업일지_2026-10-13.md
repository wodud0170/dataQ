### 4.3 WP2 역할·권한·시스템 계층 — 설계 (구현 전)

104 §2 WP2, §3.3(역할 테이블은 `quality` 에 새로) 기준.

**원칙**
- `TB_USER.ADM_YN=true`(관리자)는 지금처럼 모든 권한을 가진다. 역할은 관리자가 아닌 사용자에게 권한을 더 주는 장치다. → 기존 관리자·일반 계정은 동작이 바뀌지 않는다.
- 지금 관리자만 할 수 있는 일을 권한 코드로 나눈다. 지금 일반 사용자도 할 수 있는 일은 그대로 둔다(권한 검사를 새로 붙이지 않는다).
- 권한 판정은 요청마다 DB 기준(사용자별 10초 캐시) — 역할을 바꾸면 다시 로그인하지 않아도 곧 반영.
- q-executor 의 엑셀 일괄등록 승인값도 같은 기준(관리자 또는 `STD_MANAGE`)으로 정한다.

- `TB_ROLE`(ROLE_ID, ROLE_NM 유일, ROLE_DESC, BUILTIN_YN, 생성·수정 4칸)
- `TB_ROLE_PERM`(ROLE_ID, PERM_CD) — 역할 삭제 시 함께 삭제
- `TB_USER_ROLE`(USER_ID, ROLE_ID, SYS_CD 기본 '*'=전체 시스템, 생성 2칸) — 시스템별 DB 담당(49번)

**서버**
- `PermCode`(코드·이름·범위 목록), `PermService.has(userId, code[, sysCd])` — 관리자면 true, 아니면 역할 권한. 시스템별 코드는 '*' 이거나 그 시스템·상위 시스템에 부여된 경우.
- `SessionService.hasPerm(code)`, `hasPerm(code, sysCd)` — 52곳의 `isAdmin()` 을 위 표대로 치환. `isAdmin()` 은 로그인 처리·내 정보 표시용으로만 남김.
- `RoleController` (`/api/role/**`, USER_ADMIN): 권한 목록, 역할 목록·저장·삭제, 역할별 사용자 목록·지정·해제. `GET /api/login/myPerms` — 로그인 사용자의 관리자 여부·권한 목록(시스템 범위 포함).
- `execDdl`: 변경 이력의 모델 → `TB_DATA_MODEL.DM_SYS_CD` 로 DDL_EXEC 판정(모델에 시스템이 없으면 전체 범위 권한만).
- q-executor `ExcelUploadService.isAdminUser` → 관리자 또는 STD_MANAGE.

**화면**
- 공통 `perm.js`: 로그인 후 한 번 `myPerms` 를 읽어 `this.$can('CODE')` 제공. 18개 화면의 `isAdmin` 분기를 화면 기능에 맞는 권한으로 바꾼다(헤더·내 정보의 '관리자' 표시는 사용자 속성 표시라 유지).
- `NdNav`: 메뉴 항목별 권한으로 표시. 관리 그룹은 항목이 하나라도 보이면 표시.
- `MMRoles`: 역할 목록 / 역할 편집(이름·설명·권한 체크) / 역할별 사용자(사용자·시스템 범위 지정, 해제).
- 시스템 계층(73번): 관리 > 시스템 메뉴 연결(`MMSystem.vue`), 시스템별 기본 사전(`TB_SYS_INFO.DICT_ID`)과 그 시스템의 데이터 모델 목록.

**DDL**: 3개 테이블 + `TB_SYS_INFO.DICT_ID` + 기본 역할 시드. 덤프 2종·변경이력·sync 스크립트.
