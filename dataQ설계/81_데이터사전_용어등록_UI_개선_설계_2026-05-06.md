# 81. 데이터 사전 > 용어 등록 UI 개선 설계 (2026-05-06)

## 배경

DataQ 에서 용어 등록 경로는 4개:
1. **데이터 사전 > 용어 등록** ← 본 문서 개선 대상 (옛 개발자 작업물, UI 개선 필요)
2. 데이터 사전 > 용어 일괄 등록 (엑셀)
3. 자동 표준화 > 용어 등록
4. 표준화 진단 > 용어 gap 맞추기

**범위**: 1번만 개선. 2/3/4 는 손대지 않음. 백엔드 API 변경 없음.

## 현재 두 화면 비교

| 영역 | DSTerm.vue (1번, 2706줄) | DSTermRecommend.vue (3번, 1254줄) |
|---|---|---|
| 입력 흐름 | 3단계 스테퍼 (용어명 → 단어선택 → 메타) | 3단계 스테퍼 (한글 컬럼명 → 자동분석 → 리뷰등록) |
| 단어 분해 | **수동** (사용자가 단어 직접 선택/순서 조합) | **자동** (`analyzeTermsBatch` API) |
| 영문약어 | 자동 합성 (단어 ABRV) | 자동 합성 + 직접 수정 가능 |
| **코드 도메인 지정** | ✅ 마지막 단어 ABRV='CD' 감지 후 활성화 + 코드 검색·자동매핑 | ❌ |
| **이음동의어** | ✅ | ❌ |
| **시스템CD / 제정차수 / 공통표준** | ✅ | ❌ |
| 인라인 단어 신규등록 | ✅ | ✅ (편집 모달 안) |
| 도메인 자동 추정 | ❌ | ✅ (마지막 단어의 domainClsfNm) |

## 결정 사항

| # | 결정 |
|---|---|
| **P1** | 스테퍼 폐지 → **단일 폼** (한 모달에 모든 입력) |
| **P2** | 자동 분석 트리거 — **디바운스 자동 호출 (1초)** |
| **P3** | 코드 도메인 — **코드 picker 다이얼로그** (모달 안 모달, 코드가 늘어날 수 있음) |
| **P4** | 단건 등록만 개선 (일괄은 2번 메뉴 그대로) |

## 통합 핵심 포인트

1. **자동 분석 호출** — DSTermRecommend 의 `analyzeTermsBatch` API 호출. 결과를 DSTerm 의 기존 `addTerm_wordList` 에 매핑. 칩 형태로 매칭 상태 (✓ 매칭 / ⚠ 신규) 표시.
2. **코드 도메인 분기 보존** — DSTerm 의 `addTerm_lastWordIsCode` / `onAddDomainTypeChange()` 그대로. 자동 분석 결과의 마지막 단어가 'CD' 면 토글 자동 코드로 전환.
3. **인라인 단어 등록** — ⚠ 신규 칩 클릭 시 작은 dialog 또는 inline expand. 기존 `wordEngAbrvNm`, `wordEngNm` 입력 폼 재사용.
4. **메타 영역 접기** — 이음동의어·시스템CD 등 필수 아닌 항목은 default 접힘 (`v-expansion-panel`). 빠른 등록 시 펼칠 필요 없음.

## 구현 단계

| # | 작업 | 영향 범위 |
|---|---|---|
| 1 | DSTerm.vue 의 등록 모달 (`addTermModalShow`) 영역만 식별 → 단일 폼 템플릿으로 교체 | 등록 모달 한정 (목록/수정/삭제 흐름은 무관) |
| 2 | `analyzeTermsBatch` 호출 추가 + 결과를 단어 칩 + 영문약어로 매핑. 한글 용어명 입력에 1초 debounce watcher | data() 에 `addTerm_analyzing`, `addTerm_chips` 등 추가 |
| 3 | 코드 picker — 모달 내부에 또 다른 v-dialog (max-width 720). v-data-table + 검색. 선택 시 `addTerm_selectedCode` 채움 | DSCode.vue SELECT 로직 참고만, 별도 컴포넌트 분리 X |
| 4 | 미매칭 단어 칩 (⚠ 신규) 클릭 시 인라인 신규 단어 등록 폼 (작은 dialog 또는 inline expand) — 기존 `wordEngAbrvNm/wordEngNm` 폼 재사용 | 동작 보존 + UX만 변경 |
| 5 | 메타 영역 접기 (이음동의어·시스템CD·제정차수·공통표준) — `v-expansion-panel` default 접힘 | 필수 아님 / 빠른 등록 |
| 6 | 마지막 단어 ABRV='CD' 자동 감지 → 코드 도메인 토글 자동 활성화 (기존 `addTerm_lastWordIsCode` 로직 그대로) | 보존 |
| 7 | 기존 3단계 스테퍼 (`addTerm_step` 등) 코드 정리 | 죽은 코드 제거 |

## 보존 필수 (DSTerm 만의 고유 로직)

- 코드 도메인 지정 (라디오 + 코드 검색·자동매핑)
- 인라인 단어 신규 등록
- 이음동의어 (`allophSynmLst`)
- 시스템CD (`reqSysCd`)
- 제정차수 / 공통표준여부
- 권한 흐름 — admin 등록 시 즉시 승인, 일반사용자는 APRV_YN='N'
- 부모 그리드 리프레시 (등록 성공 후 호출되는 메서드)
- eventBus pendingXxx 처리 — 다른 화면에서 이 모달로 진입하는 경로

## 리스크

- **DSTerm.vue 2706줄** 큰 컴포넌트 — 등록 모달만 손대고 목록 그리드/수정/삭제/검색 영역은 일절 안 건드림.
- **백엔드 변경 0** — `analyzeTermsBatch`, `registerWord`, `registerTerm` 모두 기존 API.
- **2/3/4 영향 0** — DSTermRecommend, 일괄 등록, 표준화 진단 화면 모두 무관.

## 작업량 추정

등록 모달 영역 ~500-700줄 재작성. 1차 빌드까지 1시간 안.

## 검증 방법

1. 빌드 후 q-center 백그라운드 기동
2. 데이터 사전 > 용어 등록 → "추가" 진입
3. 한글 용어명 입력 → 1초 후 자동 분석 결과 (단어 칩) 노출 확인
4. 일반 도메인 / 코드 도메인 토글 (마지막 단어 'CD' 자동 전환 케이스 포함)
5. 코드 picker 다이얼로그 (검색·선택 → codeGrp/domainNm/dataType 자동 매핑)
6. 미매칭 단어 인라인 등록
7. 메타 영역 접기/펼침
8. 등록 완료 후 부모 그리드 갱신
