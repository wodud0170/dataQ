## 1. 거버넌스 흐름 (사용자 확정 — 2026-05-17)

| 단계 | 상태 | 가시성 |
|---|---|---|
| 일반 사용자가 테이블/컬럼 변경·추가 | **DRAFT** | 작성 본인만 (**관리자도 못 봄**) |
| 테이블/컬럼 화면에서 "신청" → 일괄 신청 | **SUBMITTED** | 본인 + 관리자(승인 화면) |
| 관리자가 승인 | **APPROVED** | **그제서야** 관리자 테이블 메뉴 + 전체 사용자 |
| 관리자가 반려 | REJECTED | 본인 + 관리자 (사유) |
| 관리자 본인 변경 | 즉시 APPROVED | 전체 |

핵심: **APPROVED 전까지는 관리자의 "데이터 모델 > 테이블" 메뉴를 포함해 어떤 일반 조회 화면에도 안 보인다.** 관리자는 "데이터 모델 변경 승인" 화면에서만 SUBMITTED를 보고, 승인해야 테이블 메뉴에 등장.

남이 등록한 DRAFT/SUBMITTED는 다른 일반 사용자에게 안 보임 (본인 것만).

## 3. 남은 작업 (다음 세션)

### 3-1. 신청 모달 (우선순위 높음)
- 현재 신청 화면이 별도 탭 `#tab_my_dm_changes` 으로 분리 → **사용자가 신청 단계 자체를 인지 못 함** (사용자가 지적한 핵심 문제).
- 작업하던 **테이블 화면 / 컬럼 화면** 양쪽에 "내 변경 신청" 버튼 추가 → 클릭 시 **모달**로 본인 DRAFT 목록(테이블·컬럼 통합) 띄워 일괄 신청 → SUBMITTED.
- 기존 `MMDataModelMyChanges`(또는 `#tab_my_dm_changes` 컴포넌트)의 myDrafts 조회 + selectSubmit 로직 재사용 가능. API: `POST /api/dmApproval/myDrafts`, `POST /api/dmApproval/submit`.
- 설계 §14.3 에 모달 UI 예시 있음.

### 3-2. addAttr / deleteAttr 거버넌스 누락 보완
- `DataModelController.addAttr` / `deleteAttr` (개별 컬럼 추가/삭제) — `ChangeHistoryService.record` 호출 없음 + `APRV_STATUS` 미세팅 → 이력에 안 남고 "내 변경 신청"에 안 뜸.
- `saveAttrs` (배치) 는 거버넌스 적용돼 있음 — addAttr/deleteAttr 도 동일 패턴(`resolveAprvStatusForUserChange()` + `record(...)`)으로 보완.

### 3-3. 마이페이지 "데이터 모델 변경 승인" 메뉴
- 현재 승인 화면은 `관리 > 데이터 모델 변경 승인`(#tab_dm_approval). 마이페이지에도 노출 요청.
- `NdNav.vue` 마이페이지 그룹(`navMyPageGroup`)에 링크 추가. 컴포넌트는 기존 `MMDataModelApproval.vue` 재사용.

### 3-4. 동시성 검증
- 일반 유저 2명(`jyjang`/123, `narae`/123) 으로:
  - 남이 등록한 DRAFT가 안 보이는지
  - 같은 모델·테이블에 같은 이름 컬럼 동시 등록 시 PK 충돌 → "이미 등록 중" 친화적 안내가 뜨는지 (설계 §12)
- Playwright + 통합테스트.

### 3-5. 인덱스/제약 조회 가시성 (검토)
- 가시성 수정은 obj/attr 만 적용. `getDataModelIndexListByDmId` / `getDataModelConstraintListByDmId` 는 거버넌스 필터 없음 (매퍼가 `aprvStatus` 미조회). 인덱스/제약 변경도 거버넌스 대상이면 매퍼에 `aprvStatus` 추가 + 필터 필요.

### 3-6. 전체 흐름 최종 검증
- jyjang 변경 → 신청(모달) → 관리자 승인 화면 노출 → 승인 → 관리자 테이블 메뉴 노출 — Playwright E2E.
