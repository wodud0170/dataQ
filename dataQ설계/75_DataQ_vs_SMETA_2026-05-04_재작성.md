## 1. 한 줄 요약

- **SMETA**: 주제영역→엔터티→속성의 논리 모델을 웹에서 설계 → 표준사전 기반 물리 자동 생성 → 결재 기반 배포. **메타관리 솔루션의 정석**.
- **DataQ**: 수집 기반 현행 분석 + **자동 표준화 추천 엔진** (1자 비분류어 격하, 동의어 매칭, 사후처리) + **데이터 품질 진단** (값/룰 8종 RULE_TYPE, sampling, incremental). **차별화·확장 영역**.

## 4. SMETA 대비 우위 영역

### 4-1. 자동 표준화 추천 엔진 (핵심 차별화)

```
SMETA 의 논리→물리 변환:
  사용자가 속성 등록 → 표준사전에서 수동으로 용어 선택 → 물리명 매핑

DataQ 의 자동 표준화:
  사용자가 한글 컬럼명 입력 →
    OKT 형태소분석 +
    DP 기반 최적 분리 (B: SPLIT_PENALTY, D: 1자 비형식단어 격하) +
    사후처리 (미신뢰 구간 → TB_WORD/DICT/ALLOPH_SYNM 재검색) +
    동의어 매핑 (예: 카테고리 → 범주, CTGRY)
  → 영문약어 자동 결합 + 도메인 자동 추천 (마지막 형식단어 cascade)
  → 1순위 / 2순위 추천
```

**시연 포인트**: "표준을 모르는 사람도 한글 컬럼명만 입력하면 자동으로 표준 준수 영문약어가 나온다." — 입찰 BMT/PoC 의 결정적 차별점.

### 4-2. 데이터 품질 진단 (SMETA 미보유)

SMETA 는 메타관리 중심으로 값/룰 진단은 외부 도구(예: ataccama, BiTuen DQ) 가 담당. DataQ 는 한 솔루션에 통합:
- 8 RULE_TYPE: NOT_NULL / RANGE / LENGTH / REGEX / ENUM / UNIQUE / REFERENCE / COMPARE
- 도메인 룰 1:N — 한 도메인에 여러 룰, 컬럼은 단일 룰 선택
- sampling + incremental → 대용량 DB 부하 제어
- 다중 DBMS dialect: PostgreSQL / Oracle / Cubrid

### 4-3. 진단 → 즉시 일괄등록 연계

표준화 진단 화면에서 비표준 컬럼 발견 → 클릭 한 번으로 일괄 등록 흐름 진입. SMETA 는 별도 메뉴로 이동 후 수동 작업.

### 4-4. 다중 DBMS 지원

수집 9종 + 진단 dialect 3종 (PG/Oracle/Cubrid). SMETA 는 주로 Oracle/Postgres 중심.

### 4-5. 셀레니움 자동 회귀 (27건)

매 변경마다 마스터 러너로 회귀 검증 — SMETA 는 자동 회귀 인프라 공개 자료 부재.

## 8. 결론

- **GAP 영역**: 엔터티 등 논리모델·다단계 결재·ERwin 활성화는 여전한 약점. Phase 1 로 메우기.
- **우위 영역**: 자동 표준화 + 데이터 품질 진단 + 다중 DBMS + 자동 회귀 — DataQ 의 의도적 차별화 영역. Phase 2 로 강화.
- **결론**: SMETA 는 "메타관리 정석" 영역에서 우세. DataQ 는 "표준 자동화 + 품질 진단 통합" 영역에서 우세. **Phase 1 GAP 만 해소되면 양 솔루션 동등 + DataQ 우위 영역 결합으로 BMT 경쟁력 충분**.
