# 데이터 모델 수집 — 확인 모달 화면 설계

**작성일:** 2026-04-19
**대상:** 데이터 표준 > 데이터 모델 > 데이터 모델 수집
**관련 파일:** [DSDatamodelCollection.vue](q-center/vue/front/src/components/DSDatamodelCollection.vue), [DataModelController.java](q-center/src/main/java/qualitycenter/controller/DataModelController.java), [DataModelService.java](q-executor/src/main/java/qualityexecutor/service/std/DataModelService.java)

## 1. 배경

### 현재 동작 (AS-IS)

1. 사용자가 데이터 모델 행을 선택한다.
2. 우측 상세영역의 "스키마 수집 범위"에서 체크박스로 수집 대상 스키마를 on/off 한다. (체크 변경 즉시 `saveSchemas` 호출되어 DB에 반영)
3. 우측 상단의 **수집** 버튼 클릭 → `collectionAction()` 실행.
4. 프론트는 유효성만 검사하고 바로 `POST /api/dm/collectDataModel` 호출.
5. q-executor가 **테이블/컬럼 → 인덱스 → 제약조건**을 모두 순차 수집. (인덱스·제약조건은 try/catch로 감싸져 실패해도 skip)
6. "수집 진행 상태" 다이얼로그가 로그를 stream 하면서 보여준다.

### 문제점

- **확인 단계가 없다.** 수집 버튼을 누르는 즉시 실행되므로 오클릭/오선택 시 되돌릴 수 없다.
- 수집 대상 스키마 목록을 실행 직전에 다시 확인할 방법이 없다. 체크박스는 우측 상세 영역 안에 섞여 있어 "지금 수집되는 범위"를 한눈에 파악하기 어렵다.
- **수집 범위를 건별로 끊을 수 없다.** 테이블만 다시 수집하고 싶어도 인덱스/제약조건까지 전부 다시 긁어온다. 대형 스키마에서 반복 수집 시 비용 증가.

### 기대 동작 (TO-BE)

- **수집 버튼 클릭 → 확인 모달** 표시.
- 모달은 (1) 수집할 스키마 목록 요약, (2) 수집 대상 체크박스 3종(**테이블/컬럼**, **인덱스**, **제약조건**)을 보여준다.
- 사용자가 **수집 시작** 버튼을 눌러야 실제 수집이 시작된다.
- 백엔드는 받은 체크박스 조합대로 해당 단계만 실행한다.

## 2. 화면 설계

### 2-1. 트리거 지점

[DSDatamodelCollection.vue:89](q-center/vue/front/src/components/DSDatamodelCollection.vue#L89)

```html
<v-btn class="gradient" v-on:click="collectionAction()" title="수집">수집</v-btn>
```

→ 현재 `collectionAction()`이 바로 `axios.post`를 때리고 있다. 이걸 **모달 열기**로 바꾸고, 실제 수집은 모달의 "수집 시작" 버튼이 호출하는 새 메서드(`startCollection()`)가 수행한다.

### 2-2. 모달 레이아웃

```
┌─ 데이터 모델 수집 확인 ─────────────────────────[X]┐
│                                                    │
│ ▸ 대상 데이터 모델                                   │
│   고객계_운영DB (v1.2) / Oracle / 10.10.12.5        │
│                                                    │
│ ▸ 수집 대상 스키마  (총 3개)                         │
│   ┌────────────────────────────────────────┐      │
│   │ • HR                                    │      │
│   │ • SALES                                 │      │
│   │ • ETL_STG                               │      │
│   └────────────────────────────────────────┘      │
│                                                    │
│ ▸ 수집 항목 (최소 1개 선택)                           │
│   [v] 테이블 / 컬럼      (기본 필수)                 │
│   [v] 인덱스                                        │
│   [v] 제약조건                                      │
│                                                    │
│ ⚠ 이전 수집 이력을 대체하지 않습니다. 새로운 수집 이력이  │
│   추가로 생성됩니다.                                  │
│                                                    │
│                    [  취소  ]  [ 수집 시작 ]         │
└────────────────────────────────────────────────────┘
```

### 2-3. 구성 요소 상세

| 영역 | 설명 | 데이터 소스 |
|------|------|-------------|
| **대상 데이터 모델** | 읽기 전용 요약. 모델명 + 버전 + DBMS + 호스트 | `selectedItem[0]` ({dataModelNm, dataModelVer, dataModelDsNm, …}) |
| **수집 대상 스키마** | Chip 나열 또는 bulleted list. 스키마가 0개면 "수집할 스키마를 선택해주세요" 에러로 모달 자체를 띄우지 않음 | `schemaTree[0].schemas.filter(s => s.useYn === 'Y')` |
| **수집 항목 체크박스** | v-checkbox 3개. `collectTable`은 기본 true, 비활성(disabled). `collectIndex`/`collectConstraint`는 사용자가 on/off | 로컬 state (`collectOptions`) |
| **안내 문구** | 현재 구조(스냅샷 기반)에서는 수집 시마다 새 CLCT 레코드가 쌓인다는 점을 명시. 혼동 방지 | 고정 |
| **취소 / 수집 시작** | 취소: 모달 닫기. 수집 시작: `startCollection()` 호출 → 기존 "수집 진행 상태" 다이얼로그로 이어짐 | 버튼 |

### 2-4. 체크박스 정책

- **테이블/컬럼**: 필수. 체크 해제 불가. (컬럼 없이 인덱스만 수집하면 TB_DATA_MODEL_OBJ/ATTR가 비어 있어 인덱스가 자식이 없는 고아가 됨) → 화면상 checked + disabled.
- **인덱스**: 기본 체크 ON.
- **제약조건**: 기본 체크 ON.
- 3개 모두 체크 상태는 현재 동작과 동일한 결과를 낸다(=하위 호환).
- **최소 1개** 검증은 테이블이 항상 켜져 있으므로 자연히 만족.

### 2-5. 버튼 동작 플로우

```
[수집] 클릭
   └─ collectionAction()
       ├─ 데이터 모델 미선택 → swal 에러
       ├─ 선택 스키마 0개 → swal 에러
       └─ showCollectionConfirmModal = true   (★ 신규 — 확인 모달 표시)

[수집 시작] 클릭 (모달 내부)
   └─ startCollection()
       ├─ showCollectionConfirmModal = false
       ├─ 기존 "수집 진행 상태" 다이얼로그 오픈
       └─ axios.post(.../collectDataModel, { ...params, collectTable, collectIndex, collectConstraint })
```

### 2-6. 기존 "수집 진행 상태" 다이얼로그와의 관계

- **연속된 2개의 다이얼로그**로 구성. 확인 모달이 먼저 뜨고, 수집 시작 시 닫히면서 진행 상태 다이얼로그가 열린다.
- 진행 상태 다이얼로그([DSDatamodelCollection.vue:156-197](q-center/vue/front/src/components/DSDatamodelCollection.vue#L156-L197))는 기존 그대로 유지. 변경 불필요.

### 3-5. `collectionAction()` 수정 (기존 [DSDatamodelCollection.vue:520-578](q-center/vue/front/src/components/DSDatamodelCollection.vue#L520-L578))

```javascript
collectionAction() {
  if (this.selectedItem.length === 0) { /* 에러 (기존 유지) */ return; }

  const selectedSchemas = this.schemaTree.length > 0
    ? this.schemaTree[0].schemas.filter(s => s.useYn === 'Y') : [];
  if (selectedSchemas.length === 0) { /* 에러 (기존 유지) */ return; }

  // 모달 기본값 리셋 후 오픈 (기존 axios.post 블록 제거)
  this.collectOptions = { collectTable: true, collectIndex: true, collectConstraint: true };
  this.showCollectionConfirmModal = true;
},

hideCollectionConfirmModal() {
  this.showCollectionConfirmModal = false;
},

startCollection() {
  this.showCollectionConfirmModal = false;
  try {
    const _params = {
      "dataModelId":    this.selectedItem[0].dataModelId,
      "dataModelNm":    this.selectedItem[0].dataModelNm,
      "dataModelSysCd": this.selectedItem[0].dataModelSysCd,
      "dataModelSysNm": this.selectedItem[0].dataModelSysNm,
      "dataModelDsId":  this.selectedItem[0].dataModelDsId,
      "dataModelDsNm":  this.selectedItem[0].dataModelDsNm,
      "dataModelVer":   this.selectedItem[0].dataModelVer,
      // ★ 신규 3개 플래그
      "collectTable":      this.collectOptions.collectTable,
      "collectIndex":      this.collectOptions.collectIndex,
      "collectConstraint": this.collectOptions.collectConstraint,
    };

    this.collectionLogs = [];
    this.isCollecting = true;
    this.showCollectionDialog = true;

    axios.post(this.$APIURL.base + "api/dm/collectDataModel", _params)
      .then(/* 기존과 동일 */)
      .catch(/* 기존과 동일 */);
  } catch (error) { /* 기존과 동일 */ }
},
```

## 4. 백엔드 변경 상세

### 4-1. VO 필드 추가

파일: [q-common/src/main/java/com/ndata/quality/model/std/StdDataModelVo.java](q-common/src/main/java/com/ndata/quality/model/std/StdDataModelVo.java)

```java
// 수집 범위 옵션 (기본값 true — 미지정 요청과 하위호환)
private Boolean collectTable      = Boolean.TRUE;
private Boolean collectIndex      = Boolean.TRUE;
private Boolean collectConstraint = Boolean.TRUE;
```

**왜 Boolean(래퍼)인가**: 과거 클라이언트(플래그 미전송)에서도 JSON 역직렬화 시 null 대신 기본값 TRUE를 유지해야 하위호환이 된다. 기본 생성자에서 TRUE로 초기화.

### 4-2. DataModelController 변경

[DataModelController.java:407-418](q-center/src/main/java/qualitycenter/controller/DataModelController.java#L407-L418) — 변경 없음. `StdDataModelVo`를 그대로 passthrough 하므로 VO에 필드를 더하면 executor까지 자동 전달된다. 로그에 수집 플래그를 포함하도록만 추가:

log.info(">> started collect data model : {} (collectTable={}, collectIndex={}, collectConstraint={})",

### 4-4. 스킵 상태를 통계/이력에 남기기

`TB_DATA_MODEL_CLCT`에 수집 플래그 3개를 컬럼으로 남기면, 나중에 "이 수집 이력은 인덱스가 포함되지 않은 것"을 판별할 수 있다. 수집 이력 화면에서 수집 범위 뱃지 표시 가능.

```sql
ALTER TABLE quality.TB_DATA_MODEL_CLCT ADD COLUMN CLCT_TABLE_YN CHAR(1) DEFAULT 'Y';
ALTER TABLE quality.TB_DATA_MODEL_CLCT ADD COLUMN CLCT_INDEX_YN CHAR(1) DEFAULT 'Y';
ALTER TABLE quality.TB_DATA_MODEL_CLCT ADD COLUMN CLCT_CONSTRAINT_YN CHAR(1) DEFAULT 'Y';
```

(DDL은 [dataQ설계/DDL_claude_generated.sql](dataQ설계/DDL_claude_generated.sql)에 먼저 반영)

**선택 사항**: 이 DB 컬럼 확장은 범위가 커지므로 Phase 2로 미루고, Phase 1(이번 설계)은 기능만 먼저 붙이는 것도 가능.

## 5. 테스트 시나리오

| # | 시나리오 | 기대 |
|---|---------|------|
| 1 | 데이터 모델 미선택 상태에서 수집 버튼 | 기존 에러 swal (모달 안 뜸) |
| 2 | 스키마 0개 선택 후 수집 | 기존 경고 swal (모달 안 뜸) |
| 3 | 스키마 선택 + 수집 | 확인 모달 표시 — 대상 스키마 칩이 모두 보임 |
| 4 | 모달 열린 상태에서 취소 | 모달 닫힘. 수집 실행 안 됨 |
| 5 | 기본값(전부 체크)으로 수집 시작 | 기존 동작과 동일한 결과. TB_DATA_MODEL_OBJ/ATTR/INDEX/CONSTRAINT 모두 채워짐 |
| 6 | 인덱스만 체크 해제 후 수집 | OBJ/ATTR/CONSTRAINT는 채워지고 INDEX는 비어있음. 진행 로그에 "인덱스 수집 스킵" |
| 7 | 제약조건만 체크 해제 후 수집 | OBJ/ATTR/INDEX는 채워지고 CONSTRAINT는 비어있음. 진행 로그에 "제약조건 수집 스킵" |
| 8 | 인덱스·제약조건 모두 해제 후 수집 | OBJ/ATTR만 채워짐. 수집 속도가 현저히 빨라야 함 |
| 9 | 테이블 체크박스 클릭 시도 | disabled 상태로 반응 없음 |
| 10 | 수집 중 다른 모델 전환 | 기존 거동 유지 확인 (본 설계 범위 밖이지만 회귀) |

## 6. 영향 범위 / 회귀 체크

- **DSStructDiag.vue** 등 구조 진단 화면은 인덱스/제약조건 수집이 선행돼야 의미 있는 결과를 낸다. 인덱스를 뺀 수집본에 대해 구조 진단을 돌리면 "인덱스 변경사항 없음"으로 나올 수 있음 → 진단 화면에 경고 표시를 두는 것이 바람직. (본 설계 범위 밖, 별도 개선사항으로 기록)
- **외부 스케줄러/배치가 `collectDataModel`을 호출**하는 경로가 있으면, 미지정 요청에서 기존 동작(전부 수집)을 유지해야 한다 → VO 기본값 true로 해결.
- **API 계약**: `/api/dm/collectDataModel`의 request body에 필드 3개가 추가되는 확장 변경이므로 기존 클라이언트와 호환.

## 7. 구현 순서

1. `StdDataModelVo`에 플래그 3개 추가 (기본 true)
2. `DataModelService`의 인덱스/제약조건 블록에 if 감싸기
3. 프론트 모달 템플릿 + data/methods 추가
4. `collectionAction()` 리팩토링 (axios.post 제거 → 모달 오픈)
5. `startCollection()` 신규 추가 (axios.post 포함)
6. 테스트 #1~#10 회귀
7. (선택) `TB_DATA_MODEL_CLCT`에 플래그 컬럼 3개 추가 + 수집 이력 화면 뱃지
